## 1. KGI の定義

**KGI: 14日間の累計で、pergram.site へのオーガニック流入 300 アクティブユーザー。**

「オーガニック」の定義をここで固定する。GA4 の「オーガニック検索（Organic Search）」だけを指すと、
X の施策では 2週間でほぼ動かない（検索順位は 2週間では変わらない）。したがって本 KGI は
**広告を経由しない流入すべて**を指す。

| 測る場所 | GA4 の |
|---|---|
| 指標 | アクティブユーザー数 |
| 絞り込み | セッションのデフォルトチャネルグループ が `Paid Search` / `Paid Social` **以外** |
| 主戦場 | `Organic Social` と `Referral`（X からの流入はこの2つに落ちる） |
| 期間 | Day1 0:00 〜 Day14 23:59（JST） |

### 数字の根拠

| | 実測 | 14日換算 |
|---|---|---|
| 直近7日 | アクティブユーザー **1** / イベント 7 / キーイベント 0 | 2 |
| 直近28日 | アクティブユーザー **38** / イベント 296 / キーイベント 4 / 新規 38 | 19 |

**28日で 38人・うち新規 38人＝リピートゼロ。直近7日は 1人。** 28日の数字は期間前半に集中しており、
現在は実質ゼロである。したがって KGI 300 は、ベースライン比で約 150倍という見え方になるが、
これは「倍率が野心的」なのではなく **母数がゼロに近い**ためである。判断は倍率ではなく
絶対値で行う。**300 ユーザー = 1日あたり 21ユーザー。**

### 副次指標（KGI の内訳と、その先）

| 指標 | 目標 | 根拠 |
|---|---|---|
| X 起点の流入（Organic Social + Referral） | 250 | KGI の 83%。残り 50 は直接・検索 |
| `waitlist_submit` | 20件 | CVR 6.7%。実測は 4/38 = 10.5% だが n=38 なので保守側に置く |
| インプレッション合計 | 100,000 | 下の先行指標から逆算 |
| プロフィールクリック | 1,500 | インプレッションの 1.5% |
| リンククリック | 400 | プロフィールクリックの 27%。GA4 到達で 25% 落ちる想定 → 300 |

**先行指標は毎日見る。KGI は Day7 と Day14 に見る。**

## 4. 手持ちの弾（2026-09-02 時点の実データ）

46製品すべてでタンパク質1gあたり単価が計算できる。

| 種別 | 件数 | 1gあたり単価のレンジ | 開き |
|---|---|---|---|
| ソイ | 22 | ¥1.92 〜 ¥34.55 | **18.0倍** |
| WPC | 11 | ¥4.88 〜 ¥11.65 | **2.4倍** |
| WPI | 9 | ¥6.86 〜 ¥10.53 | 1.5倍 |
| 全体 | 46 | ¥1.92 〜 ¥34.55 | 18.0倍 |

**最も強い1枚は「同じ WPC で 2.4倍の開き」。** 種別を揃えた比較なので反論されにくい。
ソイの18倍は数字として派手だが、ソイとホエイを混ぜた比較は
「別物を並べている」と批判されるため、**種別を明示せずに18倍だけを出さない**。

含有率も出せる（1食あたりのタンパク質 ÷ 1食の粉量）。実データでは 60% 〜 90% の幅がある。
**「同じ1kgでも中身のタンパク質量が違う」という一次情報**であり、単価と並べると説得力が出る。

## 5. 戦術（優先度順）

作業量の合計は **1日あたり 60〜90分**。これを下回ると KGI は達成できない。

### T1｜「プロテイン高すぎ」に困っている人への個別リプ ★最優先

**根拠（実観測）**: 検索語 `プロテイン 高すぎ lang:ja` で、表示 20〜2,700 の投稿が**毎日途切れず流れている**。
「最近プロテイン高すぎませんか」「ジム通い始めたしプロテイン買うかと思ったら高すぎわろた」など。
表示数は小さいが**購入意図が最大**で、返信が返ってくる確率が高い。

- 量: **1日 8〜12件**
- 探し方: `プロテイン 高すぎ` / `プロテイン 迷う` / `プロテイン どれ` を X 検索の「最新」タブで
- 書き方: 宣伝しない。数字だけ渡して、リンクは相手が聞いたときか、2文目に自然に置く
- 期待値: 1件あたりサイト流入 1〜3。14日で 110〜500

### T2｜値上げニュースへのぶら下がりリプ

**根拠（実観測）**: `【プロテインの値上げ続く 需要拡大】`（@YahooNewsTopics、**表示 351,349 / いいね 375**）が走っている。
「9月1日から飲食料品4,531品目が値上げ」（表示 28,441）も同時期。**値上げ文脈は今まさに開いている窓である。**

- 量: 大型ニュースが出た日に **1〜3件**
- 書き方: ニュースは「値上げ」を報じている。pergram は「では現時点で1gあたりいくらか」を足す。
  **自分から「上がった」と書かない**（C-1）
- 期待値: 1件あたり表示 1,000〜5,000、サイト流入 2〜25

### T3｜自前ポスト（1日 2本）

Media Agent が候補を生成する（`/media-draft`）。段階が `test` の間は人が見て手で投稿する。

- 朝1本（型 A/B）、夜1本（型 C/D）
- **1日2本**（`content.posts_per_day = 2`）。段階を上げても承認制なので、`/media-approve` を通すまで出ない
- **1投稿目に URL を貼らない。** ツリーの2投稿目に UTM 付きリンクを置く
- ハッシュタグは 0〜1個
- **1枚目に比較画面のスクリーンショットを必ず添付**（0-4 の整備が前提）

### T4｜セール連動

楽天スーパーセール / マイプロテインのゾロ目セール / Amazon タイムセール祭りに合わせ、
**セール開始から6時間以内**に「現時点の1gあたり最安」を出す。14日間に1回来れば大きい。

### やらないこと

- 手当たり次第の宣伝リプライ（シャドウバン・凍結のリスク）
- ハッシュタグの羅列
- 行政処分・回収ニュースで企業名を挙げた論評

## 6. 投稿の型（禁止語を置き換えた版）

`X_post_strategy.md` の A〜D を、実データと禁止語規約に合わせて書き直したもの。
**数字は投稿前に必ず再計算する**（価格は上書き更新されるため）。

### 型A｜同種別の中の開き（最も反論されにくい）

```
「WPCなら似たようなもの」と思って選んでいたんですが、
楽天で取れた WPC 11製品をタンパク質1gあたりの単価に直したら
¥4.88 〜 ¥11.65 でした。同じ WPC で 2.4倍の開きです。

内容量でも税込価格でもなく、
「タンパク質1gあたりいくらか」で並べ直すとこうなります。
（2026-09-02 時点・楽天で取得した46製品）
```

### 型B｜含有率（一次情報の見せ方）

```
プロテイン1kgを買っても、中身のタンパク質は1kgではありません。
手元の46製品だと、1食あたりの含有率は 60% 〜 90% の幅があります。

含有率60%の製品と90%の製品では、
同じ「1kg・同じ価格」でもタンパク質1gあたりの単価が1.5倍変わります。
```

### 型C｜問いかけ（会話を発生させる）

```
タンパク質1gあたりの単価で並べると、
いま手元のデータでは ¥1.92 〜 ¥34.55 まで開きます（46製品・楽天）。

種別で分けるとソイが一番安く出るんですが、
ホエイから乗り換えてまで単価を取りにいくかは別の話だと思っていて。
みなさんは種別と単価、どちらを優先していますか。
```

### 型D｜Build in Public

```
セールのたびに「結局タンパク質1gあたりいくらだ」と電卓を叩くのが面倒で、
楽天の製品を集めて単価を自動計算するサイトを作りました。

・タンパク質1gあたりの単価で並べ替え
・WPC / WPI / ソイ の種別で絞り込み
・登録不要

まだ46製品しか入っていません。「この製品も入れてほしい」があればリプで教えてください。
```

**使った置き換え**: コスパ最強 → 1gあたり最安 / 神コスパ → 単価が低い / おすすめ → 削除 /
全主要メーカー → 楽天で取得した46製品 / 損してる → 「並べ直すとこうなります」

## 9. 型の効果をどう測るか

### 使う道具（Media Agent に既にある）

| コマンド | 役割 | 前提 |
|---|---|---|
| `media-agent x metrics --account x/pergram-jp` | 自分のプロフィールを1枚読み、直近投稿の指標を取り込む | **`x_reader.own_handle` が必要（T-028）** |
| `media-agent report --account x/pergram-jp` | playbook 別・ペルソナ別に集計する | ネットワーク不要 |
| `media-agent x learn --account x/pergram-jp` | 観測から新しい型の提案を `playbooks/proposals/` へ書く | 採用は `playbook apply <id>` で人が行う |

**T-028 が終わるまで型別の分析は一切できない。** これが T-028 を「高」に置いている本当の理由である。

### 型（playbook）と読み手（persona）

`.media-agent/x/pergram-jp/playbooks/` に4本、`personas/` に3本を置いてある。

| playbook | 型 | | persona | 読み手 |
|---|---|---|---|---|
| `spread` | A 同種別の中の開き（既定） | | `price-shock` | 「プロテイン高すぎ」と言っている人 |
| `content-rate` | B 含有率 | | `sale-hunter` | セールで買い時を計っている人 |
| `question` | C 問いかけ | | `builder` | 個人開発・エンジニア界隈 |
| `build-in-public` | D Build in Public | | | |

playbook は**採用中の1本**が使われる（`content.playbooks.active`）。日々変えるときは
`media-agent post --playbook <id>` で上書きする。persona は曜日で切り替わる（`content.personas.schedule`）。

### 判定指標は「インプレッション」ではなく「プロフィールクリック率」

14日 × 2本/日 = **28投稿**。4型に割ると **1型あたり7本**しかない。
X のインプレッションは裾が極端に重く、1本ハネると平均が壊れる。**7サンプルでは中央値も安定しない。**

| 指標 | 7サンプルで読めるか |
|---|---|
| インプレッション | **読めない**。外れ値に支配される |
| **プロフィールクリック率** | 読める。率なので分母が効き、KGI（サイト流入）にも直結する |

したがって **Day7 で決めるのは「勝った型」ではなく「落とす型」だけ**にする。
7本でプロフィールクリックが0なら死んでいると言えるが、7本で1位でも勝ったとは言えない。

### 型を増やすのは Day14 以降

いま8型に増やすと1型3〜4本になり、分析は改善ではなく**悪化する**。
新しい型は `media-agent x learn` が実観測から提案を書き出す。**提案は自動採用されない**
（少数サンプルからの抽象化はノイズを規則として固定するため、設計上そうなっている）。
人が中身を読んで `media-agent playbook apply <id>` で採用する。

### 日次・節目でやること

```
毎日（投稿後）   media-agent x metrics --account x/pergram-jp
                 media-agent report    --account x/pergram-jp
Day7            report の playbook 別クリック率を見て、0 の型を外す
Day14           media-agent x learn --account x/pergram-jp  → 提案を読んで採用を判断
```

**記録は T-030 の作業ログに残す。** コマンドを流しただけで読まなければ、仕組みは無いのと同じ。
