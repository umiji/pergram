### 登録の経路について（残しておくべき事実）

- **`media-agent` の CLI 経由では登録できない。** `post` / `run` は必ず AI が本文を生成する。
  手書き本文を投稿候補として登録する口が無い。今回は `BufferConnector` を直接呼ぶ
  スクリプトで入れた（`schedule="draft"` を明示）
- したがって **PolicyEngine を通っていない。** 承認キュー・1日2本の上限・重複判定は
  どれも適用されていない。下書きなので公開はされないが、**この経路を常用するなら
  本文差し込みの口を正規の機能として作る必要がある**

### Buffer 側の制約（明日の運用に直接効く）

- **ツリーにならない。** `createPost` は単発投稿を作る。上の4件は独立した下書きとして
  並んでいる。**「1投稿目に URL を貼らない／リンクはツリー2投稿目」を守るには、
  投稿時に人が返信をぶら下げる**
- **スロット表が午前しかない。** mon〜sun すべて 07:43〜11:58 の4枠だけで、夜の枠が無い。
  `live` に上げて `queue` で流すと、夜用に書いた投稿も午前に出る。
  **スロット表は API から変更できない**（publish.buffer.com の画面で行う）
- 観測では「プロテイン高すぎ」の声の7割が **18〜24時 JST** に出ている。
  夜枠が無いままでは、書き手の意図した時間帯に一切出せない
