## 目的

`btn--signal`（背景 `#ea580c` に白文字）のコントラスト比が **約 3.6:1** で、
WCAG 2.2 AA が本文相当のテキストへ求める **4.5:1** を下回っている。

**T-010 でこれが悪化したわけではない**（signal ボタンの数も色も同じ）。
ただし T-010 によって**待機リスト登録が主導線になった**ため、
**最も押させたいボタンが読みにくい**という状態になった。測っているのはメール登録の件数である。

### 追記（2026-09-02・T-010 のレビュー R-010-1 を合流）

**従（ベータ版導線）の側にも同じ種類の問題がある。こちらのほうが重い。**

T-010 で従へ落とした2つのベータ版導線は `btn--quiet`（`src/styles/lp.css:105-113`）を当てており、
背景 transparent・文字色 `--ink`（本文と同色）・境界 `--line`=rgba(22,24,29,0.1) だけになった。
`--paper`(#fafaf9) に対する**境界のコントラスト比は約 1.25:1**（WCAG 2.2 AA の非テキスト 3:1 未満）。
**「押せる操作である」ことを示す手掛かりが、面でも文字色でも無い。**

T-010 の停止条件（「導線を弱めた結果、流入が実質ゼロになりそうなら相談する」）に該当すると
オーケストレーターが判定した。**`btn--subtle` へ替えても約 1.5:1 で解決しない。**
主従の関係は保ったまま、**従が「押せる」と分かる下限**を確保すること。

## 決定ログ

### 2026-09-02 従CTA の非テキストは「面と境界の良い方」で判定する
- 対象: LP のボタン / コントラスト検査
- 決定: 完了条件1b の判定を `max(面 vs ページ背景, 境界 vs ページ背景) >= 3:1` とする。
  面か境界のどちらか一方が満たせばよく、両方は求めない。
- 却下案: 境界だけを見る → 面（塗り）で解く直し方を、テストが理由なく塞いでしまう。
  完了条件1b の本文が「**境界または面**」と書いているので、テストもその通りにする。
- 出典: docs/tasks/T-017.md §完了条件1b、tests/styles.test.js「完了条件1b」

### 2026-09-02 完了条件3 は一回限りの手作業確認ではなく恒久テストにする
- 対象: LP のボタン / コントラスト検査
- 決定: 「変更前の色を入れるとテストが落ちる」を、変更前の色（`#ea580c` / 白、
  `rgba(22,24,29,0.1)` を `#fafaf9` に重ねたもの）を計算関数へ直接渡し、
  3.56:1 / 1.23:1 という**実測値と一致すること**を検査するテストに変換した。
  併せて黒白 21:1・同色 1:1・`#777` 4.48:1 で式そのものを自己検査する。
- 却下案: 実装時に一度だけ色を戻して落ちるのを目視で確認し、証拠に貼る
  → 確認した瞬間しか効かない。以後、計算側が壊れても誰も気付けない。
  色の判定はコードを読んでも正しさが分からない種類の処理なので、
  「測る道具が本当に測れているか」を恒久的に残す方を採った。
- 出典: tests/styles.test.js「完了条件3: コントラスト比の計算が、変更前の色を実際に落とせる」

### 2026-09-02 範囲外の2つのコントラスト不足を、テストにせず記録に残す
- 対象: LP のボタン / コントラスト検査
- 決定: 次の2つは同種の AA 未達だが、**アサーションにしない**。テストファイルの
  コメントと本タスクの記録に残すだけにする。
  (a) `.btn--quiet:hover` の文字（`--signal` を `--paper` の上に置く。変更前 3.41:1）
  (b) `products.css` の `.btn--ghost` の境界（変更前 1.23:1。`.btn--quiet` と同じ問題）
- 却下案: 併せてテストにする → (a) を 4.5:1 にすると、白地で 4.5:1 を満たす橙より
  さらに暗い橙が必要になる（白地で 4.5:1 ちょうどの色は `--paper` 地では約 4.31:1）。
  完了条件が名指ししていない条件のために停止条件（橙系を保てるか）へ踏み込ませることになる。

### 2026-09-02 主CTA の橙は、既にパレットにある `#c2410c` まで落とす
- 対象: LP のボタン / 色トークン
- 決定: `--signal` を `#ea580c`(白文字 3.56:1) から `#c2410c`(5.18:1) へ。
  `--signal-hover` は `#c2410c` から `#9a3412`(7.31:1) へ更に落とす。
  いずれも同じ橙のランプ上の値で、橙系の主張は保っている。
- 却下案: 4.5:1 をぎりぎり満たす `#d1440a`(4.62:1) → 明るさは最大限残るが、余裕が 0.12 しかない。
  かつ `--signal` は紙地の**文字色**としても使われており（リンク、`.btn--quiet:hover`）、
  そちらは 4.43:1 で AA 未達のまま残る。`#c2410c` なら紙地の文字でも 4.96:1 になる。
- 却下案: 文字を大きくして緩和基準 3:1 へ逃げる → 禁止事項で明示的に塞がれている。
- 却下案: `--signal-hover` を据え置き `--signal` と同値にする → 押下前後の差が消える。
- 出典: tests/styles.test.js「完了条件1」、src/styles/tokens.css の 🔒 コメント

### 2026-09-02 従CTA の輪郭には専用トークンを足す。`--line` は動かさない
- 対象: LP のボタン / 色トークン
- 決定: `--line-control: rgba(22, 24, 29, 0.5)`（紙地に対して 3.35:1）を新設し、
  `.btn--quiet` の `border` だけを差し替える。
- 却下案: `--line` 自体を濃くする → `products.css` の `.btn--ghost` まで道連れで直る利点はあるが、
  `--line` はカード・セクション・表の**装飾の罫線**として全面的に使われており、
  サイト全体の罫線がボタンと同じ濃さになる。禁止事項「ブランドの視覚的な一貫性を壊さない」に反する。
- 却下案: 既存の `--muted-faint`(0.65 / 5.41:1) を輪郭に流用 → トークンを増やさずに済むが、
  文字色とほぼ同じ濃さになり、輪郭だけの従CTA が面のある主CTA と同格に見える。主従が崩れる。
- 却下案: 面（塗り）で 3:1 を取る → 紙地に対して 3:1 の面はかなり暗く、従が主より強くなる。
- 付帯条件: `tokens.css` 冒頭の「色を増やさない」方針に対する明示的な例外である。
  理由（`--line` が 1.23:1 で SC 1.4.11 を満たさないこと）をトークンの直上に 🔒 で書いた。
- 出典: src/styles/tokens.css `--line-control`、src/styles/lp.css `.btn--quiet`

### 2026-09-02 `--signal-tint` / `--signal-edge` を新しい RGB へ揃える
- 対象: 色トークン
- 決定: `rgba(234, 88, 12, ...)` を `rgba(194, 65, 12, ...)` へ。
  「`--signal` の薄い版」という関係を値の上でも保つ。
- 却下案: 据え置く（完了条件が要求していない）→ base に存在しない橙がサイト内へ残り、
  次に色を触る担当が「どちらが正しい橙か」を判断できなくなる。透明度 0.08 / 0.25 なので
  見た目の差はほぼ無く、コストに対して得られる一貫性が大きい。
- 出典: src/styles/tokens.css

### 2026-09-02 `--verified` は敢えて `--signal` に揃えない
- 対象: 色トークン / 最安値の強調
- 決定: `--verified` は `#ea580c` のまま据え置く。`--signal`(操作) より明るい橙にしておくことで、
  「押せる場所」と「データの強調（最安値）」を明度で読み分けさせる。
- 却下案: `--signal` と同値へ揃える → 見た目は完全に統一されるが、**操作とデータの区別が消える**。
  また T-017 の変更範囲（`btn--signal` に使う色）を超え、製品一覧の価格表示全体が動く。
- 付帯条件: `--verified` を紙地の**文字**に使うと 3.41:1 で AA 未達である。
  T-017 の完了条件が名指ししていないため手を付けていない。別タスクの候補。
- 備考: この決定は「理由を知らない担当が将来これを元に戻してしまいそうなもの」に当たる
  （2つの橙が並ぶと不揃いに見えるため、揃える方向の"整理"を受けやすい）。
  同じ内容を `tokens.css` の `--verified` の直上にも ⚠️ で書いた。
- 出典: src/styles/tokens.css `--verified`
