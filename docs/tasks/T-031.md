## 目的
X_kgi_2weeks.md の KGI（14日累計でオーガニック流入 300 アクティブユーザー / 1日21）を
**必達させるために、毎日どういう投稿とリプライを打つべきか**を、需要側（読み手）の視点から設計する。

現状の実測は自前ポストで 17imp / 16imp である。**これは「バズっていない」以前に、
アカウントが誰にも認識されていない状態**を意味する。既存の型（playbook 7本）と
戦術（T1〜T4）が、この状態から 14日で 300 ユーザーを作れる構成になっているかを、
マーケティングの観点から検証し、足りないものを設計する。

これを飛ばすと、機構（T-032）だけを直しても「よく整備された経路で、誰にも読まれない投稿を
毎日2本流す」状態が続く。

## 決定ログ

### 2026-09-03 露出の主経路を自前ポストからリプライへ移す
- 対象: X運用 / 露出の調達
- 決定: 14日の露出の主供給源を、自前ポスト（T3）から**他人のスレッドへのリプライ**へ移す。
  自前ポストは1日2本のまま維持するが、KGI の供給源としては数えない。
  リプライは「意図層 7件/日」「露出層 4件/日」の2層に分け、露出層は `min_faves:` で
  伸びている投稿だけを対象にする。
- 却下案:
  ①自前ポストを1日3〜4本へ増やす → 実測 17imp のまま本数だけ増やしても
  28本で 462imp、目標 100,000 の 0.46%。分母（フォロワー）が増えないので線形にしか伸びない。
  同じ時間をリプへ回す方が1桁効率が高い。
  ②引用リポストを露出の柱にする → 引用は自分のフォロワーへ配信されるため、
  フォロワー0では露出が出ない。「相手1人に見つけてもらう施策」としてだけ残した。
  ③ハッシュタグを増やす → スパム判定。rules.md で最大2個。
- 出典: docs/Marketing/X_growth_design.md §1.2 / §2.1 / §2.2 / §8-A,B,C

### 2026-09-03 副次指標の内訳を組み直す。KGI 300 は据え置く
- 対象: X運用 / KGI の内訳
- 決定: インプレッション目標を 100,000 → **32,000** へ。リプライ送信数143件・
  返信が返ってきた数30件・**捕まえた「窓」の数5回**・フォロワー増+60 を新設。
  プロフィールクリックを 1,500 → 600 へ。**リンククリック400 と GA4 流入300 は動かさない。**
- 却下案: 100,000 を維持する → 放送モデル（配信 → 1.5% がプロフィールへ）から出た数字で、
  会話モデルのこの経路では原理的に到達しない。**到達しない数字を掲げると Day7 の判定が
  「全部だめ」としか読めなくなり、ゲートが機能しなくなる。**
- 付帯条件: KGI 本体（300 アクティブユーザー）は PO 確定値なので下方修正しない。
  内訳の書き換えの可否は PO 判断（付録B-1）。
- 出典: docs/Marketing/X_growth_design.md §1.3 / §2.4 / §8-I

### 2026-09-03 型を7本から「露出型4本＋会話型1本＋息継ぎ1本」へ絞る
- 対象: X運用 / 投稿の型
- 決定: 露出型を `ranking-doubt`(6) / `whats-inside`(6) / `not-comparable`(5) /
  `build-in-public`(5) の4本に絞る。`beauty-premium` は14日間の運用から外す。
  `unit-price` と `trivia` は**削除せず、自前ポストからリプライへ置き場所を移す**。
- 却下案:
  ①7本のまま走らせ Day7 で絞る → 26枠 ÷ 7 = 1型3.7本。X_kgi_2weeks.md §9 自身が
  「1型3〜4本になると分析は悪化する」と書いており、**「落とす型」すら判定できない**。
  ②`trivia` を主軸に据える（実測16imp で2位） → **プロフィールクリックが構造的に発生しない型**で、
  imp は伸びるが KGI（サイト流入）へ変換しない。**実測が高いことと目的に合うことは別。**
  ③`beauty-premium` を未観測のまま試す → 読み手が自ら「未観測」と書いており、
  N-10 / N-03 の危険度が最も高い。14日という短さで、外れたときの損失が利得を上回る。
- 付帯条件: `.media-agent/` へは書き込んでいない。採用は PO / 機構側の判断（付録B-2）。
  `config.yaml` の persona 曜日割当（水・日 = `beauty-first`）の振り替えが必要（付録A-5）。
- 出典: docs/Marketing/X_growth_design.md §6 / §8-D,E,F

### 2026-09-03 「1食の粉量 13g〜100g、12通り」は投稿に使わない
- 対象: X運用 / 投稿の型 / データの正しさ
- 決定: `not-comparable` の型が立っている数字を差し替える。46製品のうち**12製品は
  `serving_size_g` が 100 だが、これは「1食100g」ではなく栄養成分表示が「100gあたり」の製品**
  だった（`serving_size_g:100 × servings_per_unit:100 = 10,000g` の製品が実在する）。
  正しくは **「1食の粉量は 13g〜30g、11通り（1食表示の34製品）」**。
  「100gあたり表示が12製品ある」という事実は、型の主張（1食では比べられない）を
  むしろ強めるので、そちらを本文に使う。
- 却下案: 既存 playbook の数字をそのまま使う → **事実として誤っている。**
  プロテインに詳しい層のいるスレッドで書けば必ず訂正され、比較サイトとしての信用を失う。
- 出典: 実データ再計算（`data/products.json` / `nutrient_contents.json` /
  `price_snapshots.json` / `product_attributes.json`、46製品）。
  docs/Marketing/X_growth_design.md §1.6a / §8-H

### 2026-09-03 会話型の型は、露出型と同じ指標で比較しない
- 対象: X運用 / 型の効果測定
- 決定: 新設する `price-on-request` の判定指標を、プロフィールクリック率ではなく
  **「返ってきたリプの件数」**にする。露出型4本とは別の集計とし、相互に比較しない。
- 却下案: 全型をプロフィールクリック率で並べる → 26枠を型数で割ると1型5〜6本しかなく、
  X のインプレッションは裾が重いため中央値が安定しない。**会話型を同じ土俵に載せると、
  露出型の1型あたりのサンプル数まで削ってしまう。** 返信件数は n=3〜5 でも判定できる。
- 出典: docs/Marketing/X_growth_design.md §2.3 / §6.5 / §6.6

### 2026-09-03 リプライ1件ごとの表示回数は記録しない
- 対象: X運用 / 日次の計測
- 決定: 日次で数えるのは **「送ったリプ数」と「返信が返ってきた数」の2つだけ**にする。
  リプ1件ごとの表示回数・プロフィールクリックは追わない。
- 却下案: 全リプの表示回数を記録する → 1件30秒 × 143件 = **約70分が計測だけに消える**。
  1日60〜90分という制約の下では、得られる精度が失う実行時間に見合わない。
- **将来これを「計測が足りない」として元に戻さないこと。** 意図的に測っていない。
- 出典: docs/Marketing/X_growth_design.md §3.4 / §3.5 / §8-M

### 2026-09-03 リプライ本文に URL を貼らない（相手が聞いた場合を除く）
- 対象: X運用 / リプライ
- 決定: リプに URL を貼るのは、相手が「どこで見られますか」と聞いたときだけ（テンプレ R-8）。
  それ以外のリプでは貼らず、**変換はすべてプロフィールと固定ポストで起こす。**
- 却下案: 毎回リンクを貼って取りこぼしを無くす → 貼った瞬間に「宣伝リプ」の枠に入り、
  相手にも観客にも読まれなくなる。取りこぼしを防ぐ代わりに母数が消える。
- **この決定の帰結として、T-028（プロフィールと固定ポスト）が本設計の単一障害点になる。**
  無い状態でリプを打っても流入は0。Day2 の最優先に置くことを PO へ上げた（付録B-6）。
- 出典: docs/Marketing/X_growth_design.md §4.0 / §2.5 / §8-G
