## 目的

流入の**100%がスマートフォン**であるのに対し、現在のフォームは1画面に4項目ある
（メールアドレス／見たい成分チップ＋自由記述／普段の購入先チップ／その他ご要望の自由記述）。
狭い画面でのアンケート項目数は離脱に直結する。

**ステップ1をメールアドレス1項目だけにし、残りを登録完了後のステップ2へ移す。**

  置き去りにしない

  （上限は `src/lib/waitlist_fields.js`）
- 🔒 チップの並びも許可リストも `src/lib/waitlist_fields.js` が唯一の出所。
  LP側とWorker側で二重に持たない

- ステップ2を必須にしない（ステップ1の送信時点で登録は完了している）

## 完了条件

1. ステップ1の入力欄がメールアドレス1つだけになっている
2. ステップ1の送信だけでD1にレコードが作られる（ステップ2に進まなくても登録は成立する）

## 決定ログ

### 2026-09-02 GA4 のイベント名は waitlist_step2_view / waitlist_step2_submit
- 対象: 待機リスト / 計測
- 決定: ステップ2への**到達**を `waitlist_step2_view`、ステップ2の**送信**を
  `waitlist_step2_submit` として送る。ステップ1の登録は従来どおり `waitlist_submit`。
  選択内容のパラメータ（`selected_nutrients` / `purchase_channel` /
  `has_nutrients_other` / `has_requests`）は **`waitlist_step2_submit` の側へ移った**。
  `waitlist_submit` はパラメータを持たない（登録できたという事実だけ）
- 却下案: `waitlist_submit` に「どの段か」のパラメータを足して1つのイベントで数える
  → 到達と送信を**別々に**数えられない（完了条件4）。既存のキーイベント
  `waitlist_submit`（T-001 で GA4 管理画面に登録済み）の意味も変わってしまう
- 付帯条件: **T-007 が GA4 管理画面へ登録するのは上の2つの綴り**である。
  併せて、カスタムディメンション4つ（`selected_nutrients` / `purchase_channel` /
  `has_nutrients_other` / `has_requests`）の**紐付け先イベントが
  `waitlist_submit` から `waitlist_step2_submit` へ移った**ことを反映する必要がある
- 出典: `src/assets/lp.js`（`track('waitlist_step2_view')` / `track('waitlist_step2_submit')`）

### 2026-09-02 Worker の UPSERT は「空の値では上書きしない」
- 対象: 待機リスト / 保存
- 決定: `ON CONFLICT(email) DO UPDATE SET` を
  `COALESCE(NULLIF(excluded.x, ''), waitlist.x)` の形にし、**送られてきた値が空なら
  今ある値を残す**。列は増やしていない（6つのまま）
- 却下案: 現行のまま `excluded.x` で素直に上書きする → **2段階化した瞬間に壊れる。**
  ステップ1はメールアドレスだけを送るので、ステップ2に答えた人が後日もう一度
  ステップ1から送信した時点で、集めた回答が丸ごと消える。旧 SQL で再現済み
  （3回目の送信後に `nutrients` が `''`、自由記述が `null` に戻る）
- 付帯条件: 値を空に戻す UI は存在しないので、この変更で失われる操作は無い。
  やり直しは「新しい値を入れて送り直す」で従来どおり効く
  （`tests/waitlist_upsert.test.js`「ステップ2をやり直したら新しい回答で置き換わる」）
- 出典: `worker/waitlist.js` / `tests/waitlist_upsert.test.js`

- [道具] LP を実ブラウザで確認するとき、`dist/` は CSS を `/assets/...` の絶対パスで読むため `file://` で開くとスタイルが当たらず、レイアウトの観測が**エラーにならないまま誤る**（`display:grid` が `block` に見えた）。ローカル HTTP で配信する必要があるが、その手順がリポジトリに無い
- [規約] 実装担当が変更範囲外のテスト（`tests/render.test.js`、T-020 の持ち物）に当たらないようマークアップを選んでおり、テスト側で**その回避が妥当かを独立に確かめる**必要が生じた。テストの所有者と、そのテストが縛る実装の所有者が別タスクに分かれていることの費用が、判定側にも出ている
