## 目的

流入の**100%がスマートフォン**であるのに対し、現在のフォームは1画面に4項目ある
（メールアドレス／見たい成分チップ＋自由記述／普段の購入先チップ／その他ご要望の自由記述）。
狭い画面でのアンケート項目数は離脱に直結する。

**ステップ1をメールアドレス1項目だけにし、残りを登録完了後のステップ2へ移す。**

## 変更範囲

| ファイル | 変更内容 |
|---|---|
| `src/templates/lp/form.js` | ステップ1をメールのみに。残り3項目をステップ2（完了状態の中）へ |
| `src/assets/lp.js` | ステップ2の送信。GA4イベントを追加（ステップ2の到達と回答） |
| `worker/waitlist.js` | 既存レコードへの追記経路。**列は増やさない** |
| `worker/schema.sql` / `worker/migrations/` | 追記経路に必要な変更があれば |
| `tests/worker.test.js` | 上記と必ず揃える |
| `locales/*.json` | 文言 |

**保存してよい列は現行の6列のまま**（`email` / `nutrients` / `channel` / `nutrients_other` /
`requests` / `created_at`）。2段階化は入力の分割であって、取得項目の追加ではない。

## 禁止事項

- 🔒 **送信後に別ページへ飛ばさない。** 同一ページ内で完了状態に切り替える（`form.js` の既存の 🔒）。
  ステップ2は完了状態の中に置く
- 🔒 **自由記述の注記（`lp.form.freeTextNote`）を一緒にステップ2へ移す。消さない。**
  これはN-01 / N-05（症状・服薬の書き込み口）に対する唯一の防波堤。自由記述だけ移して注記を
  置き去りにしない
- 🔒 **自由記述の中身を解釈して弾かない。** サーバがやるのは長さで切ることだけ
  （上限は `src/lib/waitlist_fields.js`）
- 🔒 チップの並びも許可リストも `src/lib/waitlist_fields.js` が唯一の出所。
  LP側とWorker側で二重に持たない
- 🔒 年齢・性別・体調・服用中サプリを取らない。列を増やさない
- 🔒 GA4に自由記述の本文を送らない。書かれたかどうか（0/1）だけ
- ステップ2を必須にしない（ステップ1の送信時点で登録は完了している）

## 完了条件

1. ステップ1の入力欄がメールアドレス1つだけになっている
2. ステップ1の送信だけでD1にレコードが作られる（ステップ2に進まなくても登録は成立する）
3. ステップ2の回答がD1の**同一レコードに追記**される（新規レコードを作らない）
4. GA4で「ステップ2に到達した数」と「ステップ2を送信した数」が別々に数えられる
5. 自由記述の注記がステップ2に存在する
6. `npm test` が通っている（`tests/worker.test.js` を含む）
7. 🔒 禁止語が出力に含まれていない

## テスト方法

- `npm test` — 描画・バリデーション・Worker
- 本番相当環境で、①ステップ1だけで離脱 ②ステップ2まで完了 の2経路を実際に送信し、
  D1のレコードがそれぞれ期待どおりになることを確認する
- ヘッドレスChrome 375px でステップ1・ステップ2の両方を確認

## 停止条件

- §4の共通のものに加えて:
- 既存レコードへの追記に、現行スキーマの主キー設計では対応できないと分かった場合、
  マイグレーションの是非を相談する（既存データへの影響があるため）
- ステップ2の到達率が著しく低く「見たい成分」の回答数がステップ1の件数を大きく下回る場合、
  検証の主目的が測れなくなる。§決定ログの付帯条件に従って構成を見直す

## 決定ログ

### 2026-09-02 ステップ1をメールアドレスのみにする
- 決定: 1画面目の入力をメールアドレス1項目に絞り、見たい成分・購入先・要望をステップ2へ移す
- 却下案: **ステップ1に「見たい成分」チップを残す案**（メール＋チップの2項目）
  → 「見たい成分」は[validation-plan.md §6](../research/validation-plan.md)で
  **P1で作る成分の決定に直結する検証の最重要項目**と定義されており、`form.js` にも
  🔒「見たい成分はメールアドレスの直下に置く。ここが検証の主目的」と書かれている。
  ステップ2へ移すと、この回答数がステップ2の到達率に丸ごと依存する。
  それでも離脱の削減を優先する判断をユーザーが行った
- 付帯条件: ①ステップ2の到達率と送信率をGA4で必ず別々に計測する
  ②[validation-plan.md §5](../research/validation-plan.md) の判定指標「成分アンケート回答率」の
  **分母がステップ2到達者に変わる**ため、次回の判定時に読み替えを明示する
  ③到達率が低く成分の回答が集まらない場合は、チップをステップ1へ戻すことを再検討する
- 出典: セッションでの決定（2026-09-02）
