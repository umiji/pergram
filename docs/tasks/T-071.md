## 目的

**ブラウザで幅ごとの実測を取る手順が、道具として組織に残っていない。** T-053 / T-057 / T-061 の
3タスクが同じ測定台（Chrome の起動オプション、依存なしの CDP クライアント、
`Emulation.setDeviceMetricsOverride`、`document.fonts.ready` の待機、`.preview` のローカル配信）を
**毎回ゼロから書き起こしている。少なくとも6回。**

飛ばすと何が壊れるか —— **実際に壊れている。**

- T-057 で `document.fonts.ready` を待たない測定台を使い、**文字幅が約16%細く出た値で判断した結果、
  「折り返さないはず」の幅で折り返す設計を一度確定した**
- T-057 で、同じ道具が担当によって動いたり動かなかったりした（設計担当のシェルでは Chrome が
  終了コード 21 で落ちる。`--headless`（旧）と絶対パスの `--user-data-dir` に変えると動く）
- T-061 で、設計と実装が測定台を**それぞれ書いた**。設計が scratchpad に残した `cdp.js` は
  セッションの一時領域にあるだけで、次のタスクには残らない

**T-061 の担当の観測が正確である** ——「タスクファイルの申し送りは『作り直さない』と書いているが、
**残っているのは注意書きだけで、コードはどこにも残っていない**」。

## 変更範囲

- `.claude/skills/browser-measure/`（新設。`SKILL.md` とスクリプト本体）
- `.claude/agents/org-design.md` / `.claude/agents/org-implementation.md` /
  `.claude/agents/org-review.md` の**「使うスキル」の表に1行ずつ足すことだけ**

**`.claude/agents/org-*.md` は配布物だが、スキルの割り当てだけは明示的な例外である**
（`.claude/rules/org-improvement-feedback.md`「例外は2つだけ」）。**それ以外の記述に触れない。**

## 禁止事項

- **依存パッケージを追加しない。** このリポジトリは依存なしで動く（Node 22 標準の `WebSocket` で
  DevTools Protocol を叩ける）。`package.json` に手を入れない
- `.claude/agents/org-*.md` の「使うスキル」以外の記述を変えない
- `.claude/scripts/org-*.py` / `.claude/rules/org-*.md` / `.claude/templates/` に触れない（配布物）
- **スキルの名前に `org-` を付けない。** これはこのリポジトリの持ち物であって配布物ではない
- 製品側（`src/` `scripts/` `worker/` `config/` `locales/`）に触れない

## 完了条件

**すべて、コマンドと出力で確認できること。**

- **A-1** `.claude/skills/browser-measure/SKILL.md` が存在し、`name` と `description` の
  frontmatter を持つ
- **A-2** スキルに含まれるスクリプトを**引数だけを変えて実行**したとき、`.preview` の LP に対して
  幅 375 / 768 / 1440px の3点で、指定した CSS セレクタの**位置（x, y）・寸法（幅, 高さ）・
  `scrollWidth`・可視かどうか**を JSON で返す。**タスクごとにスクリプトを書き足さずに済むこと**
- **A-3** そのスクリプトが `document.fonts.ready` を待ってから測っている。**待つ前と待った後で
  同じ要素の幅を出力し、値が異なることを実測で示す**（T-057 で約16%の差が出た箇所が再現できる）
- **A-4** Chrome が終了コード 21 で落ちる環境でも起動する（旧 `--headless` と絶対パスの
  `--user-data-dir` を使う）。**起動に失敗したときは黙って0を返さず、終了コードを添えて失敗する**
- **A-5** `.preview` をローカル HTTP で配信する手順がスキルに含まれ、**`file://` で開いたときに
  スタイルが当たらない**こと（`dist/` は CSS を `/assets/...` の絶対パスで読む）が注意書きとして
  書かれている
- **A-6** `org-design` / `org-implementation` / `org-review` の3定義の「使うスキル」に
  `browser-measure` の行がある（`grep -l browser-measure .claude/agents/org-*.md` が3件返す）
- **A-7** `npm test` が着手前と同じ結果である（このタスクは製品側に触らないため、増えも減りもしない）

## テスト方法

- **単体/実行確認（実装の担当）**: `.preview` を生成し、A-2〜A-4 を実際に走らせて出力を貼る
- **回帰（テストの担当）**: `npm test` が着手前と同じ結果であること（A-7）
- **実環境確認**: 不要。ローカルで完結する
- **シナリオ（テストの担当）**: **T-057 で実際に誤った箇所**を、このスキルだけで測り直せるかを
  1件流す。指示文へ手順を書き写さずに済むことが、このタスクの目的である

### 2026-09-08 ブラウザ実測の測定台を、指示文への書き写しではなくスキルとして常設する

- 対象: 組織の道具 / ブラウザでの実測
- 決定: `.claude/skills/browser-measure/` を新設し、**手順とスクリプト本体の両方**を置く。
  担当エージェント3体（設計・実装・レビュー）の「使うスキル」へ割り当てる
- 却下案:
  - **Q-011（見た目のタスクに標準フルフローを回し続けるか）の回答を待つ** → **どの案を選んでも
    測定台は要る**（フルフローを回すにせよ縮めるにせよ、幅ごとの実測は必要である）。待つ理由が無い
  - **これまでどおりタスクの指示文へ毎回書き写す** → **それが症状そのものである。** 段1（指示文）は
    既に3タスクで実施され、6回の書き起こしと1回の誤った設計を生んだ
- 付帯条件: 依存パッケージを追加しない。スキル名に `org-` を付けない（配布物ではない）
- 出典: `docs/po-queue.md` の Q-014（PO 回答 A案）/ `docs/org-improvements.md` の I-003

### 2026-09-08 スキルがこのリポジトリの Chrome の版とパスに依存することを、承知の上で受け入れる

- 対象: 組織の道具 / ブラウザでの実測
- 決定: 環境依存を残したまま常設する。**スキルの冒頭に「動かなくなったら指示文へ書き写さず、
  このスキルを直す」の1行を入れる**
- 却下案: 環境非依存に作る → Chrome の起動方法そのものが環境依存の本体であり、抽象化しても
  どこかに具体値が要る。**抽象化のぶんだけ読みにくくなり、直す場所が分かりにくくなる**
- 出典: 組織点検（2026-09-08）の診断「悪化しうるもの」
