## 目的

**日次の価格更新が 2026-08-21 から12回連続で失敗しており、公開中の価格が 2026-08-24 で止まっている。**

`.github/workflows/prices.yml` は毎日 06:00 JST に走るが、2026-08-21 以降すべて 10〜13 秒で
失敗している。失敗を知らせる仕掛けは正しく動いており、Issue #19 が開いたままコメントが積まれている。

**原因は特定済み。** 最新の失敗ログ（run 33569554924）に楽天APIの応答がそのまま出ている。

```
楽天 API が 403 を返しました: {
  "errors": { "errorCode": 403, "errorMessage": "HTTP_REFERRER_NOT_ALLOWED" }
```

`scripts/rakuten_api.js` は `RAKUTEN_APP_URL` を `Referer` ヘッダに載せている（41〜47行）。
403 `HTTP_REFERRER_NOT_ALLOWED` は、**送っている Referer が楽天のデベロッパー画面に登録された
アプリURLと一致していない**ことを意味する。`REQUEST_CONTEXT_BODY_HTTP_REFERRER_MISSING`
（Referer が無い場合）とは別のエラーである。

**直近にドメインを移した経緯がある**（コミット 9bff404「旧ドメインを新ドメインへ恒久転送する」）。
登録済みアプリURLか GitHub Secret の `RAKUTEN_APP_URL` のどちらかが旧ドメインのまま、
という筋が最も濃い。ただし**確認していない。断定せずに切り分けること。**

放置すると、価格が古いまま広告費を投じ続けることになる。T-009 がヒーローに出す単価も
この止まったスナップショットに基づく。

## 決定ログ

### 2026-09-02 403 の原因は GitHub Environment 側の `RAKUTEN_APP_URL` が旧ドメインのまま残っていたこと
- 対象: 価格 / 楽天API
- 決定: **原因は「楽天に登録したアプリ URL」と「CI が送っている Referer」の食い違い。
  食い違っているのは CI 側**。楽天デベロッパー画面の許可リストは新ドメイン
  `pergram.site` に更新済みだが、GitHub Environment `pergram-dev` の
  `RAKUTEN_APP_URL` だけが旧ドメイン（`pergram.pergram-official.workers.dev`）のまま残った。
  **リポジトリ内のコードに誤りは無い。直す先はリポジトリの外**（完了条件 2(b)）。
  タスク登録時の仮説「ドメイン移転が原因ではないか」は**当たっていたが、
  ずれていたのは登録側ではなく CI の secret 側**だった。根拠は3つ。
  1. Referer だけを差し替えて実際に叩くと、`pergram.site` は 200、
     旧 `pergram.pergram-official.workers.dev` は 403 `HTTP_REFERRER_NOT_ALLOWED` を返す
     （`## 証拠` の切り分け1）。**つまり楽天側の登録は新ドメインになっている**
  2. `gh secret list --env pergram-dev` の更新日時で、`RAKUTEN_APP_URL` の最終更新は
     **2026-08-10**。ドメイン移転（2026-08-24）より前で、以後触られていない。
     同じ日に `RAKUTEN_APP_ID` は 2026-08-24 に更新されている＝**移転当日に他の secret は
     見直されたが、APP_URL だけ漏れた**
  3. 失敗の並びが一致する。2026-08-17〜23 は版の廃止による 400。版を直した
     コミット a60fa03（08-24）**以降の全 run が 403 に変わっている**。
     403 は前から在ったが 400 に隠れており、400 を直した瞬間に露出した
- 却下案:
  - **楽天側の登録が旧ドメインのまま** → 却下。それなら `pergram.site` を Referer にした
    問い合わせも 403 になるはずだが、実際は 200 が返る
  - **認証情報（App ID / Access Key）の失効** → 却下。失効なら 401 系か
    `API Configuration not found` になる。403 `HTTP_REFERRER_NOT_ALLOWED` は
    **アプリの特定に成功した後のリファラ審査で落ちている**ことを意味する
  - **API の版がまた廃止された** → 却下。同じ版のエンドポイントに
    正しい Referer を付ければ 200 が返っている
  - **`apiHeaders` の組み立ての不具合** → 却下。`Referer` は `RAKUTEN_APP_URL` を
    そのまま載せており、ローカルの値では通っている。組み立てではなく渡している値の問題
- 付帯条件: 直すのは PO（リポジトリ外）。手順は `## 証拠` に置いた
- 出典: 本タスクでの実測（`## 証拠`）/ GitHub Actions run 32667395324・32779980554・32901405475 /
  コミット a60fa03・fb11d43・9bff404
