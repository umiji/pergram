## 目的
手書き本文を Buffer へ入れる経路を正規化する。**60〜90分/日の手作業を「書く」へ寄せられる唯一の手当て。**

現状は使い捨てスクリプトで直接 `BufferConnector` を叩いており、再現性が無い。
**Buffer は削除も更新もできないので、登録は一度きりの不可逆な操作である。**

## 変更範囲
- 新規: 下書き登録スクリプト（置き場は判断してよい範囲）
- その単体テスト

## 禁止事項
- `.media-agent/` 配下の変更（T-033 / T-034 の担当分である）
- 実際に X へ投稿・返信・いいね・リポストする操作
- タスク台帳 CSV への書き込み
- **`schedule` に `now` / `next` / `queue` を使うこと。** 必ず `draft`（`saveToDraft: true`）で登録する。
  **下書き＋人の目視が、いま唯一の安全弁である**（T-032 §5）
- **検査（T-036）を通っていない行を登録すること**
- `BUFFER_API_KEY` などの秘匿値をコード・ログ・成果物へ書くこと

## 完了条件
1. 台帳（T-035）の1行を `saveToDraft: true` で Buffer へ登録し、返ってきた **Buffer post id が台帳へ書き戻される**
2. **検査（T-036）に落ちた行では、Buffer への呼び出しが起きない**ことを単体テストで示す（送信部分をモックする）
3. 同じ行を2回登録しようとすると止まることを単体テストで示す（Buffer 側で重複を消せないため）
4. **ツリー（1投稿目＋リンクを置く2投稿目）が1回の呼び出しで登録される。**
   `metadata.twitter.thread`（`[ThreadedPostInput!]`）を組み立てること
5. 次の2点を**実際に叩いて確かめ、結果を `## 証拠` に書く**。
   - `saveToDraft: true` と `metadata.twitter.thread` を**同時に指定できるか**
     （できない場合、下書き＋人の目視という安全弁とツリーは両立しない。**そのときは安全弁を優先し、報告する**）
   - `ImageAssetInput` が**公開 URL を受け取るのか、先に別のアップロードを要するのか**
     （T-041 のカード画像を自動で添付できるかが、ここで決まる）
6. 実際に1件を登録した実行出力（または dry-run の出力）が `## 証拠` に貼られている

## 判断してよい範囲

  **自前で組み立てる側を推奨する。本体を触らずに済み、変更がこのリポジトリ内で閉じる**
