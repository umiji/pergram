## 目的
**決定ログ索引 `docs/decisions-index.md` が、失効していない決定を「置き換え済み」と表示し、
実際に失効した決定を「有効」と表示している。**

`.claude/scripts/org-decisions.py` の `apply_supersede()` は、決定を
`by_key = {(タスク, 日付): 決定}` という辞書に入れている。**1つのタスクが同じ日に複数の決定を持つと、
後から入ったものだけが残り、それ以前が消える。** `上書き対象: T-031 2026-09-03` を書くと、
その日の**最後の決定**が問答無用で失効扱いになる。

実害（2026-09-04 に発生済み）: T-044 は `X運用 / 露出の調達`（T-031）を上書きしたが、
索引では `X運用 / リプライ`（T-031、同日、ファイル上の最後）が「置き換え済み → T-044」になり、
**本当に失効した `X運用 / 露出の調達` は「有効」のまま残っている。**

**これは規約の土台を壊す。** `.claude/rules/org-task-ledger.md` は「過去の決定ログは書き換えない。
**失効を知る手段はこの索引だけである**」と定めている。索引が誤るなら、担当エージェントは
失効した決定に従い、生きている決定を無視する。

## 決定ログ

### 2026-09-04 上書き対象の指し先は、括弧の中身（対象 または 要約）で絞る
- 対象: 決定ログ索引 / 上書き対象
- 決定: `上書き対象: T-031 2026-09-03（X運用 / 露出の調達）` のように、**タスクIDと日付の後ろへ
  括弧を書けば1件へ絞れる**ようにした。括弧の中身は、指したい決定の `対象` か見出しの要約を
  そのまま書く（前後に説明の文が続いてよい）。照合は空白・バッククォート・強調記号を落として
  部分一致で行い、対象が入れ子（`A / B` と `A / B / C`）のときは**長く一致したほうが勝つ**。
  **括弧は任意** — 同じ日の決定が1件しか無ければ従来どおり `T-XXX YYYY-MM-DD` だけで定まる。
- 却下案:
  - 決定に一意な ID（連番）を振る → **過去の決定ログへ ID を書き足すことになり、「過去の決定ログは
    書き換えない」という規約そのものを破る。**後方互換も無い
  - 上書きした側の `対象` と一致する決定を暗黙に選ぶ → 書き手が何も指定していないのに機械が
    推測することになり、**黙って別の決定を失効させる今の不具合と同じ性質**である。加えて実データで
    解けない（T-044 の対象は `X運用 / 露出の調達 / リプライ` で、指し先の `X運用 / 露出の調達` と
    完全一致しない）
  - 曖昧なときは候補を全件失効させる → 生きている決定を巻き添えにする。**誤って失効させる害は、
    失効を見落とす害より大きい**（失効した決定に従うと、新しい決定が無かったことになる）
- 付帯条件: 既存の決定ログを1件も書き換えずに、実データの2件（T-031 / T-010）が正しく解決すること。
  T-044・T-020 はどちらも既に括弧付きで書いていた
- 出典: `.claude/scripts/org-decisions.py` の `resolve_target()`、`tests/org_decisions.test.py`

### 2026-09-04 指し先が絞れないときは、どれも失効させずに警告する
- 対象: 決定ログ索引 / 上書き対象
- 決定: 候補が複数あって括弧が無い／括弧がどれとも一致しない／同じだけ一致する候補が複数ある、の
  3つの場合は**1件も失効させず、警告を出す**。警告には候補の件数と、括弧で絞る書き方を入れる。
- 却下案: 従来どおり候補から1件選ぶ（例: 最初の1件、最後の1件）→ **索引は「決定が失効した」ことを
  伝える唯一の手段である。**取り違えると担当エージェントは失効した決定に従い、生きている決定を
  無視する。**黙って間違えるより、警告を出して何も失効させないほうが安い**
- 出典: `.claude/scripts/org-decisions.py` の `resolve_target()`

### 2026-09-04 折り返した次の行を読むのは、`上書き対象` の値だけに限る
- 対象: 決定ログ索引 / 決定ログの読み取り
- 決定: `- 上書き対象:` の値が次の行へ折り返されている場合だけ、続きを連結して読む。
  **他のメタ項目（`- 決定:` 等）の折り返しの扱いは一切変えていない。**
- 却下案: すべてのメタ項目で折り返しを読む一般的な作りにする → **`決定` 欄の連結条件が変わり、
  索引の本文が広範囲に書き換わる。**このタスクの範囲（上書き対象の解決）を超え、差分の検証が
  できなくなる。**「一般化されていないのは書き忘れではない」** —— 後から整理して一般化すると、
  索引の内容が黙って変わる
- 付帯条件: 実データでの差分が、意図した4行（状態2件の訂正＋2件の付与）と対象一覧の件数だけで
  あることを確認した（`## 証拠`）
- 出典: `.claude/scripts/org-decisions.py` の `parse_decisions()`
