## 目的
`.media-agent/` 配下の設定・型・数字が、実データと運用の実態から離れている。
**このまま AI に生成させると、事実として誤った投稿が出る。**

判明している食い違い:
- **含有率「60%〜90%・1.5倍」は誤り。正しくは 33%〜93.6%・2.8倍**（T-031 §1.6 / T-032 G-13）
- **`not-comparable` の「1食の粉量 13g〜100g、12通り」は誤り。** 46製品中12件は「1食100g」ではなく
  栄養表示が「100gあたり」の製品。正しくは **13g〜30g・11通り（1食表示の34製品）**（T-031 §1.6a）
- playbook の例文2本が X の重み付き280字を超えている（型A 296 / 型D 302）。**そのままでは投稿できない**
- `strategy.md` が「1日3件まで」と書いているが、`content.posts_per_day` は 2（T-032 G-11）
- `config.yaml` の persona 曜日割当に `beauty-first`（水・日）が残っている。**T-031 §6.4 で運用から外す判断**
- `x_search` が無効で、露出層リプの相手を機械で見つけられない（T-031 付録A A-8）

## 完了条件
1. `strategy.md` と該当 playbook から含有率の誤記（60%〜90% / 1.5倍）が消え、**33%〜93.6% / 2.8倍**になっている
2. `playbooks/not-comparable.md` の粉量が **13g〜30g・11通り（1食表示の34製品）**＋「100gあたり表示が12製品」になっている
3. `playbooks/*.md` の例文がすべて **X の重み付き280字以内**（CJK は1文字2）であることを、計測スクリプトの出力で示す
4. `strategy.md` の投稿本数が `content.posts_per_day`（2）と一致し、重み付き280の上限が明記されている
5. `config.yaml` の persona 曜日割当から `beauty-first` が外れている
6. `x_search` が有効化され、`filters` に `min_faves:` を含む検索演算子が設定されている
7. `media-agent config` と `media-agent doctor` の実行出力が `## 証拠` に貼られ、**新たな検証エラーが出ていない**

- **（2026-09-04 追加・T-044 の結果による）検索演算子 `from:` が最新タブで実際に効くことを、1回手で確かめて結果を `## 証拠` に残している。** 効かない場合は実装を進めず報告する（露出層リプの主経路が成立しないため、設計の側の問題である）
