## 目的

T-047 で CSP を直し、GA4 の計測は本番で復旧した（ビーコン12本を実測で確認）。
**しかし Google 広告のコンバージョン計測だけ、本番で2件のCSP違反が残っている。**

```
Connecting to 'https://www.google.co.jp/pagead/1p-conversion/18396158699/'
violates ... "connect-src ..." The action has been blocked.
```

Google 広告は 1st-party コンバージョンを**閲覧者の国別ドメイン**（日本なら `www.google.co.jp`）へ送る。
T-047 では `www.google.com` を許可したが、`.co.jp` は別ホストなので届いていない。

**ローカル配信では踏めない。** 国別ドメインは本番の実環境でしか現れず、T-047 の
ローカル実測（違反0件）をすり抜けた。飛ばすと T-007「広告のコンバージョン計測の
疎通確認」が通らない。

## 変更範囲

- `src/build/headers.js` の `MEASUREMENT_CONNECT_SRC`
- `tests/headers.test.js`

## 禁止事項

- `https://*.google.com` のような広い書き方に逃げない。**必要なホストだけを列挙する**
- `connect-src` に `https:` / `*` を書かない
- T-047 で入れた既存のホスト・テスト・`withOrigin` の出し分けを変えない
- CSP の他のディレクティブを触らない

## 完了条件

1. `connect-src` に `https://www.google.co.jp` を含む（トークン完全一致のテストで検査）
2. `npm test` が通る
3. `npm run build` が成功し、`dist/_headers` に反映されている（実出力を証拠に貼る）
4. **本番デプロイ後の実測で、`/ja/` のCSP違反が0件になっている**（実施者はオーケストレーター）

## 判断してよい範囲

- 日本以外の国別ドメイン（`google.co.uk` 等）を先回りして足すかどうか。
  **既定は足さない**（禁止事項「必要なホストだけを列挙する」）。US市場を出す段で
  実測して足すのが正しい順序

## 申し送り

**T-047 で3回踏んだ罠の4例目である。** 順に、(1) ワイルドカードは裸のホストに
マッチしない、(2) ディレクティブが違えば許可は効かない、(3) 1つ塞ぐと次の層が出る、
そして今回 (4) **ローカル実測は本番の全経路を再現しない**。

T-047 のレビュー指摘 R-3（CSPに `report-to` が無く、本番で新しい違反層が出ても
誰も気づかない）が、まさにこの形で現実になった。**R-3 の対応を先に入れると、
この種の残件を実測して回らずに検知できるようになる。**
