# T-052: 規約が「サーバが保持してよい列」の実態と食い違っている

## 目的

**T-051 で `request_signal` テーブルが増えたが、規約はそれが存在しない前提のままである。**

`.claude/rules/pergram-compliance.md` の「データ保護」節は
**「サーバが保持してよいのは、待機リストの6列と、価格アラートの監視製品ID のみ」**
と書いており、この文書は `paths:` を持たないため**毎セッション読まれる**。

放置すると2つのことが起きる。

1. **理由を知らない担当が `request_signal` を「規約違反だから」と削る。**
   規約は実装より強い建て付けなので、食い違えば規約が勝ってしまう
2. 逆に、規約が実態と違うと分かった時点で**規約全体が信用されなくなる**

加えて同節は「**列**を足すときは `worker/schema.sql`・`worker/migrations/`・
`tests/worker.test.js` を必ず揃える」としか言っておらず、
**新しいテーブルを足す場合の手順を持たない。** T-051 は正しい手順を踏んだが、
それは実装担当の判断であって規約に書かれていたからではない。

## 変更範囲

- `.claude/rules/pergram-compliance.md` の「データ保護」節
- 必要なら `docs/product/requirements.md` §3.4 / §10.1（保存するデータの定義）

## 禁止事項

- 🔒 **保持してよいものの範囲を、この機会に広げない。** 直すのは「実態に追随していないこと」
  だけであり、新しく何かを保存してよくする作業ではない
- 🔒 `request_signal` が **UUID と日時の2列だけである**という制約を緩めない。
  IP・User-Agent・リファラ・成分・自由記述を入れてよいと読める書き方にしない
- コードを変更しない（規約文書の修正のみ）

## 完了条件

1. `.claude/rules/pergram-compliance.md` に `request_signal` テーブルの記述があり、
   **持ってよいのが UUID と日時の2列だけであること**が明記されている
2. **新しいテーブルを足すときの手順**が書かれている（`worker/schema.sql`・
   `worker/migrations/`・`tests/worker.test.js`・この規約の4つを揃える、等）
3. なぜ匿名シグナルが例外として認められたのか（**個人を識別できるものを何も持たないこと**が
   その理由である）が読み取れる
4. `python .claude/scripts/org-check.py` が新しい警告を出さない
5. 既存の禁止事項（N-01 / N-05、自由記述の扱い、GA4 へ個人識別情報を送らない）が
   一字も弱まっていないこと

- `request_signal` の列は `id TEXT PRIMARY KEY`（UUID v4）と `created_at TEXT NOT NULL` の2つだけ

  （`tests/worker.test.js` が「UA / page を混ぜたら 400」で固定済み）
- IP・User-Agent・リファラの保存もログ出力も無い
- 既存の `waitlist` テーブルは6列のまま変わっていない
