## 目的

ヒーローとヘッダに「ベータ版を使ってみる」と「待機リストに登録」が同じ強さで並んでいる。
訪問者は**すでに使えるのか事前登録なのかを判断できない**。

さらに、ベータ版の遷移先（`/ja/protein/`）は現在この状態にある。

- `src/build/crawl.js` で **robots.txt によりクロールを塞いでいる**（β版のプレースホルダ価格が出ているため）
- `src/templates/products/item.js` の `PLACEHOLDER_MERCHANTS` により、楽天以外の価格欄に
  **`¥X` / `¥XXXX` が表示される**

つまり、ベータ版を押した先で「金額が伏せられた表」に着地する。失望離脱の受け皿になっており、
そこから待機リストまで戻ってくる動機がない。

**測っているのは購入ではなくメール登録**であるため、主CTAは待機リストに寄せる。
ただしベータ版の導線を消しはしない — 実データ46件の単価順一覧は本物であり、
遷移先ページの利便性は品質スコアの構成要素でもある。

## 変更範囲

| ファイル | 変更内容 |
|---|---|
| `src/templates/lp/hero.js` | ヒーローとヘッダのボタンの強さを入れ替える。待機リストを `btn--signal`、ベータ版を `btn--subtle` かテキストリンクへ |
| `locales/*.json` | 上記に伴う文言。ベータ版側は「何が見られるか」を名乗らせる（操作の結果をそのまま書く） |
| `src/assets/lp.js` | 変更不要の見込み。`data-cta` の値は変えない（GA4の `cta_click` の比較可能性が切れるため） |

## 禁止事項

- 🔒 **`data-cta` の値を変えない。** `hero_beta` / `hero_waitlist` / `header_beta` / `header_waitlist` は
  GA4の `cta_click` のパラメータであり、変えると変更前後の比較ができなくなる
- 🔒 ベータ版の導線を**完全に削除しない**。押せる場所を残したうえで優先度だけ下げる
- 🔒 禁止語を使わない（`おすすめ` `安心` `話題の` 等）。ボタンは操作の結果をそのまま名乗る
- 🔒 文言をテンプレートに直書きしない。すべて `locales/*.json` の翻訳キー経由
- 🔒 色・寸法をコンポーネントに直書きしない（`src/styles/tokens.css` が唯一の出所）
- `/ja/protein/` のクロール設定や `PLACEHOLDER_MERCHANTS` に手を出さない（本タスクの範囲外）
