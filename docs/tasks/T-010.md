## 目的

skill を回して実際に投稿し、**どのペルソナ・どのトピック・どの型が反応を取るかを
実測で知る。** validation-plan.md 段1（データコンテンツの反応テスト）の母数は
X / note のオーガニックで取るのが現実的、と決まっている。

🔒 有料広告は獲得チャネルにならない（validation-plan.md §1）。ここが本命。

## 変更範囲

コード変更なし。運用と記録のみ。
ただし運用で分かったことは skill の reference に反映する（型が古びたら書き直す）。

## 禁止事項

- 🔒 `npm run x:lint` で error が残った文章を投稿しない
- 🔒 `npm run x:facts` に出ていない数字を書かない（価格は毎日動く）
- 🔒 同じペルソナに2本続けない / 単価の話は3本に1本まで / 同じ型を3回続けない
- 🔒 画像は必要なときだけ作る（`/image`）。毎回付けない
- 会話を増やすために煽らない（通報 -234.0 = いいね468個分）
- 需要が大きいからといって「効果」「飲むタイミング」「おすすめ」を扱わない（N-02 / N-03）

## 完了条件

1. 8本以上を投稿し、各投稿について ペルソナ / トピック / 型 / メッセージ を記録している
2. 3ペルソナ（P-A / P-B / P-C）すべてに最低1本ずつ当てている
3. 単価の話が全体の 1/3 以下に収まっている（`npm run x:feed` の偏り表示で確認）
4. 各投稿の反応（いいね / リプライ / リポスト / インプレッション）を記録している
5. リプライが付いた投稿すべてに返信している（返信はいいねの10倍以上の重み）
6. 反応の良かった型・悪かった型を `## 証拠` にまとめ、
   必要なら `reference/formats.md` `reference/topics.md` を更新している

## テスト方法

投稿前は毎回:

```bash
npm run x:facts
npm run x:feed
npm run x:lint -- draft.txt --feed
```

投稿後は X アナリティクスの数値を記録する。
🔒 **他人のインプレッションは見えないので、見えない項目は空欄のままにする**
（docs/research/x-post-corpus.md の収集ルールと同じ）。

## 停止条件

- 通報・ミュートが観測できるほど反応が悪い場合、続けずに型とトピックを見直す
- β版の制約（他ストアの価格欄が表示例）を誤解させる反応が付いた場合、
  投稿を続ける前に文言を直す
