## 目的
`/media-method` の中で規則が正面から矛盾していた。系統2が「文章の型は業界を超える。**題材は借りない**」と書く一方、骨格の採用条件4が「**題材が personas/ の誰かの困りごとに触れている**」を要求している。他ジャンルの型はこの2つを同時に満たせない。2026-09-08 の実行ではこの矛盾を「題材が合うジャンルを探す」方向へ解いてしまい、価格比較ジャンルへ絞り込んだ結果、骨格が0本になった。**型の抽出とペルソナ照合を段として分離しないと、同じことが必ず再発する。**

## 決定ログ

### 2026-09-08 型の抽出とペルソナ照合を別の段に分ける
- 対象: X運用 / 投稿メソッドの手順
- 決定: `/media-method` は①型のリサーチ（題材不問）と②定型手順化までを担当し、ペルソナ・テーマとの照合は③へ移す。骨格の採用条件4を「題材がペルソナの困りごとに触れているか」から「題材を入れ替えても成立するか（スロットとして書けているか）」へ差し替える
- 却下案: 採用条件4を残したまま、題材が近いジャンルを探して両立させる → 2026-09-08 に実際にこれをやり、母集団が 1 クエリ 3〜5 件まで縮んで骨格が 0 本になった。他ジャンルの投稿が自分の読み手の困りごとに触れているはずがないので、両立は構造上不可能
- 出典: PO 指摘（2026-09-08 セッション内）と `.media-agent/x/pergram-jp/method-log.md`

### 2026-09-08 骨格に `accepts_numbers` を必須の欄として持たせる
- 対象: X運用 / 骨格の書式
- 決定: 各骨格に「この型は数値の羅列を受け取れるか」（yes / no / conditional）を持たせ、④でテーマを流し込むときの相性判定に使う
- 却下案: ④で毎回判断する → 共感だけで伸びる型に数字を入れて壊す失敗を、ドラフトのたびに繰り返すことになる
- 出典: セッション内の判断、成果物なし
