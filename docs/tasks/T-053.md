## 目的

**PO がプレビューを見て「デザインがバラバラ」と指摘した。** 主観の問題ではなく、
製品一覧の縦に並ぶ4つのセクションが**別々のデザイン語彙**で書かれている。

| セクション | クラス | 背景 | 枠線 | 角丸 | パディング |
|---|---|---|---|---|---|
| 単価の出し方 | `.explainer` | `--surface`（白） | `--line`（薄グレー） | `--radius` 14px | `--space-4` 16px |
| 注意事項・広告表示 | `.notice` | `--fill-panel`（グレー） | **無し** | `--radius-interactive` 8px | `--space-3` 12px |
| 要望の帯 | `.request-band__inner` | `--signal-band`（橙） | `--signal-edge` | `--radius-lg` 16px | `--space-6` 24px |
| 段のカード | `.request-flow__step` | `--surface`（白） | `--signal-edge` | `--radius-lg` 16px | `--space-6` 24px |

**角丸3種・背景3種・枠線3種・余白3種が縦に並んでいる。** 同じ階層の情報が
4通りの見た目を持つと、読み手は「これは別の種類の情報だ」と誤って受け取る。

加えて、実画面の確認で**PO の指摘以外に2件の不具合**が見つかっている（後述の完了条件 B-5 / B-6）。

文言側の問題は、**要望ボタンを押した直後に出る文が、押した人の行動を否定していること**である。
現在の `request.surveyLede` は「回答は任意です。リクエストはすでに受け取りました。」で、
**礼を言う前に免責から入っている。** PO の指示は、礼と依頼を先に置き、この免責文を消すこと。

## 禁止事項

- **`tokens.css` の既存トークンの値を変えない。** `--signal` / `--signal-hover` /
  `--line-control` は WCAG 2.2 AA のコントラスト比を根拠に固定されている（🔒 コメントあり）
- **`.check-other` を改名しない。** `tests/render.test.js` の検査がこの綴りを見ている
- **`.request-flow__heading` のクラス名を変えない。** `src/assets/request.js` が
  フォーカス移動に使っている
- **段の順序を変えない**（アンケート → メール → 支援）
- **`data-cta` / `data-request-*` / `aria-controls` の値を変えない。** GA4 の前後比較が切れる
- **押下数を画面に出さない**（景表法）。**リクエスト数を並び順に使わない**（N-03）
- **成分の効能・効果に触れる文章を書かない**（N-02）。文言は既存の範囲内で言い換えるだけ
- LP（`src/templates/lp/`）の構造そのものは変えない。`.request-*` は共用なので
  **LP 側の見た目が壊れていないことは確認する**が、LP 固有の改造はしない

## 申し送り

**PO の指示の原文（要旨）:**
1. 単価の出し方・注意事項・リクエストの各セクションのデザインがバラバラ。統一感を出すこと
2. ボタンが左端に寄っていてダサい

   「リクエストありがとうございます。／もしよければ任意で詳しくご要望をお聞かせください。」を入れる
4. 「回答は任意です。リクエストは既に受け取りました」は削除
5. 成分回答した段・リクエストを受け取った表示・メールで知らせる段で、
   フォント・文字色・サイズが違う
6. **デザイナーロールをアサインし、そのエージェントに徹底的にデザインさせること**

### 2026-09-08 面の統一は「見た目を揃える」ではなく「役割の数を減らす」で解く
- 対象: 製品一覧 / 面のデザイン

### 2026-09-08 面の役割を3つに固定し、値の出所を `--panel-*` トークンへ寄せる
- 対象: 製品一覧 / 面のデザイン
- 決定: 縦に積まれる箱の役割を **A 読む面（カード）/ B 呼びかけの面（帯）/ C 注記（面を持たない）**
  の3つに固定する。**A と B は角丸・余白・枠線の太さを完全に共有し、色だけが違う**。
  値は `tokens.css` へ足す `--panel-bg` / `--panel-border` / `--panel-radius` /
  `--panel-pad` / `--panel-pad-lg` / `--panel-call-bg` / `--panel-call-border` から引き、
  コンポーネント側に直書きしない。**既存トークンの値は1つも変えていない**
  （新トークンはすべて既存トークンの別名で、新しい色も寸法も足していない）
- 却下案:
  (1) 各セクションの角丸・余白を目視で合わせる → 値を揃えても**出所**が揃わないので、
      次にセクションが増えたときまた別の値が直書きされる。今回の食い違いはそうやって生まれた
  (2) `.surface` のような基底クラスを作ってテンプレートへ付与する →
      `.p-item` は T-053 の変更範囲外でクラスを足せない。トークンなら
      テンプレートを触らずに出所を1箇所にできる
  (3) 面の役割を4つにし「注記の面」を灰色の箱として残す → 3つに収まるものを4つにすると、
      次の1つを足す言い訳になる
- 出典: docs/design/design.md「面の体系と字送りの階層（2026-09-08 / T-053）」§1〜§2

### 2026-09-08 要望ボタンは 900px 以上で「左に文・右にボタン」の2列にする

### 2026-09-08 空の器は「段そのものを畳む」で消す。フォームの hidden は維持する
- 対象: 要望導線 / 段の開閉
- 決定: `collapseStep()` でフォームを隠すのに加えて**段そのものを `hidden` にする**。
  `finishStep()` は完了文言を出すので段を戻す。あわせて
  `.request-flow__step:first-child { margin-top }` を
  `.request-flow:has(> .request-flow__step:not([hidden]))` の側へ移す
  （先頭の段を畳むと2番目の段が余白を失うため）
- 却下案:
  (1) CSS の `:has()` だけで消す → 二重否定の `:has()` は読めず、次に触る担当が意味を復元できない
  (2) 飛ばしたときにフォームを元へ戻して段を初期状態へ返す → 既存テスト
      「飛ばした段でもフォームは畳まれ、次の段が開く」が `form.hidden === true` を検査している。
      **視覚の修正にテストの書き換えを混ぜない**
- 付帯条件: 段を畳んでも要望ボタンの `aria-expanded` は `true` のまま残る（WCAG 4.1.2）。
  `false` へ戻すと「押し直すと空の段が開く」という別の不整合が出るため、
  **状態機械の設計として別タスクへ送る**。現状（空の器が実際に見えている）より悪化はしない
- 出典: docs/design/design.md 同節 §5
