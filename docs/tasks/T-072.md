## 目的

**ブラウザで幅ごとの実測を取る手順が、道具として組織に残っていない。** T-053 / T-057 / T-061 の
3タスクが同じ測定台（Chrome の起動オプション、依存なしの CDP クライアント、
`Emulation.setDeviceMetricsOverride`、`document.fonts.ready` の待機、`.preview` のローカル配信）を
**毎回ゼロから書き起こしている。少なくとも6回。**

飛ばすと何が壊れるか —— **実際に壊れている。**

- T-057 で `document.fonts.ready` を待たない測定台を使い、**文字幅が約16%細く出た値で判断した結果、
  「折り返さないはず」の幅で折り返す設計を一度確定した**
- T-057 で、同じ道具が担当によって動いたり動かなかったりした（設計担当のシェルでは Chrome が
  終了コード 21 で落ちる。`--headless`（旧）と絶対パスの `--user-data-dir` に変えると動く）
- T-061 で、設計と実装が測定台を**それぞれ書いた**。設計が scratchpad に残した `cdp.js` は
  セッションの一時領域にあるだけで、次のタスクには残らない

**T-061 の担当の観測が正確である** ——「タスクファイルの申し送りは『作り直さない』と書いているが、
**残っているのは注意書きだけで、コードはどこにも残っていない**」。
