## 目的

**重複チェックが機能していない。** `npm run x:feed` が過去投稿を1件も取得できておらず、
「直近と切り口が被っていないか」を確認できないまま投稿文を作っている状態。

フィード URL は `config/x.json` の `pastPostsFeed`
（`https://politepaul.com/fd/k6l77typtks2.xml`）。2026-08-21 時点、Claude Code の
リモート実行環境からは **egress ポリシーで HTTP 403** となり読めない。
ユーザーのローカル環境で読めるかは未確認。

🔒 これが通らない限り、重複チェックは**落ちずに素通りする**（0件と比較しても常に「近い投稿なし」）。
気づけないまま同じ話を繰り返し、ミュート（-58.8）を踏む。

## 変更範囲

- 実フィードでの疎通確認（コード変更が不要な可能性が高い）
- パーサが実フィードの構造で本文を取れているかの確認 → 取れなければ `src/lib/x_feed.js`
- 読めない場合の代替経路の決定（`config/x.json` の URL 差し替え、または `--file` 運用）

## 禁止事項

- 🔒 読めないまま「重複チェック済み」として投稿文を出さない
- 🔒 取得できない項目を推測で埋めない。本文が取れない item は空のまま扱う
- egress で塞がれている場合、TLS 検証の無効化や proxy の迂回で回避しない

## 完了条件

1. `npm run x:feed` が実際の投稿を新しい順に一覧できる
2. 各 item の本文が**全文**取れている（タイトルだけの状態になっていない）
3. `npm run x:lint -- draft.txt --feed` が過去投稿との近さを数値で出す
4. 既知の投稿と同じ内容の下書きを流したとき、近さが閾値 0.35 を超えて ⚠️ が出る
5. 読めなかった場合、原因（egress / フィード側の仕様）と代替手段を `## 決定ログ` に記録している

## テスト方法

```bash
npm run x:feed                       # 実フィード
npm run x:feed -- --limit 30 --json  # 本文が全文入っているか目視
npm run x:lint -- draft.txt --feed   # 近さの数値が出るか
```

`tests/x_feed.test.js` は RSS 2.0 / Atom / CDATA / 二重エスケープを固定済み。
**実フィードで本文が取れなかった場合は、その構造をテストに追加してから直す。**

## 停止条件

- ユーザーのローカルでも読めない場合、フィード提供元の変更はユーザーの判断を仰ぐ
