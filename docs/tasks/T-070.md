## 目的

**PO 報告（2026-09-08）:**

> Request signal に id, created_at は追加されてるが、メールアドレス入力をしないと waitlist 側に
> レコードが追加されてない。メールアドレス追加しなかった場合もアンケート内容がレコードに
> 追加されるようにしておいてくれ。

**これは仕様どおりの挙動である。** `src/assets/request.js` の 🔒 にこう書いてある ——
「アンケートの回答は、メールアドレスの段を送ったときに相乗りする
（**メールアドレスが無ければ保存しない。保存の鍵がそれしかない**）」。

`waitlist` は `email` が主キーなので（`worker/schema.sql`）、**メールアドレスの無い行は
物理的に入らない。** つまり導線はこうなっている。

| 利用者の行動 | いま残るもの |
| --- | --- |
| ボタンを押す | `request_signal` に1行（id / created_at / page） |
| 成分アンケートに答える | **何も残らない** |
| メールアドレスを入れる | `waitlist` に1行（回答も相乗り） |

**「押した → 成分を答えた → メールは入れない」人の回答を、いま全部捨てている。**
次に何を載せるかを決めるための情報そのものであり、`docs/research/validation-plan.md` の
「成分アンケート回答率」の分子でもある。

### 2026-09-08 匿名のアンケート回答は新しいテーブルへ入れる。既存2つには列を足さない
- 対象: アンケートの保存 / データ保護
- 決定: 新しいテーブル（`request_survey` を想定）を1つ足し、**T-062 の匿名の識別子を主キー**にして
  成分・経路・自由記述を持つ。`waitlist` と `request_signal` の定義は変えない
- 却下案: `request_signal` に列を足す（3列 → 7列）→ **その行の存在理由を壊す。**
  「個人を識別できるものを何も持たないこと」が存在理由であり、自由記述が混ざれば成り立たない
- 却下案: `waitlist` に匿名の行を入れる → **不可能。** `email` が主キーで、SQLite では後から変えられない
- 却下案: メールアドレスを必須にして今の経路に寄せる → 1クリックまで対価を下げた T-050 / T-051 の
  設計を丸ごと巻き戻す
- 出典: セッション内の PO 報告と、`.claude/rules/pergram-compliance.md`「データ保護」

### 2026-09-08 受け口・テーブル・送信本文の形をテスト側で先に決めた

- 対象: アンケートの保存 / 受け口の契約
- 決定: TDD の先行テストを書くにあたり、`## 判断してよい範囲` にある未決の4点を
  **テスト側で確定した**（実装はこれに合わせる）。
  - 受け口: `POST /api/request-survey`。成功は **204 No Content**（`worker/request_signal.js` と同じ）
  - テーブル: `request_survey`。列は `id` / `nutrients` / `channel` / `nutrients_other` /
    `requests` / `created_at` の6つ。`id TEXT PRIMARY KEY`（＝上書きの鍵）、
    `created_at TEXT NOT NULL`。**`waitlist` から `email` を `id` に差し替えた形**
  - 送信本文: `{ id, nutrients, channel, nutrients_other, requests }` **ちょうど一致**。
    `page` を含めない（位置も経路も持たない）
  - 上書き: **実現方法は縛らない。** 検査するのは挙動だけ（同じ id で2度送っても行は1つ、
    後から来た回答が勝つ）。`INSERT OR REPLACE` でも `ON CONFLICT DO UPDATE` でも通る
  - テストの置き場: `tests/request_survey.test.js` 1本（受け口・ブラウザ側・スキーマ・手順書）
- 却下案: 上書き時に「送られてきた値が空なら今ある値を残す」（`worker/waitlist.js` の
  COALESCE 方式）を要求する → **`INSERT OR REPLACE` では実現できない。**
  `## 判断してよい範囲` が両方を許している以上、テストで片方に縛るのは越権
- 却下案: 送信本文に `page` を入れる → `## 判断してよい範囲` の列の構成に無い。
  「どのページか」は `request_signal` が既に持っており、同じ id で突き合わせられる
- 却下案: 自由記述が空のときにキーごと落とす → キー集合ちょうど一致（A-5）と両立しない。
  空は `null` で送る
- 出典: セッション内のテスト設計。成果物は `tests/request_survey.test.js`

### 2026-09-08 何も選ばずにアンケートを送っても1行残す

- 対象: アンケートの保存
- 決定: 成分も経路も選ばず自由記述も空のまま送信した場合も、**行を1つ残す。**
  空を理由にサーバもブラウザも送信を止めない
- 却下案: 空の回答は送らない → **「答えない」の意思表示は skip ボタン（`data-request-skip`）
  が既に担っている。** 送信ボタンを押したのは「送る」という操作であり、
  それを空だからと握り潰すと、分母（`request_survey_view`）と分子の対応が崩れる
- 出典: `src/assets/request.js` の skip の実装。目印は
  `tests/request_survey.test.js`「A-6 何も選ばずに送っても1行残る」
