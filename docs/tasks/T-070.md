## 目的

**PO 報告（2026-09-08）:**

> Request signal に id, created_at は追加されてるが、メールアドレス入力をしないと waitlist 側に
> レコードが追加されてない。メールアドレス追加しなかった場合もアンケート内容がレコードに
> 追加されるようにしておいてくれ。

**これは仕様どおりの挙動である。** `src/assets/request.js` の 🔒 にこう書いてある ——
「アンケートの回答は、メールアドレスの段を送ったときに相乗りする
（**メールアドレスが無ければ保存しない。保存の鍵がそれしかない**）」。

`waitlist` は `email` が主キーなので（`worker/schema.sql`）、**メールアドレスの無い行は
物理的に入らない。** つまり導線はこうなっている。

| 利用者の行動 | いま残るもの |
| --- | --- |
| ボタンを押す | `request_signal` に1行（id / created_at / page） |
| 成分アンケートに答える | **何も残らない** |
| メールアドレスを入れる | `waitlist` に1行（回答も相乗り） |

**「押した → 成分を答えた → メールは入れない」人の回答を、いま全部捨てている。**
次に何を載せるかを決めるための情報そのものであり、`docs/research/validation-plan.md` の
「成分アンケート回答率」の分子でもある。

## 禁止事項

- **🔒 `waitlist` に列を足さない。6列で打ち止め**（T-058）。`email` が主キーである以上、
  匿名の行はそもそも入らない
- **🔒 `request_signal` に列を足さない。3列で打ち止め。**
  「個人を識別できるものを何も持たないことが、この行の存在理由である」（`worker/request_signal.js` が正典）。
  **自由記述をこの行に混ぜない**
- **🔒 IP・User-Agent・リファラを保存しない**（どのテーブルでも）
- **🔒 ページ内の位置（上の帯 / 下の帯）を保存しない。** 位置は GA4 の `data-cta` が持つ
- **自由記述の中身を解釈して弾かない**（N-01 / N-05）。誤検知で正当な要望を捨てるほうが害が大きい。
  サーバがやるのは**長さで切ることだけ**（上限は `src/lib/waitlist_fields.js`）
- **自由記述の本文を GA4 へ送らない。** 書かれたかどうか（0 / 1）だけを数える
- **回答数・人数を画面に出さない**（N-03 / 景表法）
- **メールアドレスをこの新しいテーブルに入れない。** 入れた瞬間に匿名でなくなる
- 帯の見た目（T-061 で確定）を触らない
