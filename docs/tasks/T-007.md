## 目的

Google広告の管理画面に「最近のコンバージョンがありません」と出ている。
現状の9クリック・0登録では、**「本当に誰も登録していない」のか「登録は届いているが計測が落ちている」のか
区別がつかない**。改善サイクルはコンバージョンが数えられることが前提なので、ここを最初に確定させる。

登録が届いているかどうかの正はD1である（[T-005](T-005.md) テスト方法）。
確認すべきは、D1に届いたものがGA4とGoogle広告まで伝わるかの3点の突き合わせ。

## 変更範囲

原則としてコード変更なし。管理画面の設定確認と、本番LPからの実際のテスト送信。

| 見る場所 | 確認すること |
|---|---|
| 本番LP（`/ja/`） | 実際にテスト用アドレスで登録を1件送信し、完了状態に切り替わるか |
| D1 | 上記のレコードが `waitlist` テーブルに入っているか |
| GA4 リアルタイム | `waitlist_submit` イベントが着弾するか。あわせて `lp_view` の `source` が `google` になるか（UTM付け忘れの検知。[google-ads-first-campaign.md](../ops/google-ads-first-campaign.md) (4-3) が未完了のまま） |
| Google広告 コンバージョン | GA4からインポートした `waitlist_submit` が**主要コンバージョンとして有効**か、ステータスが「未確認」で止まっていないか |

コード変更が必要になった場合に触れてよいのは `src/assets/lp.js`（イベント送信）のみ。

## 禁止事項

- 🔒 **Google広告専用のコンバージョンタグを別途追加しない。**
  外部スクリプトを足すと `src/build/headers.js` のCSP許可リストの変更が必要になる
  （[google-ads-first-campaign.md](../ops/google-ads-first-campaign.md) (0-4) で明示的に排除済みの選択肢）
- 🔒 テスト送信のアドレスに個人のメールアドレスを使わない。使い捨てを使い、確認後にD1から削除する
- 🔒 GA4に自由記述の本文を送らない。テスト送信でも同じ（書かれたかどうかの0/1だけ）
- 計測が落ちていた場合でも、原因の切り分けが済むまでLP側のコードを直しにいかない

## 完了条件

1. 本番LPからのテスト送信が1件、**D1に実レコードとして存在する**ことをクエリ結果で示せている
2. 同じ送信がGA4のリアルタイムに `waitlist_submit` として現れたか、**現れなかったかが明記されている**
3. Google広告のコンバージョン設定画面で、`waitlist_submit` のステータスと「主要コンバージョン」指定の
   実際の値が記録されている
4. 上記3点のうち途切れている箇所が特定されている（全て繋がっている場合は「登録が実際にゼロ」と確定する）
5. テスト送信したレコードがD1から削除されている
6. コードを触った場合は `npm test` が通っている
