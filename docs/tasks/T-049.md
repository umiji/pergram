## 目的

**起票時、`main` で `tests/hero_ranking.test.js` が2件落ちていた。**

⚠️ **2026-09-07 再実行時点で、10件すべて通っている（オーケストレーター確認済み）。**
価格スナップショットの日次更新で実データが動いた結果、たまたま記録値と一致した状態にある。
**根本原因（ヒーロー3件を `HERO_PRODUCT_IDS` で手動指定しており、実データの変動に追随しない）は
解消していない。次の価格更新で再び落ちうる。** 本タスクは閉じない。

```
完了条件2: ヒーローの各行が、その製品の実データの単価と袋価格を出している
  → rakuten:myprotein:10001199 の行の単価が ¥4.0 ではありません
T-009 が記録した順位・単価が、いまの実データと一致する
  → rakuten:myprotein:10001199 の実際の単価が 3.9889 から動いています（3.59 !== 3.9889）
```

原因は価格スナップショットの日次更新で実データが動いたこと。T-009 が
`HERO_PRODUCT_IDS` に手動指定したヒーロー3件の記録値が追随していない。

**このテストは「ヒーローの手動指定が実データから乖離したこと」を検知するための
仕掛けであり、落ちていること自体は仕掛けが機能している証拠である。**
ただし落ちたまま放置すると、`main` が常に赤い状態になり、
**本当に壊れたときの検知が効かなくなる**。

## 変更範囲

## 禁止事項

- 🔒 独自スコアや加重平均で並べ替えない（N-03）
- `HERO_PRODUCT_IDS` を空配列に戻す判断を単独でしない（β版の暫定措置の解除は
  design.md「ヒーローのランキングカードの例外」の解消条件に従う）
