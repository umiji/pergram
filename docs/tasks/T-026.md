## 目的

**T-011 のレビューが、T-011 由来ではない既存の問題として2件を報告した。**
**どちらも T-011 以前から存在する。** ただし T-011 が1登録あたりの POST を1→2に増やしたため、
1件目の面は広がっている。

### 1. レート制限が無い（`worker/index.js:13-15`）

`/api/waitlist` は**認証の無い書き込みエンドポイント**で、レート制限がかかっていない。
共通規約（`~/.claude/rules/common/security.md`）は**全エンドポイントへのレート制限**を求めている。

**この面で何ができるか**（T-011 のレビューが確認した範囲）:
- 第三者が**任意のメールアドレスに回答を「埋める」ことができる**（UPSERT のため）
- **T-011 の UPSERT 修正により、本人がそれを空に戻せなくなった**
  （`COALESCE(NULLIF(...))` は空を無視するため）
- 🔒 **ただし変更前も第三者は同じ経路で上書きできたので、T-011 が悪化させたわけではない**

害は「待機リストのアンケート回答が汚れる」であって、**個人情報の漏洩ではない**
（読み出し経路は無い）。ただし**アンケートの内訳は P1 で整備する成分の決定に直結する**
（`docs/research/validation-plan.md` §5）ため、**汚れると次に何を作るかの判断を誤る。**

### 2. エラーログに個人情報が残りうる（`worker/waitlist.js:108`）

```js
console.error('waitlist insert failed', err)
```

**D1 のエラーオブジェクトに SQL やバインド値が含まれる場合、メールアドレスや自由記述が
Workers のログに残りうる。**

🔒 `.claude/rules/pergram-compliance.md` は「自由記述は**症状・服薬の書き込み口になりうる**
（N-01 / N-05）」としている。**その本文が Workers のログへ落ちる経路は、
サーバが保持してよいものの定義から外れている。**

## 禁止事項

- 🔒 **保存列を増やさない**（`email` / `nutrients` / `channel` / `nutrients_other` /
  `requests` / `created_at` の6列）。**レート制限のためにアクセス記録を待機リストの表へ足さない**
- 🔒 **UPSERT の SQL を変えない。** T-011 のレビューが独立に検証して「正しい」と判定している
- 🔒 **自由記述の中身を解釈して弾かない。** サーバがやってよいのは長さで切ることだけ。
  **レート制限は流量の話であって、内容の検閲ではない**
- 🔒 **IP アドレスを永続化しない。** レート制限に使うのは構わないが、**待機リストの
  レコードと結び付けて保存しない**（`.claude/rules/pergram-compliance.md`）
- 🔒 **エラーログを消さない。** 落とすのは**個人情報だけ**であって、
  何が起きたかが追えなくなってはいけない（`.claude/rules/pergram-ui-copy.md`
  「エラー文は何が起きて、どうすれば直るかだけを書く」の精神を、ログにも当てる）
- 🔒 **正当な利用者を弾かない。** 待機リストは**登録数を測っている実験の途中**である。
  厳しすぎる制限は、測っている数字そのものを壊す
- `src/` を触らない

## 申し送り

**T-011 のレビューが確認した事実**: この面には**読み出し経路が無い。** 第三者にできるのは
「任意のメールアドレスに回答を埋める」ことまでで、**登録済みのメールアドレスや回答を
読み出すことはできない。** したがって**情報漏洩ではなく、データの汚染**である。

**優先度を「高」にしたのは、待機リストの回答が P1 の成分選定に直結するため**
（`docs/research/validation-plan.md` §5）。**汚れた回答で次に作るものを決めると、
気づかないまま間違ったものを作る。**

**閾値の設計で最も気をつけること**: T-011 により、**1人の登録で `/api/waitlist` への
POST が2回**（ステップ1とステップ2）**になった。** 1回しか想定していない閾値を置くと、
**アンケートの回答が全員分弾かれる** —— しかもステップ1は成功しているので、
**登録数だけが伸びて回答がゼロという、原因の分かりにくい壊れ方をする。**

`docs/ops/deploy.md` は **T-016 が実態へ更新済み**である（独自ドメインは `pergram.site`、
2026-08-24 から本番稼働）。**古い前提で読まないこと。**
