## 目的

構造的に空である（T-032 G-03）。一方 Buffer 側には送信済み9件と登録済み下書き4件がある。
投稿は機構の外を通っており、**何を出したかがどこにも残っていない。**

**この2つが無いと、9/9 の Day7 ゲートを判定できない。**

**今日（Day1）の4件は今日出る。出たあとに台帳を作ると本文が回収できない。**

## 申し送り
**PO 回答済み（Q-007 / 2026-09-03）**: 「毎日 Buffer のデータを見ればよいのではないか」との差し戻しを受け、
**このタスクは当初の「本文まで持つ台帳」から2ファイルへ縮小された。**
数字（本文・配信時刻・post id・リンククリック数）の**正典は Buffer である。二重持ちしない。**
このタスクが作るのは、**Buffer が構造的に持てない2つ**だけ ——
(1) 型と読み手のラベル（Buffer はこれを知らず、投稿を更新できないので後付けもできない）
(2) 手動リプの記録（リプは Buffer を通らないが、流入の主戦場である）。
**Buffer の API には投稿の削除・更新の mutation が無い。** 台帳から Buffer を書き換えることはできない。
