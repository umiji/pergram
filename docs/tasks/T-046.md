## 目的

**PO の判断（2026-09-05）で、露出モデルの骨格が変わった。**

> 「リプはおれが手動でやらないといけないんだろ？だったらこのプロジェクトの意味ないやん。
> **自分の投稿でちゃんとインプ稼げるメソッド考えろよ。リプはこっちでやっとく。**」

**これは正しい指摘である。** T-031 / T-044 の設計は露出の主供給源を「他人のスレッドへのリプライ」に
置いていたが、**リプライは人間が手で打つ作業であり、機構が肩代わりできない。**
機構（`.media-agent/`）が生成・検査・登録・集計できるのは**自前ポストだけ**である。
**露出の主経路が機構の外にあるなら、機構を作る意味が薄い。**

したがって **`X_growth_design.md` の骨格を「自前ポスト主軸」へ組み替える。**
リプライは「PO が手でやる補助的な経路」として残し、**設計の中心から外す。**

**推測で組み直してはならない。** T-044 が読んだ一次情報（`xai-org/x-algorithm` @ `9b0dc31`）を
土台にすること。**この組み替えの成否は、一次情報のどの仕組みを使うかで決まる。**

## 申し送り

**PO の判断（2026-09-05、Q-009 への回答）**:
リプライは PO が手動で行う。**機構は自前ポストの露出に集中する。**

**T-044 が確定させた、自前ポストに効く一次情報（すべて出典付きで findings にある）**:

| 事実 | 値 | 効き方 |
|---|---|---|
| リンクをコピーして共有 | `share_via_copy_link` **20.0** | **いいねの40倍。全行動中で最大** |
| リプライ | `reply` 5.0 | 10倍 |
| リポスト | `retweet` 1.0 | **2倍。二次情報の「20倍」は誤り** |
| いいね | `favorite` 0.5 | 基準 |
| **プロフィールをクリック** | `profile_click` **0.0** | **0倍。順位に一切効かない** |
| 通報 | `report` **-234.0** | 一撃で沈む |
| 新規著者ブースト | `ColdStartFollowerCap` = 1000 | フォロワー1,000人以下を優遇。**ただし適用は観測できない** |
| 可視性ラベル | 基本28 + 追加26 = 54種 | ラベルが付くと配信が絞られる |

**`share_via_copy_link` が最大の梃子である可能性が高い。** 「このプロテイン、1gあたりで見ると
3倍払ってる」という種類の情報は、**人が友人へ送る形をしている。** pergram の手持ちのデータは
まさにそれである。**ただしこれはオーケストレーターの見立てであって、裏は取れていない。
あなたが一次情報で確かめること。**

**現状の観測（動かない事実）**: 自前ポスト26本が 17imp 前後。**「優遇する仕組みがあるのに 17imp」
という状態である。** 原因の候補3つのうち③は観測できない。

**Buffer の API はツリーと画像に対応している**（2026-09-03 確認）。
ツリーは2投稿を維持と判定済み（T-044 §5.8）。**自前ポスト主軸へ変えた結果として
本数の判断が変わるなら、決定ログに `上書き対象` を書いて変えてよい。**

**PO の手作業の枠**: 1日60〜90分。**リプライを PO が引き取ったので、
機構側が使ってよい「人の判断」の時間は増えている。** ただし増えた分を全部使ってよいとは限らない。

- 決定: プロフィールクリック率は事業上の変換指標としては維持するが、
  「クリック率の高い型を伸ばせば imp（配信量）も伸びる」という因果の判定には使わないと明記した。
  imp を伸ばす判定には `share_via_copy_link` に相当する行動（共有数、無ければ imp の伸び率）を使う。
  `X_kgi_2weeks.md` 自体は書き換えず、必要な改訂点として一覧に報告した（T-039 へ送る）
- 却下案: プロフィールクリック率を imp 成長の先行指標として使い続ける → 重みが0.0であるため
  クリック率と将来の配信量の間に因果が無いことが一次情報で確定しており、
  先行指標として使うと誤った打ち手（クリック率の高い型を追いかける）につながるため却下
- 出典: `docs/Marketing/X_algorithm_findings.md` §1.2・§1.3 W-2
