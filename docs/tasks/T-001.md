## 目的

広告出稿の判定は、LPのファネル（`lp_view` → `cta_click` → `waitlist_start` → `waitlist_submit`）を
GA4で読めることが前提になっている（[docs/ops/google-ads-first-campaign.md](../ops/google-ads-first-campaign.md) §3・§4）。

送信コード側はほぼ入っているが、**ヘッダCTAの計測用属性が未コミットのまま**で、
GA4管理画面側にもβ版画面の新イベント（`filter_click` / `list_show_more`）が登録されていない可能性がある。
このまま広告を回すと、支払ったクリックがどこで落ちたのか分からないまま7日が終わる。
広告テストの3つの目的（[同 §0](../ops/google-ads-first-campaign.md)）のうち「LPのメッセージが刺さるか（CVR）」が測れなくなる。

## 禁止事項

- 🔒 自由記述（`nutrients_other` / `requests`）の**本文をGA4に送らない**。書かれたかどうかの 0 / 1 だけを数える
- 🔒 メールアドレスその他の個人識別情報をイベントパラメータに含めない
- 🔒 健康状態・体調・服薬に関する値をパラメータに含めない（[requirements.md §11.1](../product/requirements.md)）
- **新しい外部スクリプトを足さない。** Google広告専用のコンバージョンタグを別途入れると
  [src/build/headers.js](../../src/build/headers.js) のCSP許可リスト変更が必要になる。GA4連携で完結させる
- イベント名・パラメータ名の設計変更はこのタスクの範囲外。今あるものを本番で動かすことに限定する
- `.env.example` の削除差分はこのタスクと無関係。ここでは触らない（別途扱いを決める）

## 決定ログ

### 2026-08-18 新規カスタムイベントとして追加する（既存イベントへのディメンション追加ではなく）
- 決定: β版画面の絞り込み・もっと見るは `filter_click` / `list_show_more` という新規イベントで送る
- 却下案: 既存イベントにカスタムディメンションを足してパラメータで区別する案 → GA4上の探索が
  イベント名で絞れなくなり、ファネル定義が読みにくくなるため。効果に大差がないならイベント名で明示的に分ける方を採る
- 出典: 2026-08-17 のセッション判断（成果物なし）

### 2026-08-18 GA4管理画面への登録はGUI手動ではなくAdmin API経由のスクリプトで一括投入する
- 決定: サービスアカウント（`.env.local` の `GOOGLE_SERVICE_ACCOUNT_KEY`）でGA4 Admin APIを叩き、
  カスタムディメンション17個・キーイベント2個（`waitlist_submit` / `affiliate_click`）を一括登録した
- 却下案: GUIで1件ずつ手動登録 → 17件を毎回スペル完全一致でタイプするのは手間・事故率とも高い。
  `gcloud auth print-access-token` によるショートカットも検討したが、ローカルに `gcloud` CLI 未導入のため
  サービスアカウント方式を採った
- 付帯条件: 登録スクリプト（`register-ga4-events.js` / `patch-ga4-dimensions.js`）はリポジトリ外の
  スクラッチパッドに置き、コミットしない。サービスアカウントキーもリポジトリには置かない
- 出典: 2026-08-18 のセッション判断（成果物: スクラッチパッドの2スクリプト、実行ログはこのタスクの証拠欄）

### 2026-08-18 カスタムディメンションの表示名は英語（コードのパラメータ名と一致）、説明文は日本語
- 決定: `displayName` はコード上の `parameterName` と同じ文字列（例: `nutrient_id`）、`description` に日本語の説明を書く
- 却下案: 表示名を日本語ラベルにする案（最初の一括登録時点ではこちらで登録していた） → GA4のUI表示言語が
  英語のため、項目名だけ日本語だと一覧が読みにくく、コードとの対応も追いづらいと判断して後から
  `patch-ga4-dimensions.js` で更新し直した
- 出典: 2026-08-18 のセッション判断（成果物なし）
