## 目的

**OGP 画像だけが古いブランドカラーで出ている。**

| 定数 | `scripts/make_ogp.js` | `src/styles/tokens.css` |
|---|---|---|
| SIGNAL | `#2454E6`（青） | `--signal: #ea580c`（オレンジ） |
| INK | `#16181D` | `--ink: #0f172a` |
| PAPER | `#FAFAF7` | `--paper: #fafaf9` |

CLAUDE.md は「`scripts/make_ogp.js` の定数も tokens.css と同じ値に保つ」と定めており、
現状はその不変条件から外れている。SNS でシェアされたときのサムネイルだけが
別サービスの色に見える。

`scripts/make_x_card.js` は同じ問題を避けるため tokens.css を実行時に読んでいる
（`readTokens()`）。**同じ読み取りを make_ogp にも使えば、二度とずれない。**

## 変更範囲

- `scripts/make_ogp.js` — ハードコードした色定数を廃止し、tokens.css から読む
- `readTokens()` の置き場所（現在 `scripts/make_x_card.js` の export）。
  2箇所から使うなら共有モジュールへ移す

## 禁止事項

- 🔒 16進数を script 側に書き戻さない。色の唯一の出所は tokens.css
- OGP の寸法（1200×630）と `src/lib/site.js` の `OG_IMAGE` の width/height を食い違わせない
  （`tests/render.test.js` が実ファイルと突き合わせている）

## 完了条件

1. `npm run ogp` が tokens.css の現行値で SVG を書き出す
2. 生成物にハードコードされた `#2454E6` が含まれない
3. 色がずれたときにテストで落ちる（`tests/x_card.test.js` と同じ形の不変条件を追加）
4. `npm test` が通る
5. PNG に変換して実ファイルを差し替える場合、`OG_IMAGE` の寸法と一致している

## テスト方法

```bash
npm run ogp
grep -c "2454E6" dist/assets/ogp.svg   # 0 であること
npm test
```

## 停止条件

- OGP 画像の差し替えは実ファイル（`src/assets/images/pergram_logo_ogp.jpg`）にも
  影響する。差し替えるかどうかはユーザーの判断を仰ぐ
