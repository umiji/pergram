## 目的

現在の登録メリットは「公開時の通知」と「リクエストの優先」だけで、
まだ愛着のないサービスにメールアドレスを渡す動機として弱い。

ただし**提示できる価値は実装できる範囲に限られる**。現状のWorkerはD1に保存するだけで、
**メール送信の手段を持っていない**。したがって以下は今のままでは約束できない。

| 案 | 現状での実現性 |
|---|---|
| 登録すると単価比較表を即時配布 | ✗ 送信基盤なし |
| 値下がりをメール/LINEで通知 | ✗ 送信基盤なし。監視製品IDの保存は可 |
| セール時に最安トップ3を配信 | ✗ 送信基盤なし |
| **登録完了画面で現時点の単価一覧を全件見せる** | ○ ビルド済みデータで完結。送信不要 |

**履行できない約束を文言だけ先に書くことはしない。**
本タスクは実装ではなく、どの経路を採るかを決めるための調査。

## 変更範囲

調査とドキュメント化のみ。コード変更なし。

| 調べること | 判断への使い方 |
|---|---|
| Cloudflare Workers から使えるメール送信手段と費用・設定量 | 送信基盤を持つコストの見積り |
| 送信基盤を持つ場合に増える保存列と、データ保護方針との整合 | 列を増やすなら `worker/schema.sql` / migrations / tests を揃える対象 |
| 配信停止（オプトアウト）の実装義務と、特定電子メール法上の表示義務 | 送信を始める場合の必須要件 |
| 完了画面で単価一覧を見せる案の実装量 | 送信基盤なしで出せる価値の上限 |

## 禁止事項

- 🔒 **成分の効能・効果に触れる訴求を作らない（N-02）。** インセンティブは価格と更新頻度で語る
- 🔒 独自の総合スコア・品質スコアを配布物に含めない（N-03）
- 🔒 健康状態・体調・服薬情報を保存しない（N-05）。通知の希望を取る場合も監視製品IDまで
- 🔒 メールアドレスをGA4のイベントパラメータに含めない
- 🔒 禁止語を使わない。「安心」「話題の」等
- **実装しない。** 本タスクの成果物は決定であって、コードではない
