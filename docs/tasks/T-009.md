## 目的

**外部に貼る URL が確定していない。**

| 出所 | 値 |
|---|---|
| `src/lib/site.js` の `SITE_ORIGIN` | `https://pergram.pergram-official.workers.dev` |
| X 投稿の依頼元プロンプト | `https://pergram.site/ja/` |

`x:facts` は site.js から URL を組み立てるため、いまツリーの2投稿目に入るのは
workers.dev のほう。独自ドメインが生きているなら、**投稿・OGP・canonical・
sitemap・robots が全て古いドメインを指したまま外部に出る。**

requirements.md Q-16（ドメイン取得）が未決のままである点も併せて確認する。

## 変更範囲

- `src/lib/site.js` の `SITE_ORIGIN`（🔒 **ドメインの唯一の出所**。ここ以外に書かない）
- 必要なら `wrangler.toml`（カスタムドメインのルート）
- 反映先の確認: canonical / og:url / og:image / sitemap.xml / robots.txt / llms.txt

## 禁止事項

- 🔒 ドメインを2箇所に書かない。`config/x.json` や skill の文書に URL を書き写さない
- 🔒 canonical / og:url を相対パスにしない（SNS のクローラは解決しない）
- 旧ドメインからのリダイレクトを用意せずに切り替えない

## 完了条件

1. 本番の配信ドメインが1つに確定し、`SITE_ORIGIN` がその値になっている
2. `npm run build` 後、`dist/` の canonical / og:url / sitemap.xml / robots.txt が
   すべて同じオリジンを指している
3. `npm run x:facts` が出す LP / 製品一覧の URL が実際に開ける
4. requirements.md Q-16 の記述を実態に合わせて更新している
5. `npm test` が通る

## テスト方法

```bash
npm run build
grep -r "workers.dev\|pergram.site" dist/ | sort -u   # 混在していないこと
npm run x:facts                                        # 出た URL を実際に開く
```

## 停止条件

- ドメインの所有・DNS の状態が不明な場合、切り替えずにユーザーに確認する
