## 目的

要望ボタン（`[data-request-cta]`）は `aria-controls` でアンケートの段を指し、
`aria-expanded` を持つ。段を畳んだ後もこの値が `true` のまま戻らない。
支援技術には**開いていると言いながら閉じている**状態に見える（WCAG 4.1.2）。

**単純に `false` へ戻すと別の不整合が出る** — 押し直したときに、
すでに回答済み（または飛ばし済み）の空の段が開くことになる。
ボタンの状態機械そのものの設計が要るため、T-053 から分離した。

⚠️ **この記述は 2026-09-08 に誤りになった。** T-053 が段そのものを `hidden` にしたため、
`aria-expanded="true"` が指す先は `display:none` になり、WCAG 4.1.2 の不一致は
**名目から実体へ変わった**（R-053-1 / R2-053-1）。優先度を「低」から「中」へ上げている。

## 完了条件
- 1. 段が畳まれている状態でボタンの `aria-expanded` が `false`、開いている状態で `true` である
- 2. 回答済み・飛ばし済みの後にボタンを押しても、**中身の無い段が開かない**
     （T-053 で既に達成済み。**この状態を壊さないことが条件**である）
- 2b. **押し直したときに、画面が無反応にならない。** T-053 の修正で、段が `settled` の後は
     早期 return するため `bringIntoView` もフォーカス移動も走らず、**押しても画面で何も
     起きない**（R2-053-1）。押した人へのフィードバックが失われている。
     いま開いている段（または導線そのもの）が画面に見えること
- 3. 上記を検査するテストがあり、**元の実装へ戻すと落ちる**
- 4. `npm test` が全件通る

## 判断してよい範囲

- 属性を持たせる要素（ボタンか段か）

## 申し送り

T-053 のレビューで出た `R2-053-1`（2026-09-08）:
`src/assets/request.js:107-108` で、段が `settled` になった後に要望ボタンを押すと
早期 return するため **画面上で完全に無反応**になる。修正前は（空の器ごと）段へ
スクロールしていたので、押した人へのフィードバックはこの修正で失われた。
`aria-expanded` の状態機械と同じ場所の話なので、このタスクで一緒に解く。
