## 目的

要望ボタン（`[data-request-cta]`）は `aria-controls` でアンケートの段を指し、
`aria-expanded` を持つ。段を畳んだ後もこの値が `true` のまま戻らない。
支援技術には**開いていると言いながら閉じている**状態に見える（WCAG 4.1.2）。

**単純に `false` へ戻すと別の不整合が出る** — 押し直したときに、
すでに回答済み（または飛ばし済み）の空の段が開くことになる。
ボタンの状態機械そのものの設計が要るため、T-053 から分離した。

**現状より悪化はしていない。** T-053 の変更で新たに壊れるものではない。

## 変更範囲
- `src/assets/request.js`
- `src/templates/request.js`（属性の持たせ方を変える場合）
- `tests/request_unify.test.js`

## 禁止事項
- `data-cta` の値を変えない（GA4 の前後比較が切れる）
- 段の順序を変えない
- 第1段階の匿名シグナル送信の重複抑止（1ブラウザ1件）を壊さない

## 完了条件
- 1. 段が畳まれている状態でボタンの `aria-expanded` が `false`、開いている状態で `true` である
- 2. 回答済み・飛ばし済みの後にボタンを押しても、**中身の無い段が開かない**
- 3. 上記を検査するテストがあり、**元の実装へ戻すと落ちる**
- 4. `npm test` が全件通る

## 判断してよい範囲
- 状態機械の設計（押し直しで何が起きるべきか）。ただし「押下数を画面に出さない」は不変
- 属性を持たせる要素（ボタンか段か）

## テスト方法
- 単体: 実装担当。`tests/request_unify.test.js` へ追加
- 実環境: ヘッドレス Chrome で `aria-expanded` の値を実測する
