## 目的
46製品の外にある商品について、たんぱく質1gあたりの単価をその場で出す手段が無い。
手で楽天を見て計算すると1件2分かかり、**T-031 が提案する型 `price-on-request`
（「この製品はどうですか」に数字で答える）の実行可能件数が 1/6 になる。**

リプライ戦術 T1 の核は「宣伝しない。数字だけ渡す」であり、**その場で数字を出せることが導線そのもの**である。

## 変更範囲
- 新規: 単発計算コマンド（置き場は判断してよい範囲）
- その単体テスト

## 禁止事項
- `.media-agent/` 配下の変更（T-033 / T-034 の担当分である）
- 実際に X へ投稿・返信・いいね・リポストする操作
- タスク台帳 CSV への書き込み
- **推定値で埋めること。** 栄養成分が取れない製品は「取れない」と返す（`.claude/rules/pergram-compliance.md`）
- 元素量換算を通さずに数字を出すこと（🔒 不可逆な設計判断）
- 導出値（含有率・単価）を保存すること（🔒 保存する独立変数は3つだけ）
- 楽天 API の呼び出し口を新設すること。**楽天 API の唯一の出所は既存の実装である**

## 完了条件
1. 商品名または楽天の商品 URL を1つ渡すと、**たんぱく質1gあたりの単価・取得日・出典**が出る
2. 栄養成分が取得できない製品では、**推定せずに「取得できない」旨を返す**ことを単体テストで示す
3. 出力に**取得日が必ず含まれる**ことを単体テストで示す（日付の無い価格は出さない規約）
4. 実際に1件を計算した実行出力が `## 証拠` に貼られている

## 判断してよい範囲
- 実装言語、既存の導出計算をどう再利用するか、出力形式
- 商品名から特定できなかった場合の挙動

## テスト方法
単体: 取得不可時の挙動、取得日の有無。実装担当が書く。受け入れテストは org-test が先に書く。
