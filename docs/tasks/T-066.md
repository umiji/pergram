## 目的
4段の②。①で見つけた型を、書く人がそのまま形にできる設計図へ落とす。**ここで題材を混ぜない。** スロットだけを書き、中身は③④で入れる。

## 変更範囲
- `.media-agent/x/pergram-jp/structures/`

## 禁止事項
- **観測した本文の語句をそのまま書かない。** 固有名詞・製品名・具体的な数値が入っていたら写しである
- 1本にしか無い言い回しを「言い回しの部品」へ入れない
- ペルソナ名を型に紐づけない（③の仕事）
- 140字を超える長さの型を作らない（無料アカウントの天井）

## 完了条件
1. `structures/*.md` が 3本以上ある
2. 各ファイルに次の節が全て埋まっている — `運び（スロット）` / `数値の実体` / `語の水準（トーン）` / `言い回しの部品` / `言わないこと（引き算）`
3. 各ファイルの front matter に `sources: N posts / M authors` があり、N・M ともに 3 以上
4. 各ファイルに **`accepts_numbers:` の欄があり、`yes` / `no` / `conditional` のいずれかが入っている**（その型が数値の羅列を受け取れるか。共感だけで伸びる型に数字を入れると壊れるため、④で選び間違えないようにする）
5. `数値の実体` に書かれた全体の長さが 135 字以内である
6. `言わないこと（引き算）` が空のファイルが無い

## 判断してよい範囲
- 型の名前と id
- スロットの粒度
- `accepts_numbers` を `conditional` にするときの条件の書き方

## テスト方法
ファイルの節の有無と front matter の値による機械的な確認。実環境での確認は不要。

## 停止条件
- 完了条件3を満たす型が3本に届かない場合、**下限を下げずに** T-065 へ差し戻す
