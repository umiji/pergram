## 目的

**本番の CSP が GA4 の計測ビーコンをブロックしており、サイト全体の計測が機能していない。**

現在の GA4（gtag.js）は計測データを `https://analytics.google.com/g/collect` へ送るが、
`src/build/headers.js` の `connect-src` は `https://www.google-analytics.com` しか許可していない。
このためブラウザが送信を拒否し、`page_view` を含む全イベントが GA4 に届いていない。

**タグの読み込み自体は成功するため、画面上は完全に正常に見える。**
落ちるのは最後の送信の一歩だけで、痕跡はブラウザのコンソールにしか出ない。

飛ばすと何が壊れるか: 広告費を使っても効果が測定できない。実害が出ている
（Google 広告 110 クリックに対し GA4 のアクティブユーザーが 2 人）。
X 運用の KGI（14日で 300 アクティブユーザー）も同じ理由で測定不能。

## 禁止事項

- `connect-src` に `https:` や `*` を書いて全許可にしない。**必要なホストだけを列挙する**
- `default-src` を緩めない
- `frame-ancestors 'none'` / `object-src 'none'` / `base-uri 'self'` / `form-action 'self'` を触らない
- `script-src` の `'unsafe-eval'` の条件分岐（支援ウィジェットのある市場だけ）を変えない
- GA4 の測定 ID やイベント定義（`src/assets/lp.js` / `src/templates/layout.js`）を触らない。**本タスクは CSP だけ**
- 🔒 個人識別情報を GA4 へ送る変更を一切入れない（`.claude/rules/pergram-compliance.md`）

## 申し送り

**原因はオーケストレーターがヘッドレス Chrome で実測して特定済み。調査からやり直さないこと。**

実測で得られたブロック済みホストの全量（`connect-src` 違反 17 件 / `script-src` 違反 3 件）:

```
analytics.google.com          ← GA4 の page_view。これが致命傷
www.google.com
google.com
www.googleadservices.com
googleads.g.doubleclick.net
stats.g.doubleclick.net
ad.doubleclick.net
static.cloudflareinsights.com ← script-src 側
```

実際に出ていたコンソールエラー:

```
Connecting to 'https://analytics.google.com/g/collect?v=2&tid=G-VNXR1NWKDR
  ...&en=page_view&...' violates the following Content Security Policy
directive: "connect-src 'self' https://www.google-analytics.com https://codoc.jp".
The action has been blocked.
```

補足: `img-src` は既に `https:` を許可しているため、ピクセル経由で送られる
一部の広告タグ（`www.google.com/ccm/collect` / `rmkt/collect`）は実際に発火していた。
**落ちていたのは fetch / beacon 経由のものだけ**である。この非対称性が
「広告タグは動いているのに GA4 だけ空」という紛らわしい状態を作っていた。

## 決定ログ

### 2026-09-07 計測ホストは定数配列で持ち、支援ウィジェットの `withOrigin` とは別の層に置く
- 対象: CSP / 計測ホストの許可
- 決定: 計測ビーコンの送信先を `MEASUREMENT_CONNECT_SRC` / `MEASUREMENT_SCRIPT_SRC` の
  モジュール定数配列として持ち、CSP の**基底値**に組み込む。市場ごとに出し分ける
  支援ウィジェットのオリジン（`withOrigin`）とは層を分ける。
- 却下案: 既存の `withOrigin()` を並べて足す → 計測ホストは市場に関係なく常に要るのに、
  出し分けの仕組みに載せると「JP だけ計測できる」という壊れ方を招きうる。負けた理由は
  出し分けの軸（市場）と、常時必要という性質が一致しないこと。
- 出典: `src/build/headers.js`

### 2026-09-07 `https://*.analytics.google.com` と `https://analytics.google.com` を両方書く
