## 目的
**投稿の型は「1枚目に比較画面の画像を必ず添付」を前提にしているが、画像を作る手順が無い。**
`connectors/buffer.py` には image / media / attachment の記述が1件も無く（T-032 G-06）、
機構からは添付できない。

T-031 §5.7 は、比較画面のスクリーンショットではなく**数字だけのカード画像**を提案している
（商品名が楽天の生データのままでは信用を落とすため。`X_kgi_2weeks.md` 0-4）。

## 変更範囲
- 新規: カード画像の生成手順とテンプレート（置き場は判断してよい範囲）
- 生成された画像の置き場

## 禁止事項
- `.media-agent/` 配下の変更（T-033 / T-034 の担当分である）
- 実際に X へ投稿・返信・いいね・リポストする操作
- タスク台帳 CSV への書き込み
- **画像に使ってはいけないもの**: 葉・植物・カプセル・錠剤・筋肉・ハート・体のシルエット・
  チェックマーク・人物写真（`.claude/rules/pergram-ui-copy.md`）
- 禁止語を画像内に書くこと
- 優劣を述べる表現（「◯◯は割高」等）を画像内に書くこと
- 色・寸法をテンプレートに直書きすること。値の出所は `src/styles/tokens.css`

## 完了条件
1. 型（playbook）と数字を渡すとカード画像が1枚出る手順が存在し、**実際に生成した画像が置かれている**
2. 生成した画像に、**ブランド表記 `pergram`（全て小文字）とタグライン「1gあたり、いくら払ってる?」**が入っている
3. 数値に**単位と基準と取得日**が添えられている
4. 禁止ビジュアルが含まれていないことを、生成物を見て確認した記録がある

## 判断してよい範囲
- 生成手段（HTML→スクリーンショット / SVG / 画像ライブラリ）、テンプレートの設計、画像サイズ
- 1枚に載せる情報量

## テスト方法
実環境確認: 生成した画像を人が見て、禁止ビジュアルと表記規約を満たすか判定する。実施者は org-test。
