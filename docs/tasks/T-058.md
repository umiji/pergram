## 目的

**PO が「リクエストボタンを押されたら記録できるようにしてくれ。UUIDと日付、どのページで
ボタンが押されたかは必要でしょ」と指示した。**

現状、UUID と日付は T-051 で実装済み（`request_signal` テーブル、`worker/request_signal.js`、
移行SQL）。**足りないのは「どのページで押されたか」の1列だけ**である。

押された場所は現在 GA4 の `location`（`request_click` の `products_request_top` /
`products_request_bottom` / LP 側）が持っているが、**GA4 は CSP の設定ミスで全滅した実績があり
（T-047）、自分の手の中に無い**。どのページからの要望が多いかは、次に掲載する成分を決める
材料そのものなので、サーバ側にも残す。

## 決定ログ

### 2026-09-08 「どのページか」は器（data-request-page）に載せ、ボタンには載せない
- 対象: 要望導線 / DOM
- 決定: ページ識別子は段の器（`[data-request-flow]`）に `data-request-page` として1つだけ置く。
  値は `requestPageId(locale, key)` が組む `<locale>:<識別子>`（`ja:lp` / `ja:protein`）
- 却下案: (1) 各ボタンに `data-page` を足す → ボタンは1ページに2つあり、同じ値を2箇所に
  持つと片方だけずれた状態が作れる。器は1ページに1つしかない。
  (2) `location.pathname` から作る → パスは将来変わるうえ、クエリや断片が混ざると
  「どのページか」以上のものがサーバへ渡りうる。**語彙を閉じて渡すほうが安全である**
- 付帯条件: `data-cta` / `aria-controls` の既存の値は変えていない（GA4 の前後比較を切らない）
- 出典: コミット ce47edb / `src/templates/request.js`

### 2026-09-08 page が読めないときは送らない（400 を貰いに行かない）
- 対象: 要望導線 / 匿名シグナル
- 決定: ブラウザ側（`src/assets/request.js`）で `^[a-z]{2}:[a-z0-9-]{1,40}$` を検査し、
  合わなければ `fetch` そのものを行わない。**段は必ず開く**
- 却下案: 形に関わらず送る → 受け口は 400 で捨てるので行は増えず、
  `localStorage` の識別子だけが消費される。**次に正しく送れる回まで潰す**
- 出典: `src/assets/request.js` の `sendRequestSignal()`

### 2026-09-08 T-051 の受け入れテストのうち「2列だけ」を主張する箇所を3列へ書き換えた

- [道具] 本番 D1 の状態を読むコマンド（`npx wrangler d1 execute --remote` の SELECT）が実行許可で拒否され、コードが本番に反映されているかを確かめられない
- [規約] 上流タスク（T-051）の受け入れテストが「列は2つだけ」という形で仕様を固定していたため、PO 判断で仕様が変わったとき、実装タスクの側が他人の受け入れテスト4ファイルを書き換える必要が生じた。「テストを緩めて通さない」の禁止と、上書きされた仕様への追随の区別が、規約からは読み取れない
