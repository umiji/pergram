## 目的

**PO が「リクエストボタンを押されたら記録できるようにしてくれ。UUIDと日付、どのページで
ボタンが押されたかは必要でしょ」と指示した。**

現状、UUID と日付は T-051 で実装済み（`request_signal` テーブル、`worker/request_signal.js`、
移行SQL）。**足りないのは「どのページで押されたか」の1列だけ**である。

押された場所は現在 GA4 の `location`（`request_click` の `products_request_top` /
`products_request_bottom` / LP 側）が持っているが、**GA4 は CSP の設定ミスで全滅した実績があり
（T-047）、自分の手の中に無い**。どのページからの要望が多いかは、次に掲載する成分を決める
材料そのものなので、サーバ側にも残す。

## 禁止事項

- 🔒 **`waitlist` テーブルに列を足さない。** PO が「Waitlist にカラム追加して」と指示したが、
  **PO 判断で `request_signal` 側へ足すことに決まった**（決定ログ参照）。
  `waitlist` は `email` が主キーで、匿名の押下と個人のメールアドレスが同じ表に並ぶ
- 🔒 **IP・User-Agent・リファラ・成分・自由記述を足さない。** 足すのは
  「どのページか」の1列だけである。**個人を識別できるものを持たないことが、この行の存在理由**
- 🔒 **押された場所（上の帯 / 下の帯）は入れない。** PO の指示は「どのページか」であり、
  ページ内の位置ではない。位置は GA4 の `data-cta` が持つ
- `data-cta` / `aria-controls` の**既存の値を変えない**（GA4 の前後比較が切れる）。
  **新しい属性を足すのは可**
- 押下数を画面に出さない（景表法）。リクエスト数を並び順に使わない（N-03）
- **既存の行を壊す移行を書かない。** `ALTER TABLE ... ADD COLUMN` は既存行に NULL が入る。
  `NOT NULL` を付けない
- T-053 / T-057 が整えた見た目を壊さない

## 完了条件

- 1. `worker/schema.sql` の `request_signal` が `id` / `created_at` / `page` の**3列**である
- 2. `worker/migrations/2026-09-08_request_signal_page.sql` が存在し、
     **`ALTER TABLE request_signal ADD COLUMN page TEXT;` だけ**を行う
     （`waitlist` にも `price_alert` にも触れない）
- 3. `POST /api/request-signal` が `{"id":"<uuid v4>","page":"<識別子>"}` を受け取り、
     3列を保存して 204 を返す
- 4. **`page` の形が合わない要求を 400 で捨てる。** 受け付ける形は
     `^[a-z]{2}:[a-z0-9-]{1,40}$`（例 `ja:lp` / `ja:protein` / `en:creatine`）。
     **前後の空白を落として救わない**（既存の `id` の扱いと同じ）
- 5. **キー集合が `{id, page}` ちょうどでない本文を 400 で捨てる**
     （既存の「キー集合が `id` 1つ」の検査を拡張する。余分なキーを黙って無視しない）
- 6. `page` が無い本文も 400 で捨てる（**任意項目にしない**。無いと目的を果たさないため）
- 7. 実ブラウザで、製品一覧（`/ja/protein/`）のボタン押下時の送信本文が
     `{"id":"...","page":"ja:protein"}` であり、LP（`/ja/`）では `"page":"ja:lp"` である
- 8. **1ブラウザ1件の重複抑止が壊れていない**（2回目の押下で `/api/request-signal` が飛ばない）
- 9. `worker/request_signal.js` と `worker/schema.sql` と
     `worker/migrations/2026-09-07_request_signal.sql` の 🔒 コメント
     （「列は UUID と日時の2つだけ」）が、**この決定を反映した文へ書き換わっている**。
     **消すのではなく、上書きされたことが読める形にする**
- 10. `.claude/rules/pergram-compliance.md` の「サーバが保持してよい列」の記述が実態と一致する
- 11. `npm test` 全件通過、`npm run build` 成功
- 12. 上記 3〜6 を検査するテストがあり、**実装を戻すと落ちる**
