## 0. このページの唯一の仕事

> **「この成分を、いちばん安く摂れるのはどれか」に即答する。**

これ以外は全部おまけ。トップに置くのはブランドメッセージでもヒーロー画像でもなく、**ランキングそのもの**。

副次的な仕事:
1. 「品質を上げると、いくら高くなるか」を見せる（プレミアム幅）
2. 「安すぎる製品は何が違うのか」を事実で示す（純度・塩形態・認証）

対象ユーザー: 筋トレ・美容目的でサプリを継続購入する日本の消費者。**数値を見る習慣がある層**。価格.com や PCPartPicker を使いこなす人が想定読者。

## 1. デザインベンチマーク

### 1.1 調査対象と学び

| サービス | 領域 | 取り入れること | 避けること |
|---|---|---|---|
| **PCPartPicker** | PCパーツ比較・構成組み | 単一目的（組む）に全UIを従属させる設計。ベンダーフィルタ。価格履歴。構成リスト（＝スタック機能の原型）。<cite index="39-1">100万人以上が使い、38カ国のローカライズ通貨に対応</cite> | 初心者にはスペック用語の壁が高い。専門用語をそのまま出さない |
| **Camelcamelcamel / Keepa** | Amazon 価格追跡 | <cite index="38-1">価格履歴グラフと、目標価格到達時のアラート</cite>。「今が買い時か」を一目で示す形式 | UI が古く情報密度が過剰。グラフが主役になりすぎて判断を助けない |
| **価格.com** | 日本の価格比較 | 日本ユーザーの期待値の基準。左サイドの絞り込みファセット、最安値の即時提示 | 広告と実データの境界が曖昧。中立性の見え方で差別化する |
| **Examine.com / Labdoor** | サプリ情報 | 出典の常時明示。エビデンスと意見を分けて提示する姿勢 | 英語圏向けで情報量が多く、購買判断まで遠い |
| **Cronometer** | 栄養素トラッキング | 栄養素の対RDA/UL表示のバー形式 | 記録が前提。本ツールは記録不要で完結させる |
| **Open Food Facts** | 食品オープンデータ | データの出典と更新日を製品ページに常時表示 | 情報が生すぎて意思決定を助けない |

### 1.2 最重要の設計判断

<cite index="42-1">Baymard の 335 サイト調査では、上位60 EC のうち 38% が比較ツールを実装しているが、大規模ユーザビリティテストの結果、ユーザーは比較対象を選ぶ段階でも、比較ページでスペックを見る段階でも深刻な困難を抱えることが判明している。</cite>

**結論: 並列比較マトリクスをデフォルトにしない。**

- デフォルトは **単一指標でソートされた1本のランキングリスト**
- 並列比較（side-by-side）は**最大3件までの補助機能**として、明示的に選んだときだけ出す
- 1画面に主指標は1つ。副指標は行内の小さい文字に落とす

## 2. デザイン方針

### 2.1 素材はどこから来ているか

このプロダクトの世界の材料は **成分表示パネル**。米国の Supplement Facts panel（太罫と細罫で階層を作る、左に名前・右に数値の表組み）と、日本の栄養成分表示。ラベルという印刷物の文法をそのまま UI の文法にする。

これは装飾ではなく意味を持つ選択で、**「ここはマーケティングの場ではなく、ラベルの数値を読む場だ」**というプロダクトの立場をデザインで宣言している。

### 2.2 やらないこと

- グラデーション、シャドウの多用、丸みの強いカード
- 「あなたにおすすめ」的なパーソナライズ演出（§N-03 に反する）
- 星やスコアで製品を序列化する装飾（順位はコストのみが決める）
- 効能を連想させるビジュアル（筋肉、肌、輝き、before/after）

## 2.5 ブランド: pergram

### 表記規則 🔒
| 項目 | 規則 |
|---|---|
| 正式表記 | **`pergram`**（全て小文字） |
| 大文字始まり | **使わない**。`Pergram` `PerGram` は不可 |
| 読み | パーグラム |
| 日本語圏での表記 | 英字 `pergram` を正とする。カタカナ「パーグラム」は読み方の補助としてのみ併記 |
| 由来 | per gram — 1gあたり、というこのプロダクトの唯一の指標 |

小文字固定にする理由は、単位表記（`mg` `g` `mcg`）が小文字だから。**名前を単位と同じ字面の世界に置く。**

### タグライン
- JP: **1gあたり、いくら払ってる?**
- EN: **What are you paying per gram?**

初回接触時（LP・OGP・広告）は**必ずタグラインとセットで出す**。`-gram` 接尾辞が Instagram / Telegram の連想を呼び、単体では SNS アプリに見えるため、タグラインで単位の話だと即座に確定させる。

### 単位のスコープに関する注記
`gram` はクレアチン・プロテイン（P1/P2）には字義通り合致するが、鉄・亜鉛・ビタミン類（P5）は mg / mcg スケールになる。
**ブランド名は「単位あたりで考える」という態度の表明であり、単位の literal な制約ではない。** UI 上の指標表記は成分ごとに `¥/g` `¥/mg` を出し分ける（本書 §5.1）。

### ワードマーク
```
    │  ╷  │  ╷  │      ← ルーラーティック（6px / 1px の交互）
    pergram
```
- 書体: **Archivo 800**、tracking `-0.03em`
- ワードマークの上または下に**目盛り（ルーラーティック）**を敷く。長短の交互は §3.3 の罫線階層（6px / 1px）と同じ規則から導く
- シグネチャ要素「コストの物差し」（§4）と同じモチーフ。**ロゴとプロダクトの中核機能が同じ図形**になる
- 色は `--ink` 単色。ティックのみ `--signal` を許容（1箇所まで）

### ファビコン / アプリアイコン
高さの異なる縦線3本（ルーラーの目盛り）。文字を入れない。`--paper` 地に `--ink`。

### 使ってはいけないビジュアル 🔒
葉・植物・カプセル・錠剤・筋肉・ハート・体のシルエット・チェックマーク。
いずれも効能または推薦を連想させ、[product/requirements.md](../product/requirements.md) §1.2 の立場と矛盾する。

## 3. デザイントークン

### 3.1 カラー

| トークン | 値 | 用途 |
|---|---|---|
| `--ink` | `#14161A` | 本文・罫線。純黒にしないのはラベル印刷の質感 |
| `--paper` | `#FBFAF7` | 背景。ラベル紙の白 |
| `--muted` | `#6B6F76` | 出典・更新日・補足 |
| `--line` | `#DCD9D2` | 細罫 |
| `--signal` | `#1B44C8` | **コスト指標と現在のソートキーにのみ使用** |
| `--warn` | `#B3261E` | UL 超過のみ |
| `--verified` | `#1F6F4A` | 第三者認証バッジのみ |

**色数の規律**: `--signal` は1画面に1種類の意味でしか使わない。「ここが今あなたが見ている指標だ」以外に使わない。色を増やしたくなったら、それは情報設計が間違っている合図。

### 3.2 タイポグラフィ

すべて OFL / 無料（[product/requirements.md](../product/requirements.md) §10.1 の無料構成に整合）。

| ロール | フォント | 用途 |
|---|---|---|
| Display | **Archivo** 700/800, tracking -0.02em | 成分名、ページ見出し |
| Body | **IBM Plex Sans JP** 400/500 | 本文、ラベル、UI |
| Data | **IBM Plex Mono** 500 | **すべての数値** |

**絶対規則 🔒**: 数値は `font-variant-numeric: tabular-nums` を必ず適用する。桁が揃わない比較表は比較表として機能しない。

型スケール（rem）: `0.75 / 0.875 / 1 / 1.25 / 1.75 / 2.5 / 3.5`

### 3.3 罫線の階層（Supplement Facts 由来）

| 太さ | 用途 |
|---|---|
| 6px solid `--ink` | セクションの外枠上端 |
| 3px solid `--ink` | 主要な区切り（ランキングの見出し下） |
| 1px solid `--ink` | 行の区切り |
| 1px solid `--line` | 副次的な区切り |

border-radius は **0**。ただしボタンとバッジのみ 2px（触れる要素だけ角を落とす、という規則）。

### 3.4 スペーシング

4px ベース。`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`

## 4. シグネチャ要素: コストの物差し (Cost Ruler)

**このプロダクトを記憶させる唯一の要素。**

```
安い                                                          高い
├──●─●──●───●●──────●────●───────●──────────●─────────────────┤
   ¥38                                                    ¥210
   ▲ 最安（条件なし）
        ▲ 最安（第三者認証あり） +¥19/日
```

- 横一本の対数スケール軸に、対象成分の全製品を1ドットずつプロットする
- フィルタを適用すると、条件を満たさないドットが**その場でフェードアウト**し、最安マーカーが右へ移動する
- **その移動距離が「プレミアム幅」そのもの**（[product/requirements.md](../product/requirements.md) §4.5）

なぜこれが効くか: 「オーガニックは高いけど良さそう」という迷いに対して、**いくら高いのかを一瞬で答える**。しかも判断はユーザーに委ねたままで、こちらは何も推薦していない。§1.2 の位置づけと完全に整合する。

実装上の注意:
- 対数スケールであることを軸に明記する（線形だと外れ値で潰れる）
- ドットのホバー/タップで製品名とコストを表示、クリックで該当行へスクロール
- `prefers-reduced-motion` 時はフェードせず即座に切り替える
- モバイルでは高さを詰めて表示し、ドットのタップ領域を 44px 確保する

## 5. 画面構成

### 5.1 成分ランキングページ（主画面）

```
┌──────────────────────────────────────────────────────────┐
│ ▌クレアチン                                    更新 8/3  │  ← Display, 6px 上罫
│ 1gあたりの価格で並べています                              │
├──────────────────────────────────────────────────────────┤
│ [ コストの物差し ]                                        │  ← §4
├──────────────────────────────────────────────────────────┤
│ 目標量  [ 5 ] g/日        表示 [1gあたり▾]               │
├───────────────┬──────────────────────────────────────────┤
│ 絞り込み       │  1  ブランドA モノハイドレート           │
│                │     一水和物 / 国産 / 認証なし            │
│ □ 第三者認証   │                        ¥38 /g   ¥190/日 │  ← --signal
│ □ 有機JAS      │     ★4.3 (1,204件・楽天)   [楽天で見る]  │
│ □ 人工甘味料なし├──────────────────────────────────────────┤
│ □ 国産         │  2  ブランドB クレアピュア               │
│                │     一水和物 / ドイツ / Informed Sport✓  │
│ 形態           │                        ¥57 /g   ¥285/日 │
│ ○ 一水和物     │     ★4.6 (832件・楽天)     [楽天で見る]  │
│ ○ HCl          ├──────────────────────────────────────────┤
│                │  3  ...                                  │
└───────────────┴──────────────────────────────────────────┘
│ 数値はメーカー公表のラベル表示に基づく。出典: …          │
│ 本サイトはアフィリエイト広告を利用しています。順位は      │
│ 表示中の指標のみで決定され、報酬額は影響しません。        │
└──────────────────────────────────────────────────────────┘
```

**主指標に関する絶対規則** 🔒
**per serving（1食あたり / 1粒あたり）をソートキーにしない。** serving はメーカーが任意に定義した単位であり、製品を横断して比較できない（[product/requirements.md](../product/requirements.md) §4.2）。
`¥52 /食` は補助表示として出してよいが、並び順を決めるのは常に有効成分1単位あたりの価格（`¥38 /g`）。

**行の設計原則**
- 主指標（`¥38 /g`）が行内で最大かつ `--signal`。他は全部それより小さく `--ink` か `--muted`
- 2行目の属性チップは**事実のみ**。「吸収が良い」等の評価語は入れない
- 順位番号は表示する（`rank_position` を GA4 に送るため、また「何位まで見られるか」を測るため）

### 5.2 製品詳細ページ

Supplement Facts パネルをそのまま再現した成分表を中心に置く。

- ラベル記載値と**元素量換算値を併記**する（例: `酸化マグネシウム 500mg（マグネシウムとして 約300mg）`）
- RDA/UL がある成分のみバーを表示。ない成分は**空欄のまま**にし、「公的な推奨量・上限量は定められていません」と一度だけ注記する
- データの `confidence` を表示: `high` = 通常、`medium/low` = 該当行に細いハッチングと「要確認」ラベル。**推定値で埋めない**
- 出典 URL と `verified_at` を常時表示

### 5.3 スタック / バスケット画面

PCPartPicker の構成リストが原型。製品を追加していくと成分が合算され、下部に合計コストと、RDA/UL がある成分のみ到達度バーが出る。

- UL 超過は `--warn` + アイコン + テキストの**3重表現**（色だけに依存しない）
- 超過時の文言は事実のみ: 「亜鉛の合計が耐容上限量（40mg/日）を超えています。出典: 日本人の食事摂取基準(2025年版)」。指示や助言は書かない

### 5.4 並列比較（補助機能）

- 最大3件。それ以上は選べない（§1.2 の Baymard 知見）
- 差分のある行だけを強調するトグルを用意する（全項目を平等に並べると読めない）

## 6. 空・エラー・低信頼の状態

| 状態 | 表示 |
|---|---|
| フィルタ結果0件 | 「条件に合う製品はありません。絞り込みを1つ外すと N 件になります」＋ワンタップで外せるボタン |
| データ未整備の成分 | 「この成分はまだ登録されていません」＋リクエストフォームへの導線 |
| 価格取得失敗 | 前回価格と取得日時を表示し、「最終取得: 8月1日」と明示。空欄にしない |
| `confidence: low` | 行にハッチング＋「要確認」。数値は出すが根拠が弱いことを明示 |

エラー文は謝らない。何が起きて、どうすれば直るかだけを書く。

## 7. コピーの規則

- 能動態。ボタンは操作の結果をそのまま名乗る（「価格を通知する」、「登録」ではない）
- 同じ操作は最初から最後まで同じ語を使う（「通知する」→ トーストも「通知を設定しました」）
- 効能語・評価語の禁止リスト: 効く / 改善 / 高品質 / おすすめ / 人気No.1 / 安心 / 話題の
- 使う語: 含有量 / 元素量 / 単価 / 認証 / 出典 / 更新日
- 数値には必ず単位と基準を添える（「¥38」ではなく「¥38 / クレアチン1g」）

## 8. レスポンシブ

| ブレークポイント | 挙動 |
|---|---|
| ~ 640px | 縦1カラム。フィルタはボトムシート。コストの物差しは高さを圧縮。行は2段組み（名前/属性 → 数値） |
| 640 ~ 1024px | 2カラム。フィルタは折りたたみ |
| 1024px ~ | 左サイドバー固定 + 右ランキング |

**モバイルを主とする。** 想定ユーザーは店頭やジムでスマホから見る。数値の可読性を最優先し、フォントサイズを下げてまで情報を詰めない。

## 9. アクセシビリティ（実装の下限）

- UL 超過・認証の有無を**色だけで表現しない**（アイコン＋テキストを併記）
- キーボードフォーカスを可視化する。`:focus-visible` に 2px `--signal` のアウトライン
- `prefers-reduced-motion: reduce` を尊重（物差しのアニメーションを無効化）
- コントラスト比 4.5:1 以上。`--muted` on `--paper` は要検証
- ランキングは `<ol>` でマークアップする。順位は意味を持つ
- 成分表は `<table>` + `scope` 属性。div で組まない

## 10. 多言語 UI への配慮（[product/requirements.md](../product/requirements.md) §9 と対応）

| 項目 | 対応 |
|---|---|
| テキスト長 | 英語は日本語より 1.3〜1.6 倍長い。ボタン・チップは固定幅にしない |
| 数値書式 | `Intl.NumberFormat` でロケール書式化。文字列連結禁止 🔒 |
| 通貨 | 単位記号を文言に埋め込まない。`{amount}` と通貨を分離 |
| 免責文 | 地域ごとに別テキスト。翻訳ではなく差し替え 🔒 |
| フォント | IBM Plex Sans JP は日英を同一ファミリで賄えるため切替不要 |
| ブランド名 | `pergram` は翻訳しない。全ロケールで同一表記 🔒 |

### 10.1 `locale` と `market` は別の軸 🔒

表示言語と、適用される市場は独立している。UI 実装で最も混同しやすい箇所。

| 軸 | 決めるもの |
|---|---|
| `locale` (ja / en) | 表示言語のみ |
| `market` (JP / US) | 表示する merchant、参照値、免責文、通貨 |

**「英語 UI だから楽天ボタンを隠す」は誤り。** 日本在住の外国人は英語 UI で楽天を使う。
merchant の出し分けを決めるのは `market` であって `locale` ではない。

### 10.2 出し分けは条件分岐ではなくデータで 🔒

コンポーネントに `if (locale === 'en')` を書き始めると分岐が増殖し、個人では保守できなくなる。
market 設定 JSON（[product/requirements.md](../product/requirements.md) §9.2）を**配列として回して描画する**。UI 側の分岐はゼロにする。

```
market.merchants.map(m => <MerchantButton merchant={m} />)
```

### 10.3 変えてよい部分・いけない部分

| 変化 | 判断 |
|---|---|
| 文言の差し替え | ◎ 翻訳キー |
| 数値・通貨・日付書式 | ◎ `Intl` API |
| merchant ボタンの出し分け | ◎ ただしデータ駆動で |
| テキスト長による折り返し | ○ 幅を固定しなければ吸収できる |
| **ロケール別のカラー・書体** | ✗ **やらない** |
| **ロケール別のページ構成・情報設計** | ✗ **やらない** |

**デザインシステムは1つに保つ。** トークンや情報設計を市場ごとに分けると、個人運営では確実に破綻する。

### 10.4 日本語版と英語版は「翻訳」ではない 🔒
1ドメイン + `/ja/` `/en/` のサブパス構成を採るが、**両者は対訳関係にない**。

| | `/ja/` | `/en/` |
|---|---|---|
| 掲載製品 | 日本から購入可能なもの | 米国から購入可能なもの |
| 参照値 | 日本人の食事摂取基準(2025年版) | 米国 DRI |
| 免責文 | 薬機法 + ステマ規制 | FTC / DSHEA |

したがって:
- **成分ランキングページに hreflang を相互指定しない**（掲載製品が異なり等価ページではないため）
- hreflang を付けるのは「データの作り方」「このサイトについて」など**本当に等価なページのみ**
- 言語切替 UI は「翻訳版へ移動」ではなく「**別の市場のデータを見る**」という意味であることを文言で示す（例: 「米国市場のデータを見る」）
- 言語切替と市場切替は**別のコントロール**として置く

## 11. 実装優先度

| フェーズ | デザイン範囲 |
|---|---|
| P1 | トークン定義、ランキングページ、行コンポーネント、免責・広告表示 |
| P3 | コストの物差し、ファセットフィルタ、認証バッジ |
| P5 | 製品詳細の成分パネル、UL 超過表示 |
| P6 | スタック画面、並列比較 |
| P7 | 価格履歴グラフ、アラート設定 |

**P1 で「コストの物差し」まで作らないこと。** まずランキング1本が正しく動くことを確認してから、シグネチャ要素に手をつける。
