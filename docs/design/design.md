## 1. プロダクト

**pergram（パーグラム）** — サプリメントを「有効成分1単位あたりの価格」で横並びに比較する日本市場向けサイト。

サプリは剤形・含有量・内容量・価格・塩形態がバラバラで、「同じ成分を同じ量だけ摂るのにいくらかかるか」を比べる手段が実質存在しない。日本には公的なサプリラベルのデータベースもない。pergram はラベル表示の含有量を換算したうえで、単価で並べる。

### 立ち位置 🔒

**効能を提案するツールではなく、事実を計算して並べるツール。**

- 症状や悩みから商品を推薦しない
- 独自の「総合スコア」「おすすめ度」を作らない
- 出すのは、含有量・価格・公的基準値・認証という**検証可能な数値と事実のみ**

これは法務戦略そのものなので崩せない。

### 今回作るもの

**検証用ランディングページ（1枚）。** 公開前にメール登録を集め、どの成分に需要があるかを測る。

本体サービス（成分ランキング・製品詳細）は後続。ただし**同じデザインシステムで作る**ため、LP の設計はそのまま本体に引き継げる形にしてほしい。

## 2. 対象ユーザー

**数値を見る習慣がある層。** 価格.com や PCPartPicker を使いこなす人。

- 筋トレ目的でプロテインを**継続購入**している（＝年間コストが効く）
- セール時にまとめ買いする。個人輸入・iHerb を使う層が中核
- 「おすすめ10選」記事を信用していない
- **自分で計算したいが、面倒でやっていない**

痛みは「わからない」ではなく「**面倒くさい**」。
だから LP の仕事は教育ではなく、**「その計算、全製品ぶん終わってます」と見せること**。

## 3. このページが達成すべきこと

優先順。①が達成できていれば②③が弱くても合格、逆はない。

| # | 目的 | 判定 |
|---|---|---|
| ① | **「自分がいくら払っているか」に驚かせる** | スクロールせずに驚きが起きるか |
| ② | この計算が**全製品ぶん・毎日・中立に**行われていると伝える | 3つが数字と文言で示されているか |
| ③ | メールアドレスと「見たい成分」を受け取る | フォームまで到達するか |

### 何が「凄さ」なのか 🔒

**「1gあたりで計算する」こと自体は凄くない。** 英語圏には同じことをするサービスが既に複数ある（CompareProteinPrices は700製品超、ProteinMath は毎日更新、SuppsRadar は30成分を g/mg/IU に正規化）。日本語圏にも同種の記事がある。

**凄いのは次の3点だけ。** デザインはこの3つを可視化することに奉仕してほしい。

| 軸 | 競合の欠陥 | 可視化の材料 |
|---|---|---|
| **網羅性** | 「おすすめ10選」形式で、全体の中の最安が分からない | 掲載件数の実数。分布の形 |
| **鮮度** | 執筆時点の価格が残り続ける。プロテインは頻繁にセールする | 更新日時。価格の変動 |
| **中立性** | 上位記事はすべてアフィリエイト記事 | 順位の決まり方の明示。報酬と無関係であること |

## 4. 画面に必ず載るもの

### 4.1 製品1件について

| 要素 | 必須 | 備考 |
|---|---|---|
| **製品パッケージ画像** | ◎ | **v0.4 まで欠けていた。比較サービスとして必須** |
| ブランド名・製品名 | ◎ | 実名を出す。伏せると信憑性が消える |
| **主指標（有効成分1単位あたりの価格）** | ◎ | 行内で最も強い要素にする |
| 副指標（含有率・1食あたり価格・内容量など） | ◎ | 主指標より弱く |
| 順位 | ◎ | 順位は意味を持つ |
| 価格の取得日 | ◎ | 鮮度の証拠 |
| 出典（商品ページへのリンク） | ◎ | |
| 販売元 | ○ | |
| データの確からしさ | ○ | 低信頼の行を明示する（§6） |

#### 製品画像の扱い 🔒

- **効能を連想させる画像は禁止だが、パッケージ写真は事実の提示なので可。** 価格.com と同じ扱い
- **画像が存在しない製品が必ずある。** 欠損時の代替表現を設計に含めること。ブランド名の頭文字や無地のプレースホルダなど、**欠損が「壊れている」ように見えない**こと
- 画像の縦横比・背景色・切り抜きの有無はメーカーごとにバラバラ。**揃わない前提**でレイアウトを組むこと
- 画像が主役になって数値が負けないこと。**主役は数値**
- 画像の利用条件は取得元（楽天等）の規約に従う。**要確認事項として残っている**

### 4.2 ページ全体について

| 要素 | 必須 | 目的 |
|---|---|---|
| ロゴ + タグライン | ◎ | §5 |
| 掲載件数の実数 | ◎ | 網羅性の証拠。「たくさん」ではなく「68製品」 |
| 全体の更新日 | ◎ | 鮮度の証拠 |
| **単価の差がどれくらい大きいかの表現** | ◎ | 驚きの源。年額換算など |
| 並べ替え・絞り込みができると分かる表現 | ◎ | ツールであることを示す |
| メール登録フォーム | ◎ | §4.3 |
| 「このサイトがやらないこと」の宣言 | ◎ | 中立性。競合が誰も書いていない差別化 |
| 免責文 | ◎ 🔒 | 常時表示。折りたたまない |
| 数値の出典 | ◎ 🔒 | ラベル表示値であることを明記 |
| OGP 画像 | ◎ | SNS でそのまま読める密度 |

### 4.3 フォーム 🔒

**入力は3つまで。それ以上は登録率が落ちる。**

| 項目 | 形式 |
|---|---|
| メールアドレス | 必須 |
| 見たい成分 | 複数選択（プロテイン / クレアチン / EAA・BCAA / HMB / 鉄・亜鉛 / ビタミン / その他） |
| 普段の購入先 | 単一選択（楽天 / Amazon / iHerb / マイプロテイン / 店舗） |

- **年齢・性別・体調は取らない** 🔒 — 要配慮個人情報であり、取る必要もない
- 「見たい成分」は**メールアドレスの直下**に置く。ここが検証の主目的
- 送信後は同一ページ内で完了状態に切り替える。別ページに飛ばさない
- 完了文言に感嘆符を使わない

## 5. ブランド 🔒

| 項目 | 規則 |
|---|---|
| 表記 | **`pergram`** — 全て小文字。`Pergram` `PerGram` は不可 |
| 読み | パーグラム |
| 由来 | per gram — 1gあたり、というこのプロダクトの唯一の指標 |
| タグライン | **1gあたり、いくら払ってる?**（EN: What are you paying per gram?） |
| 初回接触 | **ロゴとタグラインを必ずセットで出す** |

タグラインを必ず添えるのは、`-gram` が Instagram / Telegram の連想を呼び、単体だと SNS アプリに見えるため。

**ロゴは未確定。** 現行案は「Archivo 800 のワードマーク + ルーラーティック（長短交互の目盛り）」だが、**提案を歓迎する**。要件は次の2つだけ。

- 小文字で組む（単位表記 `mg` `g` `mcg` が小文字だから。名前を単位と同じ字面の世界に置く）
- 禁止ビジュアル（§7）を使わない

## 6. 状態の設計

比較サービスは**データが欠けている状態が常態**。ここを設計しないと本番で崩れる。

| 状態 | 要件 |
|---|---|
| 製品画像がない | 代替表現を出す。空白にしない |
| 絞り込み結果が0件 | 「1つ外すと N 件になります」と、ワンタップで外せる導線 |
| 価格の取得に失敗 | 前回価格と取得日を出す。**空欄にしない** |
| データの確からしさが低い | 数値は出すが、根拠が弱いことを明示する |
| 公的な基準値が存在しない成分 | 「定められていません」と明示する。**推定値で埋めない** 🔒 |

**エラー文は謝らない。** 何が起きて、どうすれば直るかだけを書く。

## 7. 絶対制約 🔒

薬機法・景表法に直結する。**機能要件より優先し、迷ったらより保守的な方を選ぶ。**

### 使ってはいけない語
```
効く / 効果 / 改善 / 高品質 / おすすめ / 人気No.1 / 安心 / 話題の / 選ばれる / 実感
```

### 使ってよい語
```
単価 / 1gあたり / 含有量 / 含有率 / 元素量 / ラベル表示 / 比較 / 一覧 / 出典 / 更新日 / 安い
```

### 禁止事項

| # | 禁止 | 理由 |
|---|---|---|
| 1 | 成分の働き・体への作用に言及する | 薬機法 |
| 2 | 独自の総合スコア・おすすめ度・加重平均ランキングを作る | 事実提示ではなく推薦になる |
| 3 | 「だからこちらを選ぶべき」と書く | 判断はユーザーに委ねる |
| 4 | 症状・悩みの入力を受け付ける | 「症状→成分→商品」は効能の暗示 |
| 5 | **筋肉・肌・体のシルエット・before/after・人物写真** | 効能訴求と解釈されうる |
| 6 | **葉・植物・カプセル・錠剤・ハート・チェックマーク** | 効能または推薦を連想させる |
| 7 | LP にアフィリエイトリンクを置く | 広告審査でアフィリエイトサイト判定を受ける |
| 8 | ヒーローにダミーデータを置く | ここで嘘をつくと全部が崩れる |

**⑤⑥は「製品パッケージ写真」を含まない。** パッケージは事実の提示なので使ってよい（§4.1）。

### 数値の書き方

- 単位と基準を必ず添える。「¥38」ではなく「**¥38 / タンパク質1g**」
- 前提を必ず併記する。「1年で¥100,740の差」なら「60g/日 × 365日で計算」
- 「実測」と書かない。**ラベル表示値**であることを明記する

## 8. 技術的な下限

| 項目 | 要件 |
|---|---|
| **数値の字形** 🔒 | 等幅数字（`tabular-nums`）。桁が揃わない比較表は比較表として機能しない |
| **モバイル主** | 想定流入の大半がスマートフォン。390×844 で成立すること |
| タップ領域 | 44px 以上 |
| 本文サイズ | 16px 未満にしない（iOS のズーム発動を防ぐ） |
| 書体のライセンス | 商用利用可・無料（OFL 等）。**self-host できること**。日本語と英数字の両方が必要 |
| 書体の重み | 読み込むウェイト数を絞る。日本語フォントは重い |
| 色に依存しない | 状態・方向・警告を**色だけで表さない**。記号やテキストを併記する |
| コントラスト | 4.5:1 以上 |
| 動きの抑制 | `prefers-reduced-motion: reduce` を尊重する |
| マークアップ | 順位付きリストは `<ol>`、成分表は `<table>`。`div` で組まない |
| LCP | 2.0 秒以内。広告費を払って流入させるため離脱が直接コストになる |
| JS | フレームワーク不要。静的 HTML + 最小限のスクリプト |

**書体について**: 現行の指定は Archivo / IBM Plex Sans JP / IBM Plex Mono だが、**self-host していないため実装ではシステムフォントにフォールバックしていた**。つまり現物の見た目は指定と無関係。**書体選定は Claude Design に委ねる。** 上記の要件（無料・日本語対応・等幅数字・self-host 可）を満たせば何でもよい。

## 9. 配色のたたき台

**変更可。** 要件は「色数を絞ること」と「色だけで意味を担わせないこと」だけ。

| 用途 | 現行値 | 意図 |
|---|---|---|
| 本文・罫線 | `#14161A` | 純黒にしないのはラベル印刷の質感 |
| 背景 | `#FBFAF7` | ラベル紙の白 |
| 補足・出典 | `#6B6F76` | |
| 細罫 | `#DCD9D2` | |
| **強調** | `#1B44C8` | **「今見ている指標」の意味でのみ使う** |
| 認証バッジ | `#1F6F4A` | |
| 警告 | `#B3261E` | 上限量の超過のみ |

**強調色を安売りしないこと。** 全製品の価格を強調色にすると、その色は何も意味しなくなる。色を増やしたくなったら情報設計が間違っている合図。

### 世界観のヒント（拘束しない）

材料は**成分表示パネル**（米国 Supplement Facts / 日本の栄養成分表示）。太罫と細罫で階層を作り、左に名前・右に数値を置く表組みの文法。

これは装飾ではなく立場の宣言で、**「ここはマーケティングの場ではなく、ラベルの数値を読む場だ」**と言っている。この意図が伝わるなら、別のアプローチでもよい。

## 10. 参考にした事例

| サービス | 学ぶ点 |
|---|---|
| **Wise**（送金手数料） | ヒーローに実額を直接置く。翻訳の要る文言がなく**計算が語る**。名指しの比較で価格不安をその場の操作に変える |
| **Google Flights**（価格グラフ） | 予測をせず、実在する価格を並べて**分布の形**を見せる。数日ずらすと大きく変わることが「発見」として起きる |
| **価格.com** | 日本ユーザーの期待値の基準。**製品画像 + 絞り込みファセット + 最安値の即時提示** |
| **PCPartPicker** | 単一目的（組む）に全 UI を従属させる |
| **Camelcamelcamel / Keepa** | 価格履歴と「今が買い時か」の即答 |
| **SupplementMath / SuppsRadar**（競合） | 「30回分 vs 2lb」の表記差を剥がす説明の明快さ |

### 採らないもの

- **並列比較マトリクスをデフォルトにしない。** 大規模ユーザビリティテストで、ユーザーは比較対象を選ぶ段階でもスペックを読む段階でも困難を抱えることが分かっている。デフォルトは**単一指標で並んだ1本のリスト**
- 明るい配色・イラスト・グラデーションは、ラベルの質感と衝突する

## 11. 使えるデータ

設計時に「この値は出せるか」を確認しなくて済むよう、**実際に存在するフィールド**を挙げる。

### 製品ごと
```
ブランド / 製品名 / 剤形 / フレーバー / 内容量 / 1食のグラム数 / 1容器あたりの回数
有効成分量（1食あたり・換算後） / 販売元 / 価格 / 在庫 / 商品URL / 取得日
製品画像URL（※取得は実装可能。ライセンス要確認）
データの確からしさ（high / medium / low）
```

### 導出できる値
```
有効成分1単位あたりの価格（主指標） / 1食あたり価格 / 目標摂取量あたりの日額
100gあたり含有量 / 含有率 / 内容量 / 全製品の単価分布 / 絞り込み前後の最安差
```

### まだ無い値
```
第三者認証・原産国・添加物などの品質情報（後続フェーズ）
公的な推奨量・上限量（一次資料からの転記が未了）
レビュー評価（取得は可能だが表示は未定）
```

**現時点で実データは未収集。** 掲載件数・金額はすべて仮値であり、デザイン確定後に差し替える。**リアルなダミーで組んでよいが、実装時は実データに置き換わる**前提で。

## 14. 判断に迷ったら

1. **法規制の制約（§7）が最優先。** 機能要件より上
2. **主役は数値。** 画像・装飾がそれを超えない
3. **事実だけを書き、優劣を述べない。** 判断はユーザーに渡す
4. **色を増やしたくなったら情報設計を疑う**
5. それ以外は**提案してほしい。** 本書に書いていないことは決めていないという意味
