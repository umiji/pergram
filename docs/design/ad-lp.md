## 0. このページの唯一の仕事

> **「プロテイン タンパク質1gあたり 単価」で探している人に、答えを一部見せて、残りをメールで受け取る約束をしてもらう。**

本体サービス（[service.md](./service.md)）と役割が違う点:

| | 本体サービス | このLP |
|---|---|---|
| 仕事 | 答えを出し切る | **答えの一部を出して、続きを予約させる** |
| 滞在 | 数分 | 30秒 |
| 出口 | アフィリエイトリンク | **メール登録のみ**（アフィリエイトリンクは置かない）🔒 |
| 情報量 | 高密度 | 1画面1メッセージ |

**アフィリエイトリンクを置かない理由**: 検証段階でアフィリエイトサイトと判定されると Google 広告の審査で不利になるため（[research/validation-plan.md](../research/validation-plan.md) §4）。

## 1. 絶対制約 🔒

[service.md](./service.md) §7 の禁止語リストをそのまま適用する。**広告審査に直結する。**

**使ってはいけない語**: 効く / 効果 / 改善 / 高品質 / おすすめ / 人気No.1 / 安心 / 話題の / 選ばれる / 実感
**使ってよい語**: 単価 / 1gあたり / 含有量 / ラベル表示 / 比較 / 一覧 / 出典 / 更新日

さらに:
- 成分の働き・体への作用に**一切言及しない**
- 筋肉・肌・before/after を連想させるビジュアルを使わない
- 人物写真を使わない（体型や肌が写ると効能訴求と解釈されうる）
- 免責文をフッターに常時表示（[product/requirements.md](../product/requirements.md) §3.2）

## 2. デザイントークン

[service.md](./service.md) §3 を**そのまま継承する**。LP と本体で見た目が変わると、登録者が本体を見たときに別サービスに見える。

| トークン | 値 | 用途 |
|---|---|---|
| `--ink` | `#14161A` | 本文・罫線 |
| `--paper` | `#FBFAF7` | 背景 |
| `--muted` | `#6B6F76` | 出典・補足 |
| `--line` | `#DCD9D2` | 細罫 |
| `--signal` | `#1B44C8` | **コスト指標と CTA にのみ使用** |
| `--warn` | `#B3261E` | LP では未使用 |
| `--verified` | `#1F6F4A` | 認証バッジのみ |

**ブランド**（[service.md](./service.md) §2.5 を継承）
| 項目 | 規則 |
|---|---|
| 表記 | `pergram` — **全て小文字**。`Pergram` は不可 🔒 |
| 読み | パーグラム |
| タグライン | 「1gあたり、いくら払ってる?」 |
| ロゴ | Archivo 800 のワードマーク + ルーラーティック |
| 禁止ビジュアル | 葉・カプセル・錠剤・筋肉・ハート・人物写真 🔒 |

**LP では必ずロゴとタグラインをセットで出す。** `-gram` 接尾辞が Instagram / Telegram の連想を呼び、単体だと SNS アプリに見えるため、初回接触では単位の話だと即座に確定させる必要がある。

**タイポグラフィ**（すべて OFL / 無料）
| ロール | フォント |
|---|---|
| Display | **Archivo** 800, tracking -0.02em |
| Body | **IBM Plex Sans JP** 400/500 |
| Data | **IBM Plex Mono** 500 |

**絶対規則**: 数値には `font-variant-numeric: tabular-nums` を必ず適用する。

**罫線階層**（Supplement Facts パネル由来）: 6px / 3px / 1px `--ink`、1px `--line`。border-radius は 0（ボタンとチップのみ 2px）。

## 3. ページ構成

**縦1カラム。全体で5セクション。それ以上増やさない。**

```
┌─────────────────────────────────────────┐
│ ① ヒーロー ＋ 実データのランキング       │  ← ファーストビュー完結
├─────────────────────────────────────────┤
│ ② なぜ「値段」だけでは比べられないのか   │  ← アハ体験
├─────────────────────────────────────────┤
│ ③ 品質を上げると、いくら上がるか         │  ← コストの物差し
├─────────────────────────────────────────┤
│ ④ メール登録 ＋ 2問                      │  ← コンバージョン
├─────────────────────────────────────────┤
│ ⑤ このサイトがやらないこと ＋ 免責       │  ← 信頼
└─────────────────────────────────────────┘
```

---

### ① ヒーロー（ファーストビューで完結させる）

**ヒーローは実データそのもの。** キャッチコピーとイラストの組み合わせにしない。

```
 │╷│╷│
 pergram                                    ← 左上・小さく。主役はランキング

▌タンパク質1gあたり、いくら払ってる?
市販68製品を、ラベル表示の含有量からタンパク質1gあたりの単価で並べました。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 1  ブランドA ホエイ 3kg
    含有率 78% / 国内製造              ¥3.2 /g
─────────────────────────────────────────
 2  ブランドB WPC 3kg
    含有率 71% / 国内製造              ¥3.5 /g
─────────────────────────────────────────
 3  …                                  ¥3.8 /g
 4  …                                  ¥4.1 /g
 5  …                                  ¥4.4 /g
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
残り63製品と、他の成分は公開時にお知らせします。

           [ 公開時にメールで知らせる ]
```

**設計指示**
- 上位5件は**実データを使う**（ダミーを入れない。ここで嘘をつくと全部が崩れる）
- **既存の競合も「1gあたり単価」は出している**（男前研究所、個人note等）。差別化は網羅性・鮮度・中立性なので、「68製品」「毎日更新」「順位は報酬に影響しない」を数字と文言で明示する
- 数値 `¥38 /g` は行内で最大かつ `--signal`
- ブランド名は実名を出す。伏せると信憑性が消える
- 「残り42製品」という**具体的な数**を出す。「たくさん」ではない
- CTA は1つだけ。ヒーロー内に置き、スクロールしなくても登録できる
- ヒーロー画像・イラスト・アイコンは**使わない**。表がヒーロー
- ロゴは左上に小さく置く。ロゴを大きく見せない（このLPの仕事はブランド認知ではなく登録）
- H1 とタグラインは同義。**H1 をタグラインそのものにする**ことで、ブランド想起と価値提案を1行で兼ねる

**コピー規則**
- H1 は疑問文。断定より「自分はいくら払っているんだろう」という自己参照を起こす
- 「実測」と書かない。**ラベル表示値**であることを明記する（正確さと法務の両面）

### ② なぜ「値段」だけでは比べられないのか

このプロダクトの存在理由を1つの例で示すセクション。**ここが最も重要な説得**。

```
▌同じ「マグネシウム500mg」でも、中身は6倍違う

  酸化マグネシウム 500mg
  └ マグネシウムとして 約300mg      ━━━━━━━━━━━━━━━━

  グリシン酸マグネシウム 500mg
  └ マグネシウムとして 約50mg       ━━━

ラベルの数字をそのまま比べても、単価は比較できません。
このサイトは、元素量に換算してから並べます。
```

- 横バー2本で長さの差を見せる。グラフライブラリは不要、CSS の幅だけでよい
- 「どちらが優れているか」は**書かない**。事実だけ（[product/requirements.md](../product/requirements.md) §5）
- 数値の出典を `--muted` で小さく添える

---

### ③ 品質を上げると、いくら上がるか（コストの物差し）

[service.md](./service.md) §4 のシグネチャ要素を、LP では**インタラクティブなデモ**として置く。

```
▌「認証つきがいい」は、1日いくらの話か

安い ├──●─●──●───●●──────●────●───────●──────┤ 高い
        ▲¥38                    ▲¥57
        条件なし                 第三者認証あり

         [ 第三者認証あり ]  [ 国産 ]  [ 人工甘味料なし ]
              ↑ タップするとドットが絞り込まれ、最安が右へ動く

              → 認証を条件にすると +¥95/日
```

**設計指示**
- 対数スケールであることを軸ラベルに明記
- チップをタップ → 条件外のドットがフェードアウト → 最安マーカーが移動 → 差額が数値で出る
- `prefers-reduced-motion: reduce` ではフェードせず即時切替
- ドットのタップ領域は 44px 以上
- **これを触ったかどうかを GA4 の `ruler_filter` で計測する**（[research/validation-plan.md](../research/validation-plan.md) §7）
- モバイルでは高さを圧縮し、チップは横スクロールさせず折り返す

このセクションが「オーガニックは高いけど良さそう」という迷いへの答えになる。ただし**どちらを選ぶべきかは言わない。**

### ④ メール登録フォーム

**入力は3つまで。** それ以上は CVR が落ちる。

```
▌公開したらお知らせします

  メールアドレス          [                    ]

  どの成分を見たいですか?（複数選択可）
  [プロテイン] [クレアチン] [EAA/BCAA]
  [HMB] [鉄・亜鉛] [ビタミン] [その他]

  普段どこで買いますか?
  [楽天] [Amazon] [iHerb] [マイプロテイン] [店舗]

           [ 登録する ]

  お送りするのは公開のお知らせのみです。いつでも解除できます。
```

**設計指示**
- 年齢・性別・体調は**取らない** 🔒（[product/requirements.md](../product/requirements.md) §3.4）
- 成分選択は**メールアドレスの直下**に置く。ここが検証の主目的（[research/validation-plan.md](../research/validation-plan.md) §5）
- チップはタップで選択。ドロップダウンにしない（モバイルで摩擦になる）
- 送信後は同一ページ内で完了状態に切り替える。別ページに飛ばさない
- 完了時の文言:「登録しました。公開したらお知らせします。」— 感嘆符を使わない
- エラーは謝らない。「メールアドレスの形式を確認してください」のみ

---

### ⑤ このサイトがやらないこと

**信頼構築と法務保護を兼ねる。** 競合が誰も書いていない差別化にもなる。

```
▌このサイトがやらないこと

  成分の効果や効能は書きません。
  独自の「おすすめ度」や総合スコアは作りません。
  順位は表示中の指標だけで決まります。広告収入は順位に影響しません。
  年齢・性別・体調などの情報は保存しません。

  数値はメーカーが公表するラベル表示に基づきます。
  参照値の出典: 厚生労働省「日本人の食事摂取基準(2025年版)」

  本サイトは医療上の助言を行うものではありません。
  掲載製品は医薬品ではなく、疾病の診断・治療・予防を目的としたものではありません。
  摂取の判断は医師・薬剤師にご相談ください。
  本サイトはアフィリエイト広告を利用する予定です。
```

- `--muted`、小さめのサイズ。ただし**折りたたまない**（常時表示）
- リスト形式。装飾しない

## 4. モバイル最適化

想定流入の大半はスマートフォン。**モバイルを主として設計する。**

| 項目 | 指示 |
|---|---|
| ファーストビュー | H1 + サブコピー + ランキング上位3件 + CTA が**スクロールなしで入る**こと |
| ランキング行 | 2段組み（1段目: 製品名・属性 / 2段目: 単価を右寄せ大きく） |
| CTA | ヒーロー内 + フォーム直上 の計2箇所。追従バーは置かない（圧迫感が出る） |
| タップ領域 | すべて 44px 以上 |
| フォント | 本文 16px 未満にしない（iOS のズーム発動を防ぐ） |

## 5. パフォーマンス要件

広告費を払って流入させるため、離脱が直接コストになる。

| 項目 | 目標 |
|---|---|
| LCP | 2.0 秒以内 |
| 画像 | 原則使わない。使う場合も WebP・遅延読み込み |
| フォント | Archivo / IBM Plex はサブセット化して self-host。CDN 待ちを作らない |
| JS | 物差しのインタラクションのみ。フレームワーク不要 |
| データ | 上位製品のデータは HTML に直書き。API 呼び出しをしない |

## 7. Claude Design への依頼要点

1. **ヒーローは表そのもの。** イラスト・写真・グラデーションを使わず、実データのランキングをファーストビューに置く
2. **色は `--signal` の青1色だけを意味に使う。** 単価の数値と CTA 以外に使わない
3. **Supplement Facts パネルの罫線階層（6px/3px/1px）を全体の骨格にする。** 角丸は0
4. **数値は必ず等幅（tabular-nums）。** 桁が揃わないと比較表として機能しない
5. **セクションは5つ固定。** 増やさない
6. **禁止語リスト（§1）を厳守。** 広告審査に直結する
7. モバイルファースト。ファーストビューでランキング3件と CTA まで見えること
8. **ロゴ `pergram` は全て小文字。** ワードマークはルーラーティックと組み合わせ、シグネチャ要素（③のコストの物差し）と同じモチーフで統一する
9. **OGP 画像**も用意する。ロゴ + タグライン + ランキング上位3行を、SNS シェア時にそのまま読める密度で配置（1200×630）
