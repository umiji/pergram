# PO確認待ちキュー

**書けるのはオーケストレーターだけ。** 担当エージェントは PO へ直接問い合わせられないため、判断が要るものはすべてここへ集まる。

## 書式（機械が読む部分がある）

1件は `### Q-###` で始まる見出しから次の見出しまで。**見出しの行に、識別子と状態を必ず同じ行で置く。**

```markdown
### Q-### [未回答] 一行でわかる質問の要約
- 登録日: YYYY-MM-DD
- 質問・判断事項: 何を決めてほしいか
- なぜ判断が必要か: 組織で決められない理由（権限外 / 情報不足 / 要件不明 / トレードオフ）
- 選択肢: A案 … / B案 …
- 各案の利害: A案は … / B案は …
- 推奨案: A案。理由 …
- 影響するタスク: T-XXX（回答が無いと止まるもの）
- 待つ間も進められるタスク: T-YYY, T-ZZZ
- 回答: （回答後に記入）
- 反応: （回答後に記入。下記）
```

`- 反応:` には、**回答そのものではなく、PO がどう反応したか**を書く。差し戻されたなら何を差し戻されたか、却下されたならなぜか、問いの立て方を直されたならどこが悪かったか。**PO の言葉に近い形で残す。**

これは組織改善のための信号である。**PO の反応は、組織が受け取れる最も価値の高いフィードバックであり**、いま会話の中にしか存在しない。セッションが終われば消える。次の組織点検で改善エージェントがここを読む。

反応が特に無く、そのまま承認されたなら「そのまま承認」と書く。**空欄にしない。**

**識別子と状態を同じ行に置くのは、台帳の検査スクリプトがその形で未回答件数を数えるためである。** 状態を別の行に書くと、未回答が常に0件と数えられ、ゴール健全性の指標（PO確認待ちの増加傾向）が機能しなくなる。

状態は `[未回答]` / `[回答済み]` / `[取り下げ]` の3つ。**回答が来たら見出しの状態を書き換える。**

`- 待つ間も進められるタスク:` を空にしない。**書けないなら、組織全体が止まっているということである。** それ自体が報告に値する事実であり、空欄で登録してはならない。

## 回答が来たら、4つやる

1. 見出しの状態を `[回答済み]` にし、`- 回答:` を埋める
2. 影響していたタスクの `## 決定ログ` へ、決定・却下案・出典を転記する
3. タスクの状態を `PO確認待ち` から適切な工程へ戻す
4. 回答が一般的な基準になっているなら、`CLAUDE.md` または `.claude/rules/` へ昇格させる
