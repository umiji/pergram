## 台帳検査の文字コード対策（2026-09-02）

**この環境では、台帳の整合性検査が落ちていた。** `.claude/scripts/org-*.py` は日本語を出力するが、
Windows では Python の既定の出力文字コードが cp932 になる。停滞候補の行に含まれる `—`（em dash）で
`UnicodeEncodeError` になり、**セッション開始フックが exit=1 で終わっていた**。フックの中では落ちたことが
見えないため、「検査が走っているつもりで走っていない」状態が続いていた（このセッションの開始時にも、
文脈へ入っていたのは決定ログ・モニタ・トークン集計の3つだけで、台帳検査は入っていない）。

対策として、6本すべての import 直後で `sys.stdout` / `sys.stderr` を UTF-8 へ固定した。
**異常終了と文字化けの両方がこれで消える** — 呼び出し側（フック、パイプ、CI）はいずれも UTF-8 で読むため。

確認: `python .claude/scripts/org-check.py --root . --hook` が **exit=0**、日本語が正しく出る。
以前は同じコマンドが exit=1。

**これは配布元（`agents-org`）へ差し戻す価値がある。** Windows で導入すれば、どのリポジトリでも同じことが起きる。

## 段4がエージェント定義に残した参照ずれ（2026-09-02・修正済み）

**スキルを表へ足したことで、本数や順番を指していた地の文がずれた。** 段6で `org-review` が1件目を報告し、
残り2つを横断確認で見つけた。**どれもエラーにならず、担当エージェントが誤った対象を最優先と読む形で黙って効く。**

| 定義 | 元の文 | 何が起きていたか | 直した形 |
| --- | --- | --- | --- |
| `org-review` | 「この3本は…最優先である」 | 表が4本になり、`ecc:accessibility` を優先から外して読む余地 | 「上の表のスキルは」 |
| `org-design` | 「後者を呼ぶ理由」 | 表が3本になり、`ecc:architecture-decision-records` を指すはずが `ecc:seo` を指す | スキル名で明示 |
| `org-implementation` | 「後者を必ず呼ぶ理由」 | 表が4本になり、`superpowers:verification-before-completion` を指すはずが `ecc:database-migrations` を指す | スキル名で明示 |

**位置で指す書き方（「前者」「後者」「この N 本」）をやめ、スキル名で指す形へ統一した。** 表は導入先ごとに増えるため、
位置と本数は必ず腐る。**配布元（`agents-org`）の元テキストが位置で指しているので、そこも直す価値がある。**
