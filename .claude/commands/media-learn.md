# 観測から投稿の型を学ぶ

対象: `$ARGUMENTS`

**このコマンドは投稿を行わない。** X を読んで、観測から「型」の提案を作るところまで。
**採用も行わない** — 提案を作ったら中身を見せて、採用するかどうかを利用者に尋ねる。

## 前提の確認

X の読み取りは既定で無効になっている。まず状態を見る。

```bash
media-agent x doctor --account <アカウント>
```

- `x_reader.enabled = False` なら、config.yaml の `x_reader.enabled` を true にする必要がある。
  **勝手に書き換えず、利用者に確認する。**
- 資格情報 (`X_READER_COOKIE` / `X_READER_HANDLE`) が無ければ、
  **捨てアカウント**でログインした Cookie を `.env.local` に入れてもらう。
  本体アカウントの Cookie を使ってはいけない — 凍結すると投稿チャネルごと失う。
- 「経路が無効化されています」と出たら、それはサーキットブレーカが働いた状態である。
  **勝手に `x reset` しない。** X 側でアカウントの状態を確認してもらってから解除する。

## 手順

1. キーワードが指定されていなければ、何を調べたいか尋ねる。`strategy.md` と
   `personas/` を読んで候補を出すとよい。

2. 検索して観測を保存する。**1 検索語 = 1 リクエスト**（ページ単位で 20 件前後を収穫する）。

   ```bash
   media-agent x search "<キーワード1>" "<キーワード2>" --min-impressions 50000 --account <アカウント>
   ```

   - 検索語を増やすほどリクエストが増える。**1 回に 3〜4 語までに留める。**
   - 「表示回数が取れず絞り込みから外した投稿」が多い場合は抽出が壊れている可能性がある。
     `media-agent x doctor --live` を勧める。

3. 観測から型を抽象化する。

   ```bash
   media-agent x learn --since 7d --account <アカウント>
   ```

   観測が少ないと「抽象化を見送りました」と出る。**これは失敗ではない。**
   少ないサンプルから作った規則はノイズを固定するだけなので、観測を増やしてから再実行する。

4. 提案の中身を**全文**表示する。

   ```bash
   media-agent playbook show <提案ID> --account <アカウント>
   ```

## 報告のしかた

- 提案の本文を**そのまま全文**見せる。要約しない。採用するかどうかは
  「n = 何件の観測から作られた規則か」を読んで判断するものなので、要約するとその根拠が落ちる。
- **n が小さいことを隠さない。** n = 5 の提案と n = 30 の提案は別物である。
- 「信用しすぎてはいけない点」の節を必ず読み上げる。

## 採用について

**このコマンドの中で `playbook apply` を実行しないこと。**

提案を見せたうえで、採用するかを利用者に尋ねる。採用すると決まったら:

```bash
media-agent playbook apply <提案ID> --account <アカウント>
```

採用しても、config.yaml の `content.playbooks.active` を書き換えるまでは生成に使われない。
これも**利用者の判断**なので、勝手に書き換えない。試すだけなら
`media-agent post --playbook <ID>` でその回だけ使える。
