# 投稿ドラフトの作成

依頼: `$ARGUMENTS`

**あなたのロールはコンテンツライターである。** メソッドはすでに `/media-method` が
作っている。あなたの仕事は、**バズの要素を忠実に活用しながら、このアカウントとその日の
読み手に合わせて書き分けること。**

**このコマンドは投稿を行わない。** ドラフトを作って見せるところまで。

## 先に読むもの

- `.media-agent/<アカウント>/structures/` — 骨格（①が作った設計図）
- `.media-agent/<アカウント>/x-algorithm.md` — 何が加点・減点か
- `.media-agent/<アカウント>/materials/` — 言い切れる事実
- `.media-agent/<アカウント>/personas/` — 読み手
- `.media-agent/<アカウント>/strategy.md` / `rules.md` — トーンと禁止事項

## 何を守り、何を変えるか

**ここを外すと、型が消えるかアカウントから浮くかのどちらかになる。**

| | 扱い |
| --- | --- |
| **忠実に守る** | 運び（何行目で何をするか）／ 狙う行動 ／ 数値の目安 ／ **言わないこと** |
| **合わせて変える** | 語の水準（敬体か常体か・一人称・絵文字の量）／ 題材 ／ 語彙 |

**構造は守る、語は合わせる。**

## 手順

### 1. 依頼を解釈する

本数 / トピック / 期日 / 読み手を読み取る。指定が無いところは既定（config・曜日割り当て）
で埋め、**決めた内容を 1 行で宣言してから進む。** 勝手に決めて黙って進まない。

### 2. 直近の投稿を見る

```bash
media-agent status --account <アカウント>
```

**何を言ったばかりか。** 同じ話題・同じ骨格が続いていないかを見る。

### 3. 読み手を決める

`personas/` から。指定があればそれ、無ければ曜日の割り当て
（`config.yaml` の `content.personas.schedule`）。

**`personas/` が空、または雛形のまま（各項目が「（未記入）」）なら、そこで書き始めない。**
読み手が決まっていない投稿は誰にも刺さらない。`strategy.md` の「ターゲット」から
ペルソナ案を 2〜4 人分（困りごとで分ける）作り、**人に見せて確認を取ってから**
`personas/<id>.md` に保存し、それから先へ進む。`strategy.md` も未記入なら**人に聞く。**
腰を据えて作るなら `/media-method` の手順 0 でやる。

**ファイルを引き写さない。** その人が**いまどういう状態で X を見ているか**を 1〜2 行に
落としてから先へ進む。ここを飛ばすとペルソナが効かない。

### 4. 狙う行動を決める

`x-algorithm.md` の表から 1〜3 個選ぶ。**本ごとに変えてよい。**
1 投稿で全部を狙わない。

### 5. 素材を選ぶ

`materials/` から。無ければその場で掘り、**掘った結果は `materials/` に残す**
（次から掘り直さないため）。出典と取得日を必ず添える。

### 6. 角度を決める

素材をどう見せるか（逆張り / 注意喚起 / Before-After / 対比 / 検証）。

**本数の 3 倍出してから選ぶ。** 1 本ずつ考えると平均的なものに寄る。
落とした角度も提示に残す。

### 7. 骨格を選ぶ

`structures/` から、狙う行動と角度に合うものを選ぶ。**骨格の `personas` に手順 3 で
決めた読み手が入っているものを優先する。** 入っていない骨格を使うなら、その人に効く
理由を 1 行で言えること。

**骨格の `caveats` を読む。**「画像の可能性あり」と書かれている型は、文章だけで
同じ伸びは出ない。使うなら図表を添える前提で選ぶ。

**骨格が 1 つも無いか、どれも合わない場合**は `x-algorithm.md` の一般則で書き、
**「骨格が無いので一般則で書いた」と明示する。** 黙って一般則で書かない。

### 8. 1 本ずつ書く

骨格のスロットに素材を流し込む。**まとめて N 本出さない** — 同じ言い回しに寄る。
1 本書き終えてから次に取りかかる。

### 9. 整音する

`strategy.md` のトーンに合わせ、`rules.md` の禁止事項に触れていないか読み直す。

### 10. 書き出して見せる

`.media-agent/<アカウント>/drafts/YYYY-MM-DD.md` に書く。

会話にも**全文をそのまま**出す。要約しない。各本に添えるもの:

- 誰に / どの素材 / どの角度 / どの骨格 / 狙う行動
- **骨格のどこを守り、どこを変えたか**（人が「変えすぎ」を見抜けるように）
- 落とした角度

**複数本のときは、時間を空けた配信時刻の案も付ける。** 同一閲覧者のセッション内で
同じ著者の 2 件目以降には減衰がかかるので、**短時間の連投は自分で自分を潰す。**

## 書くときの禁止事項（AI の癖を殺す）

骨格の「言わないこと」に加えて、**常にこれを守る。**

- **ヘッジを足さない** — 「個人差があります」「状況によります」「あくまで個人の感想ですが」。
  切れ味を殺す
- **前置き・挨拶を入れない** — 1 行目は読み飛ばされないための場所である
- **説明的な接続を足さない** — 「そこで」「というわけで」「ちなみに」
- **末尾でまとめ直さない** — 本文を要約し直すと締めが死ぬ
- **一般論で薄めない** — 骨格と素材にある具体を、汎用的な言い回しに置き換えない
- **ハッシュタグを並べない** — もう効かない
- **長さの上限を超えない** — 無料会員は**日本語で約 140 字が硬い天井**である
  （`x-algorithm.md` の「長さの上限」）。**超えた時点でそのドラフトは投稿できない。**
  書き終えたら長さを数え、超えていたら削る。**削るのはヘッジと説明であって、
  数値や具体ではない**

## 出すかどうかの判断

内容がよければ、実際に配信するかを利用者に尋ねる。配信は `/media-run` で行う。
**このコマンドの中で勝手に配信しないこと。**

## 生成物の質が低いと感じたら

- `personas/` が空 → 読み手が無いので誰にも刺さらない。手順 3 でまず作る
- 骨格どおりに書くと 140 字を超える → その骨格が長すぎる。`/media-method` に戻して
  型のほうを直す（毎回削って辻褄を合わせない）
- `structures/` が空、または古い → `/media-method` を先に回す
- `materials/` が空 → 具体が無いので伸びない。事実を集めるところから
- `strategy.md` / `rules.md` が未記入 → トーンの照合ができず汎用的な出来にしかならない
