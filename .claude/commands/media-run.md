# メディア運用の実行

対象アカウント: `$ARGUMENTS`

> **このコマンドは実際に投稿しうる。** 投稿先が `buffer` に設定されていれば、
> 生成された文面がそのまま外部へ出る。取り消せない。

## 実行前に必ず行うこと

1. アカウントが指定されていなければ、一覧を出して選んでもらう。**推測で決めないこと。**

   ```bash
   media-agent accounts
   ```

2. 投稿先の設定を読む。`.media-agent/<アカウント>/config.yaml` の
   `publisher.connector` を確認する。

   - `dummy_x` — 記録のみ。外部へは出ない
   - `buffer` — **実配信される**

3. まず送信の手前まで走らせて、出る文面を確認する。

   ```bash
   media-agent run --dry-run --account <アカウント>
   ```

4. 採用された文面を**全文そのまま**利用者に見せ、**本当に配信してよいかを尋ねる。**
   投稿先が `buffer` の場合は、そう明示したうえで確認を取る。
   **利用者がはっきり同意するまで次に進まないこと。**

## 実行

同意が得られてから実行する。

```bash
media-agent run --account <アカウント>
```

## 実行後

1. 結果を確認する。

   ```bash
   media-agent queue list --account <アカウント>
   ```

2. 「なぜこの投稿になったか」の記録を確認できることを伝える。

   ```bash
   media-agent task list --account <アカウント>
   ```

3. 配信先が Buffer の場合、成功は「X に出た」ではなく
   **「Buffer に受理され、予定時刻に出る」**を意味する。予定時刻も併せて伝える。

## 失敗したとき

- 終了コード 2 は設定・入力の不備。原因と対処がメッセージに出ているので、それを伝える。
- 終了コード 1 は実行時の失敗。`media-agent task show <id> --account <アカウント>` で詳細を読む。
- **同じコマンドを黙って再実行しないこと。** 二重投稿になりうる。
