# 投稿候補の生成・評価・昇格

依頼: `$ARGUMENTS`

**このコマンドは投稿を一切行わない。** 作るのは `draft` の post までで、実際の
配信は `/media-run` の経路だけが行う。

**4段のうち④を担当する。** 型（`structures/`）は ① と ② で `/media-method` が、
テーマは ③ で `/media-strategy` と `personas/` が決めている。**ここでやるのは、
決まったテーマを決まった型へ流し込むことだけである。型を作り直さない。**
型の `accepts_numbers` が `no` のものへ数値中心のテーマを流し込まない。


## `/media-draft` との使い分け

**投稿文を作る経路は 2 本ある。片方が古いのではなく、狙いが違う。**

| | `/media-draft`（= `media-agent post`） | このコマンド（= `media-agent content`） |
| --- | --- | --- |
| 材料 | 骨格 (`structures/`) と素材 (`materials/`) | **承認済みの戦略** |
| 作る数 | 数本、その場で選ぶ | 10〜20 件、**全部残す** |
| 残るもの | 選ばれた 1 件 | どの柱の仕事か・どの角度か・どの機会に紐づくか・**落ちた理由**まで |
| 評価 | 生成時にまとめて | **二段構え**（不合格判定 → 10 軸の採点） |
| 向くとき | 今日の 1 本を早く出したい | **何が効いたのかを後から測りたい** |

**戦略がまだ承認されていないなら `/media-draft` を使う。**
このコマンドは承認済み戦略が無いと終了コード 2 で止まる（それは正しい動作で、
戦略の無い評価は「一般に良い文章か」を測るだけになるため）。

## 手順

### 1. アカウントと本数を確定する

指定が無ければ一覧を出して**利用者に選んでもらう**。推測しない。

```bash
media-agent accounts
```

本数の指定が無ければ既定のままでよいが、**決めた本数を 1 行で宣言してから進む。**

### 2. 参照する戦略を確かめる

```bash
media-agent strategy list --account <アカウント>
```

`*` が無い（承認済みが 1 版も無い）なら、そこで止めて `/media-strategy` へ回す。
**黙って `/media-draft` に切り替えない。** 依頼と違うものが出てくる。

### 3. 候補を作る

```bash
media-agent content generate --account <アカウント> --count <本数>
```

出るのは全件 `generated`（未評価）である。**1 件につき Provider を 1 回呼ぶ**ので、
本数は費用に直結する。

### 4. 評価して順位を付ける

```bash
media-agent content evaluate --account <アカウント>
```

一段目（不合格条件）に当たったものは `rejected` になり、**順位を付けない。**
残りに 10 軸の採点をして `ranked` にする。

**落ちたものも本文と理由を持ったまま残る。** 報告では、不合格の件数と内訳を
必ず伝える。隠すと同じ失敗を繰り返す。

### 5. 一覧を人に見せる

```bash
media-agent content list --account <アカウント>
```

**上位だけを見せない。** 落ちたものが何件あり、なぜ落ちたのかまで伝える。
1 件の中身を読むときは:

```bash
media-agent content show <candidate_id> --account <アカウント>
```

ここに出るのは本文だけではない。**どの柱・どの角度・どの機会・どの実験・
どの出典から来たか**が 1 件ごとに残っている。人が選ぶための材料なので、
要約せずにそのまま見せる。

### 6. どれを出すか、人に選んでもらう

**勝手に昇格させない。** 順位はあくまで機械の見立てであって、出すかどうかの
判断ではない。

### 7. 選ばれたものを下書きにする

```bash
media-agent content promote <candidate_id> --account <アカウント>
```

`ranked` の候補が `promoted` になり、`draft` の post ができる。**まだ投稿されない。**

- Policy が拒否したら終了コード 1 で止まる。**候補は `ranked` のまま残る**ので、
  1 日の上限が理由なら時間をおけば通る
- 未評価や不合格の候補は昇格できない（終了コード 2）
- 同じ候補を 2 回昇格させることはできない（終了コード 2）

### 8. 配信は別のコマンド

内容がよければ、実際に配信するかを利用者に尋ねる。配信は `/media-run` で行う。
**このコマンドの中で配信しないこと。**

## 機械的に結果を読むとき

どのサブコマンドにも `--json` がある。人間向けの表示は出ず、JSON だけが出る。

```bash
media-agent content list --account <アカウント> --json
```

## 生成物の質が低いと感じたら

- 候補が 0 件 → 承認済み戦略の柱が空か、信号が集まっていない。
  `media-agent strategy show` で柱を確かめる
- 不合格ばかり → `rules.md` の禁止事項と戦略の声の制約が厳しすぎるか、
  素材が無く「裏付けのない断定」に倒れている
- 採点が全部同じ点 → 軸が機能していない。`media-agent content show` で
  素点の分布を見て、人に報告する
- 上位が同じ角度で埋まる → 一覧は多様性の入れ替えを通した順で出ているので、
  それでも偏るなら生成の段で角度が寄っている
