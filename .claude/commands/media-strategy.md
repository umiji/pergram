# 運用戦略の作成と承認

対象アカウント: `$ARGUMENTS`

**このコマンドは投稿を一切行わない。** 戦略を 1 版作り、人が承認するところまで。

**4段のうち③の半分を担当する。** ここで決めるのは**扱うテーマ**であって、型ではない
（型は `/media-method` の ①②）。**扱うテーマが 1 つの軸に寄っていると、ペルソナも投稿も
その軸だけになる** —— 2026-09-08 時点の旧版は 7 項目すべてが価格か成分で、
「価格以外の切り口を混ぜろ」という指示に応える受け皿が戦略の側に無かった。
**軸が 2 つ以上あることと、各テーマが自分たちの持っているデータで書けることを確かめる。**

戦略は**上書きされない。** 新しい版は別の `strategy_id` として足され、承認した
時点でそれまでの承認済みが `superseded` になる。過去の投稿の由来はその時点の版に
あるので、**古い版を消すと「なぜこの投稿になったか」を辿れなくなる。**

## 手順

### 1. アカウントを確定する

指定が無ければ一覧を出して**利用者に選んでもらう**。推測しない。

```bash
media-agent accounts
```

### 2. 材料が揃っているか見る

```bash
media-agent doctor --account <アカウント>
```

戦略は `strategy.md` / `rules.md` / `personas/` / 観測 / 過去の実測から組み立てる。
**FAIL があれば先に伝える。** 材料が欠けたまま作った戦略は、欠けたことが
`missing_inputs` に出るだけで、中身は薄いままになる。

### 3. 1 版作る

```bash
media-agent strategy build --account <アカウント>
```

出るのは**提案 (`proposed`)** であって、投稿生成はまだ参照しない。

`--ideas 0` を付けると着想の在庫を作らない（Provider の呼び出しが減る）。
機械的に結果を読みたいときは `--json` を付ける。

### 4. 中身を人に見せる

```bash
media-agent strategy show <strategy_id> --account <アカウント>
```

**要約して済ませない。** 少なくともこの 4 つはそのまま見せる。

- 目的と柱（何本あり、配合比がどうなっているか）
- 実験（何を検証しようとしているか）
- **材料が見つからなかったもの** (`missing_inputs`)
- **未解決の問い** (`open_questions`)

後ろの 2 つは「この戦略が何を知らないまま立っているか」である。**隠すと、
知らないことを知らないまま投稿が始まる。**

### 5. 承認を人に求める

**承認は人が行う。** 勝手に `approve` を打たない。

```bash
media-agent strategy approve <strategy_id> --account <アカウント>
```

承認すると、これ以降 `media-agent content generate` がこの版を参照する。

## 版を並べる

```bash
media-agent strategy list --account <アカウント>
```

`*` が付いているのが承認済み（投稿生成が参照する版）。

## 生成物の質が低いと感じたら

- `missing_inputs` が多い → 材料が無い。観測 (`media-agent x`) や
  `personas/` を先に埋める
- `open_questions` が的外れ → `strategy.md` の方針が曖昧。人に書き足してもらう
- 柱が汎用的すぎる → プロジェクトの知識 (C 層) が薄い。README や
  `media-agent knowledge show` で読める内容を確かめる
