# 配布物への先行適用の退避場所

`org-` で始まるファイルは **配布物**（配布元は `agents-org`）であり、
このリポジトリで直しても**次に配布物を更新した時点で上書きされて消える**。
過去に2ファイル分が黙って消えた事故がある。

PO が承知のうえでこのリポジトリへ先行適用した変更は、ここへ退避する。

## 置いてあるもの

| ファイル | 何か |
| --- | --- |
| `<名前>.orig` | **その変更を当てる前の版。** `diff` を取れば、いま自分の変更が生きているか分かる |
| `D-001.patch` | 組織の決定 D-001（対策5本）の変更を1つにまとめた差分。`git apply` で当て直せる |

`.orig` の名前は元のファイル名。同名が衝突する場合だけ、置き場所を頭に付ける
（`org-orchestrate.SKILL.md.orig` / `templates-T-XXX.md.orig`）。

## 配布物が配り直されたときの手順

```sh
# 1. 自分の変更が消えていないか見る
diff .claude/patches/org-check.py.orig .claude/scripts/org-check.py

#    差分が出なければ、変更は消えている（= 配布版に戻された）

# 2. 消えていたら当て直す
git apply --3way .claude/patches/D-001.patch

# 3. 当たらなければ手で入れ直す。目印は本文中の課題番号（(D-001-3) など）
```

**課題番号は変更した行の近くに刻んである。** `grep -rn "D-001-" .claude/` で
どこに何が入っているかが引ける。

## ここに増やすときの決まり

- **退避は、変更を入れるコミットと同じコミットで行う。** 後から思い出して置くと、
  何を当てる前の版なのかが分からなくなる
- **`.orig` は上書きしない。** 2回目以降の変更は、最初の `.orig` からの差分になる
- **不具合そのものは、配布元へ差し戻す。** ここは「消えたことに気づける」ための
  仕掛けであって、配布元を直さなくてよい理由ではない
