# 投稿の構造（いまタイムラインでよく見る型）

⚠️ **出所は検索で集めた二次情報（2026-08-21 確認）。**重みの数値は
[X_algorithm_2026.md](../../../../docs/Marketing/X_algorithm_2026.md)（公開コード）が勝つ。
表示の仕様は端末とバージョンで変わる。**型は流行り廃りがあるので、そのまま長く使わない。**

## なぜ「最後だけ見せない」型が増えたのか

タイムラインでは投稿の途中に「さらに表示」の境目ができる。

| 端末 | 隠れる条件 |
|---|---|
| ブラウザ | 141文字目以降。または **11行目以降** |
| スマホアプリ | 141文字目以降（行数は問わないという報告と、10行前後で折りたたむという報告の両方がある） |

⚠️ 端末差があるので厳密に当てにいかない。**9行以内なら全端末で全文、10行を超えたら
「隠れる前提で組む」**の2択で扱う。どこで切れるかは `npm run x:lint` が線を引いて見せる。

日本語は140文字が上限（＝加重280）なので、**文字数ではなく行数で境目を作る**のが
いま多い形。境目の向こうに答えを置くと、次の3つが起きる。

- 投稿そのもののクリック（0.4）
- 「答えは?」がリプライになる（5.0 / 相互フォロー相手なら 20.0）
- 読み飛ばし（-0.02）を避けられる

🔒 **ただし、境目の向こうに実質が無ければただの釣り。**
釣りは「興味なし -43.2」「ミュート -58.8」への最短路で、いいね100個分が一撃で飛ぶ。

## 型

そのまま流用しない。**pergram 版**の列まで読んでから使う。

### A. ラベル＋三段＋引き

```
男のレベルは
初回デートに持ってくるバッグで差がつく。

🥉それはやめよっか…
・リュック
・パンパンの肩掛け

🥈マイナスではない
・小さめのショルダー

🥇センスよき↓
```

- **構造**: ラベル1行 → 主張1行 → 空行 → 3段（各段は見出し＋箇条書き2〜3） → 最上段だけ伏せて `↓`
- **効く理由**: 段が3つだと読む負担が軽い。自分がどれかを当てはめられる。最後が空いているので続きを探す
- **pergram 版**: 🔒 **優劣の断定（「それはやめよっか」）は使えない**（コピーの規則・景表法）。
  ランクではなく**分かることの段階**に置き換える

  ```
  プロテインの単価は
  袋の値段では出ません。

  ここまでで分かること
  ・袋の値段
  ・内容量

  もう一段で分かること
  ・1食あたりの価格

  最後まで割って初めて出るもの↓
  ```

### B. 会話ログ・寸劇

```
～◯◯にて～
ぼく「〜ですか?」
担当「〜ですよ」

↓(場面転換)↓

ぼく「まず、〜とは…」
```

- **構造**: 場面の見出し → 短い掛け合い → `↓(転換)↓` → オチの直前で切る
- **効く理由**: 台詞は読むのが速くリズムが出る。難しい話を軽くできる
- **pergram 版**: 🔒 **実在の店員・メーカー・他人の発言を作らない**（創作した会話は事実ではない）。
  使うなら**自分の作業ログ**にする

  ```
  ～価格を取り直していたら～

  ぼく「この5kg、安いな」
  ぼく「…含有率85%か」
  ぼく「割ると ¥1.9 / タンパク質1g」

  ↓(そのまま隣の3kgを割る)↓
  ```

### C. リード1〜2行 ＋ 図解画像

- **構造**: 断定か問いを1〜2行 → 本体は画像1枚 → 「保存」を促す一言
- **効く理由**: 本文が短いので読み切られる。情報は画像に集約
- **pergram 版**: `npm run x:card --type rank` がこの画像。
  ⚠️ 画像の重みは 0.05 しかない。**画像はスコアのためではなく読まれるために貼る**

### D. 二分法（これまで / これから）

- **構造**: 見出し → ❌側3行 → ⭕側3行 → 締めの1行
- **pergram 版**: ❌⭕ は「間違い / 正解」ではなく「袋の値段で見る / 1gあたりで見る」の
  **見方の違い**として書く。`--type split` の画像と対になる

### E. ◯選・数字ラベル

- **構造**: 「◯◯3選」→ 箇条書き → 具体例
- **pergram 版**: 数字は `npm run x:facts` の出力から。
  🔒 「おすすめ3選」は書けない（N-03）。「1gあたりが安い3件」なら事実

### F. 体験 → 学び → チェックリスト

- **構造**: 自分の失敗の告白 → 抽象化した学び → 再現用の箇条書き
- **pergram 版**: 公式アカウントとしての体験（価格を取り直していて気づいたこと）に限る。
  「個人開発」の語りにしない

### G. ミーム構文（タゴサク構文など）

- 短い・断定的・理屈っぽい語調をそのまま借りる型。参加しやすいので広がる
- **pergram では基本使わない。** 出所の文脈（映画・事件・人物）を背負うため、
  取り違えると一撃で信用を失う。公式アカウントが払うコストに合わない

## 組み方の目安

| 項目 | 目安 |
|---|---|
| 1行の長さ | 20〜25文字（iPhone は 22 前後）。**1行目は必ず1行に収める** |
| 行数 | 9行以内なら全端末で全文。超えるなら境目を意図して置く |
| ブロック | 空行で区切って3つまで |
| 記号 | `・` `↓` `／` でリズムを作る。絵文字は0〜2個 |
| 締め | 問いかけか言い切り（[voice.md](voice.md) の「終わり方」） |

## 🔒 型を使うときに守ること

1. **引きの向こうに実質を置く。** 開いて損した投稿はミュートされる
2. **優劣を断定しない。** 三段は「良い / 悪い」ではなく「分かることの段階」
3. **会話・体験を創作しない。** 数字は `x:facts`、出来事は実際にあったことだけ
4. **同じ型を続けない。** 3回続いたら別の型に変える（`npm run x:feed` で直近を見る）。
   型の繰り返しは内容の繰り返しと同じくらい早く飽きられる
5. **流行の型に寿命がある前提で使う。** ここの型が古びていたら、この文書を書き直す
