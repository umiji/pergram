# ツリーとクリフハンガー

## 最重要ルール

🔒 **140字に収めることを目的に、文章を不自然に削らない。**

日本語は140字（加重280）が上限。**足りないならツリーにする。**
ただしツリーは「文字数超過による分割」ではない。

> **1投稿目をクリフハンガーとして設計する。**

## 1投稿目の役割

1投稿目だけで**最低限の意味は成立させる。**ただし答えを全部出さない。

理想的な読者心理:

```
「あ、これは気になる」
   ↓
「なんで？」
   ↓
「続きを読みたい」
```

## 🔒 「続く↓」を基本形にしない

「続く↓」「1/2」などの明示的な案内は、**必要な場合のみ**。
基本は**文章そのものを未完にする。**

### 切り方4種

| 切り方 | 1投稿目の終わり | 2投稿目 |
|---|---|---|
| **疑問で切る** | 「実は、容量より先に見るべき数字がある。」 | 答えを出す |
| **👇で切る** | 「タンパク質1g単価で計算してみると👇」 | 数字を提示 |
| **接続語で切る** | 「ところが、実際に計算してみると——」 | 続きへ |
| **寸止め** | 「この2つを比較すると、意外な結果になった。」 | 結果を提示 |

## クリフハンガーの型

### Pattern A：疑問型

```
「1kg 3,000円」のほうが安い。

……でも、本当にお得なのはどっちかというと👇
---
答え ＋ 理由 ＋ 具体例
```

### Pattern B：数字型

```
2,980円。

一見かなり安いプロテイン。

でも、タンパク質1g単価にすると👇
---
具体的な数字を提示
```

🔒 数字は `npm run x:facts` から。架空の例なら A / B の記号で書く。

### Pattern C：反転型

```
「大容量＝お得」だと思ってた。

ところが、比較してみると👇
---
常識が反転するデータを提示
```

### Pattern D：ストーリー型

```
最初は「価格だけ比較すれば十分」と思ってた。

でも、商品を並べてみると問題が出てきた。

それが👇
---
問題を明かす
```

## ツリー構成

### Template A：2投稿

| | 中身 |
|---|---|
| 1 | 違和感 / 問題提起 → 答えを寸止め |
| 2 | 答え → 理由 → 具体例 → **必要なら** pergram |

### Template B：3投稿

| | 中身 |
|---|---|
| 1 | 強いフック → 「なぜ？」を作る |
| 2 | 意外な答え → 数字・具体例 |
| 3 | 一般化 → 読者への問い / pergram への自然な接続 |

**「1投稿目：気になる → 2投稿目：なるほど → 3投稿目：だから pergram か」**
という読書体験を設計する。

### Template C：1投稿完結

**すべての投稿をツリーにしない。**次は1投稿完結でよい。

- あるある
- 一言の発見
- 短い意見
- 軽い問い
- データの小ネタ

🔒 **ツリーにすること自体を目的にしない。**

## 機械が見るところ

```bash
npm run x:lint -- draft.txt --feed
```

下書きは `---` だけの行で投稿を区切る。

| コード | 意味 |
|---|---|
| `url.firstPost` (error) | **1投稿目に URL を置かない。**引きを作る場所であって誘導の場所ではない |
| `thread.length` (warn) | 4投稿以上。3段までに収める |
| `layout.fold` (warn) | 10行超。**引きの位置が「さらに表示」の向こう側に落ちていないか確認する** |
| `promo.cta` (warn) | 誘導の言い回し。ツリーの**最後の投稿**でだけ素通りする |

⚠️ 以前は「2投稿目に URL が無ければ error」にしていた。**これは外した。**
誘導のためのツリーしか想定していなかったが、クリフハンガー型の2投稿目は
**答えであって URL ではない**。

🔒 **引きを折りたたみの向こうに置かない。**「続きが気になる」を作る行が
「さらに表示」の裏にあると、そもそも読まれない。`x:lint` が線を引いて見せる。
