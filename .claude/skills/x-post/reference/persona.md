# ペルソナから投稿文までの手順

「何を書くか」を思いつきで決めないための道筋。**上から順に1つずつ落としていく。**

```
① ペルソナを選ぶ  →  ② その人が読みたいものを出す  →  ③ 書ける形に変換する
```

そのあとは [SKILL.md](../SKILL.md) のワークフロー（Step 1 投稿タイプ →
Step 2 狙う反応 → Step 3 フック → Step 4 題材 → …）に渡す。
**この文書が担当するのは①〜③**で、「誰に、何を話せるか」までを決める。

②を飛ばすと「うちが言いたいこと」だけになり、③を飛ばすと薬機法・景表法に触れる。
**④を飛ばすと、題材が違っても目的が毎回「サービスの紹介」になる**（これが宣伝に見える正体）。

🔒 **この手順の出口は「読み物」であって、告知ではない。**
直接告知は **5%（20本に1本）**、開発日記を足しても 15% まで
（[post_types.md](post_types.md) の比率表）。**残りは読んで終わってよい。**

---

## ① ペルソナ

### メインターゲット

**20〜40代くらいの、プロテイン・サプリを日常的に買う人。**
ガチのボディビルダーだけではない。むしろ、

- 筋トレしている / ダイエットしている / 健康のためにタンパク質を摂っている
- プロテインを毎日飲む
- Amazon・楽天・公式セールを比較する
- 「結局どれが一番安いの？」と思っている
- コスパは気になる。でも1円単位でケチりたいわけではない
- 成分・味・ブランドも気になる

一言でいうと、

> **プロテインを買うたびに、ちょっと調べるのが面倒な人。**

🔒 **「1円でも安く」の人ではない。**そこを狙うと投稿が単価の話しか作れなくなる。
「調べるのが面倒」が中心なので、**調べなくても分かる話**が刺さる。

根拠は [requirements.md §2.1](../../../../docs/product/requirements.md) と
[validation-plan.md 段0](../../../../docs/research/validation-plan.md)・
[query-volume-research.md](../../../../docs/research/query-volume-research.md) の実測ボリューム。
**思いつきで足さない。**足すなら先に調査側を更新する。

### 3つの現れ方

同じ人でも、買い物のどの段階にいるかで読みたいものが変わる。

| | 誰 | 読みたいもの |
|---|---|---|
| **P-A** 量を飲む人 | 週3〜5回トレーニング。月2〜4kg 消費。大容量・国内ブランド中心（指名検索「エクスプロージョン プロテイン」74K） | 相場・値上げの理由 / セールの仕組み / 業界の動き |
| **P-B** 計算する人 🔒中核 | iHerb・個人輸入も使う。送料込みで自分で単価を出す（requirements.md §2.1） | 表示と単位の落とし穴 / 海外との差 / 広告の数字の読み方 |
| **P-C** 始めたばかりの人 | 選ぶ物差しを持っていない（「プロテイン おすすめ」90.5K） | 用語の意味 / ラベルの見方 / 何でできているのか / 扱い方 |

🔒 **同じペルソナに2本続けない。**同じ人にばかり話しかけると、他の層が離れる。
③共感・あるある は3人全員に当たるので、迷ったらここに寄せる。

## ② その人が読みたいものを出す ← ここが起点

**うちが答えられることから考え始めない。**それをやると必ず単価の話に戻る。
まず「その人が X で足を止めるもの」を、扱えるかどうかを気にせず全部出す。

一覧は [topics.md](topics.md) の「Ⅰ 読み手が実際に読んでいるもの」。
検索されている言葉は固有名詞ごと使う（X のアルゴリズムに読み手層を認識させる）。

---

## ③ 書ける形に変換する ← いちばん重要

**捨てるのは話題ではなく、断定の形。**
「効果」「おすすめ」を扱えないのは、それが**優劣と効能の断定**だからで、
同じ関心でも**事実・工程・制度・数字の形**にすれば扱える。

| 読み手の関心 | ❌ 書けない形（断定） | ⭕ 書ける形（事実） |
|---|---|---|
| どれがおすすめ? | 「おすすめ3選」 | 何を見れば自分で選べるか（表示の読み方） |
| WPIとWPCどっち? | 「WPIの方が吸収がよい」 | 精製の工程が違う。単価の帯も違う |
| 効果はあるのか | 「筋肥大に効く」 | 含有量と単価。それ以上は書かない |
| 高いのと安いので何が違う? | 「高い方が高品質」 | 値段の差が何の差なのか（含有率・内容量・送料・製法） |
| セールで買うべき? | 「今が買い時」 | ポイント還元と値引きは同じではない。条件で実質が変わる |
| なぜ値上げした? | 「これからも上がる」 | 輸入単価と価格改定リリースが公表している数字 |
| ダマになる | 「溶けやすい＝良い」 | 粒径・溶かす順番・水温という物理の話 |

🔒 **ずらせないものは捨てる。**トレーニング方法・論文紹介・味のレビュー・
育毛／妊活の文脈（N-09 / N-10）は、形を変えても扱わない。

🔒 **需要の大きさで選ばない。**「プロテイン おすすめ」90.5K は大きいが、
順位を語る形では扱えない。ボリュームは**言葉選び**に使い、**題材選び**には使わない。

## ④ 投稿タイプを決める ← ここが第一の軸

```bash
npm run x:feed
```

出力の **「次に書くタイプ（足りていない順）」** から選ぶ。6タイプの比率は
[post_types.md](post_types.md)。

| タイプ | 比率 |
|---|---:|
| ① 市場の発見 | 25% |
| ② コスパ・比較 | 25% |
| ③ 共感・あるある | 20% |
| ④ データ・ランキング | 15% |
| ⑤ 開発日記 | 10% |
| ⑥ 直接告知 | 5% |

🔒 **ランキング（④）だけを回さない。**「またランキングか」になる。
🔒 **直前と同じタイプを続けない。**題材が違っても、目的が同じなら同じ投稿に見える。

ペルソナとの相性:

| ペルソナ | 相性のよいタイプ |
|---|---|
| P-A 量を飲む人 | ① 市場の発見 / ④ データ・ランキング |
| P-B 計算する人 | ② コスパ・比較 / ⑤ 開発日記 |
| P-C 始めた人 | ③ 共感・あるある / ① 市場の発見 |

## ⑤ 題材を決める

`x:feed` の **「題材の候補」** から選ぶ。こちらも次を適用済み。

1. 直近2本と同じ族を外す
2. 価格系（単価の出し方 / 価格の動き）が3本に1本を超えていたら外す
3. うちの話が15%を超えていたら外す
4. 残りを「話していない順 → 族が薄い順」に並べ、族ごとに1つずつ

候補の上から1つ選び、[topics.md](topics.md) の**同じ見出し**から種を取る。
③で作った「書ける形」がその見出しの下に無ければ、②に戻って別の関心を選ぶ。

候補を無視してよいのは、**理由が1行で言えるとき**だけ（セールが今日始まった、等）。

---

## ⑥ メッセージを1行にする

材料を**読み手の持ち帰り**に変換する（SKILL.md 手順6の変換表）。
1投稿1メッセージ。2つ入れると両方伝わらない。

- ⭕「ECの『安い順』は最安を教えてくれない」（明日の買い物が変わる）
- ❌「除外リストを書く作業から始まりました」（作業報告）
- ❌「pergram なら一発で分かります」（宣伝であって持ち帰りではない）

**テスト**: 「だから何?」に1行で答える。答えられなければ捨てて⑤に戻る。
🔒 答えが**「pergram を使ってほしい」になるものも捨てる。**

## ⑦ 型に流し込む

[formats.md](formats.md) から、**メッセージの性質**で選ぶ。トピックで選ばない。

| メッセージの性質 | 型 |
|---|---|
| 思っていたことがひっくり返る | 三段＋引き / 二分法 |
| 見る場所・手順が変わる | 3ステップ図解 |
| 気づいた瞬間がある | 会話ログ（🔒 自分の作業ログに限る） |
| 順位・数字が主役 | リード＋図解画像（`x:card`） |
| 意見を聞きたい | 短い断定＋問いかけ（単発） |

⚠️ 型が3回続いたら変える。トピックを変えても型が同じなら同じ投稿に見える。

## ⑧ 機械に通す

```bash
npm run x:lint -- draft.txt --feed
```

文字数・禁止語・企業敬語・断定の推奨・URL の位置・折りたたみ位置・誘導の言い回し・
過去投稿との近さ。**error が残った文章を出さない。**

| コード | 意味 |
|---|---|
| `voice.corporate` (error) | 企業の定型文になっている。中の人が喋る言い方に直す |
| `voice.recommend` (error) | 「絶対買ったほうがいい」— 優劣の断定。事実を置いて判断は読み手に渡す |
| `voice.hype` (warn) | 「ガチで」「やばい」— 淡々と |
| `voice.today` (warn) | 「今日の最安」— `x:facts` の取得日が今日か確認する |
| `promo.cta` (warn) | その回は告知になっている。⑥の5%枠から使うか、文を落とす |

## 1週間の回し方（例）

タイプを回す。詳しい表は [post_types.md](post_types.md)。

| 曜日 | タイプ | ペルソナ | 中身 |
|---|---|---|---|
| 月 | ④ データ | P-A | 今週のプロテイン価格ランキング（先月との差を添える） |
| 火 | ③ あるある | P-C | プロテインあるある |
| 水 | ① 発見 | P-A | 意外な価格差 |
| 木 | ③ 議論 | P-C | プロテイン、何を基準に選ぶ？ |
| 金 | ② 比較 | P-B | データを見ていて気づいたこと |
| 土 | ⑤ 開発日記 | P-B | 作っていて難しかったこと |
| 日 | ② 比較 or ⑥ 告知（月1〜2回） | P-A | 今週の pergram |

7本のうち、サービスに触れるのは土と（月1〜2回の）日だけ。
**これが「毎回サービスの話をしていない」状態の見え方。**
