# 投稿タイプ（何のために書くか）

**これが第一の軸。**[topics.md](topics.md) の題材は第二の軸で、
「何の話をするか」を決める前に「何のために書くか」を決める。

宣伝アカウントに見えていた原因は題材の偏りではなく、**どの投稿も目的が
「サービスの紹介」だった**こと。目的の側を6つに分け、比率を持たせる。

## 🔒 比率

| タイプ | 比率 | 何をするか |
|---|---:|---|
| ① 市場の発見 | **25%** | プロテイン市場の変化・前提のずれを置く。サービスの話はしない |
| ② コスパ・比較 | **25%** | 本丸。ただし「1位は◯◯」で終わらせず、順位が入れ替わる理由を出す |
| ③ 共感・あるある | **20%** | 買う人の行動そのもの。pergram を知らなくても面白い |
| ④ データ・ランキング | **15%** | うちの最大の武器。数字は `x:facts` から |
| ⑤ 開発日記 | **10%** | 広告ではなく**プロダクトの思想**を伝える |
| ⑥ 直接告知 | **5%** | 20本に1本。広告ではなく「発見」として出す |

まとめると **85% : 10% : 5%**。

- **85%** ①②③④ — 面白い・役立つ・共感できる読み物
- **10%** ⑤ — pergram の思想（開発日記）
- **5%** ⑥ — サービスそのものの告知

うち「**うちの話**」（⑤開発日記 ＋ ⑥告知）は合わせて **15%**。ここが上限。

⚠️ 元の整理は「80 : 15 : 5」だったが、①25＋②25＋③20 = 70% で合わない。
**④データ・ランキングは自社の宣伝ではなく読み物**なので①〜④側に入れ、
「うちの話は15%」という意図はそのまま ⑤＋⑥ で守っている。

⚠️ **この比率は固定ルールではない。反応を見ながら調整する。**
`npm run x:feed` が直近の実績を数え、**足りていないタイプ**から順に出す。
🔒 **ランキングだけを回さない。**「またランキングか」になる。

---

## ① 市場の発見（25%）

市場の変化・前提のずれを置く。**サービス紹介ではないのに「pergram って何?」につながる**
のがこのタイプの効き方。

```
プロテインって、
「1kgいくら」で比較すると結構騙される。

重要なのは、
1kgの粉を買うことじゃなくて、
何gのタンパク質を買っているか。
```

```
プロテインの値段、ここ1〜2年でかなり変わった。

「昔からこれが安いから」で買ってる人、
そろそろ一回比較したほうがいい。
```

読み手が「自分も調べてみるか」になれば成功。**その先にうちがあるとは書かない。**

---

## ② コスパ・比較（25%）

本丸。🔒 **「1位は◯◯でした」だけだと普通の投稿になる。意外性を入れる。**

```
「3kgだから安い」は、必ずしも正しくない。

プロテインは容量じゃなくて、
タンパク質1gあたりで見ると順位が変わる。
```

数字で殴る版。**架空の例は A / B で書く**（後述の🔒）。

```
プロテインを「1kgあたり」で比較するの、ちょっと雑です。

例えば
A：1kg / 3,000円 / タンパク質75%
B：1kg / 3,300円 / タンパク質85%

300円高いBのほうが、タンパク質1gあたりでは安い。

「安いプロテイン」と「コスパがいいプロテイン」は違う。
```

🔒 **架空の例は必ず A / B などの記号にする。**実在のブランド名・製品名と結びつけて
架空の価格や含有率を書かない（実データは `x:facts` からしか出さない）。

---

## ③ 共感・あるある（20%）

**プロテインを買わない人にも届く。**このタイプだけがフォロー外に広く出る。

```
プロテイン買うとき

「今回は安いやつにしよう」
↓
セールを見る
↓
Amazonを見る
↓
楽天を見る
↓
公式サイトを見る
↓
30分経過
↓
前と同じやつを買う

これ、何回やったかわからない。
```

⚠️ 縦に長いので `x:lint` の折りたたみ判定（10行超）を必ず確認する。
矢印を横に畳む（`セール → Amazon → 楽天 → 公式 → 30分 → 前と同じやつ`）と収まる。
140字に収まらないなら削らずツリーにする（[threads.md](threads.md)）。

最後に「これをやらなくて済むように作ってます」を**入れてよいが、毎回は入れない。**
入れた回は `x:lint` が `promo.cta` の warn を出すので、**⑥の5%の枠から使う。**

---

## ④ データ・ランキング（15%）

普通の筋トレアカウントにはできない、うちだけの武器。

🔒 **順位を並べるだけで終わらせない。「動き」を添える。**

```
今日のプロテイン価格ランキング。

1位：◯◯
2位：◯◯
3位：◯◯

ついでに「先月1位だった商品」も置いておきます。

価格、結構動きます。
```

「データから見つけたこと」の形も強い。

```
プロテインの価格を見てたら、ちょっと面白いことが分かった。

同じ「1kg」でも、タンパク質1gあたりの価格にはかなり差がある。

つまり「1kg 3,000円」と「1kg 4,000円」の差は、
実際にはもっと大きい。
```

🔒 数字は `npm run x:facts` の出力からしか書かない。
🔒 **「今日の」と書けるのは、価格の取得日が今日のときだけ**（`x:lint` の `voice.today` が warn）。

---

## ⑤ 開発日記（10%）

広告ではなく、**プロダクトの思想**を伝える。公式アカウントだからできる。

```
pergramを作っていて気づいた。

プロテインの価格比較、思ってたより難しい。

「価格」は簡単なんだけど、

・容量
・タンパク質含有量
・セール
・送料
・販売元

まで考えると、単純な価格比較じゃなくなる。

こういうところをちゃんと比較できるサービスにしたい。
```

### β版は弱点ではない

「まだ完成していないサービスを一緒に作っている」というストーリーにできる。
**ユーザーを「客」ではなく「初期メンバー」にする。**

```
pergram、β版を公開しました。

今はプロテイン中心ですが、
最終的にはサプリ全般の価格を比較できるサービスにしたいと思っています。

「この商品も比較してほしい」
「この指標も欲しい」

みたいなのがあれば教えてください。
まだ小さいサービスなので、普通に反映します。
```

🔒 「個人開発」「一人で作った」とは書かない（公式アカウントとして書く）。

---

## ⑥ 直接告知（5%）

🔒 **広告ではなく「発見」として出す。**

❌ 悪い例（これは広告）

```
🎉新サービスpergramリリース🎉
プロテインの価格を簡単に比較できます！
ぜひ使ってみてください！
https://...
```

⭕ 良い例（サービス紹介＋共感＋返信誘発）

```
プロテインを買うとき、
「結局どれが一番安いんだ？」
と思って毎回検索してたので、比較するサービスを作りました。

今はプロテインだけですが、
タンパク質1gあたりの価格で比較できます。

まだβ版です。

こういうの欲しかった人います？
```

違いは3つ。**自分の困りごとから始まる / 現状の限界を先に言う / 問いで終わる。**

---

## 返信を増やす型（②③でよく効く）

会話（リプライ 5.0、相互フォローなら 20.0）はいいね 0.5 の10〜40倍。
**答えを持っている人が答えたくなる形**にする。

```
プロテインって、
安さ重視派と味重視派で結構分かれると思ってる。

ちなみに自分は
「毎日飲むものだから、多少高くても味」派。

みんなはどっち？
```

選択肢を出す形は、市場調査も兼ねる。

```
プロテインを選ぶとき、どれを一番重視しますか？

①価格
②タンパク質含有率
③味
④溶けやすさ
⑤ブランド

これ、普通に気になる。
```

🔒 **味・溶けやすさを「聞く」のはよいが、うちが評価しない。**
「◯◯は溶けやすい」と書いた時点で N-02 に一歩入る。

## 1週間の回し方（例）

ランキングだけを回さない。**発見 → あるある → 意外な差 → 議論 → データ → 開発**。

| 曜日 | タイプ | 中身 |
|---|---|---|
| 月 | ④ データ | 今週のプロテイン価格ランキング |
| 火 | ③ あるある | プロテインあるある |
| 水 | ① 発見 | 意外な価格差 |
| 木 | ③ 議論 | プロテイン、何を基準に選ぶ？ |
| 金 | ② 比較 | データを見ていて気づいたこと |
| 土 | ⑤ 開発日記 | 作っていて難しかったこと |
| 日 | ② 比較 or ⑥ 告知（月1〜2回） | 今週の pergram |

## pergram 固有のコンテンツパターン

タイプが決まったら、pergram のデータと立場だからこそ書ける形に落とす。

### Pattern 1：価格の矛盾

中心テーマは **「安い」と「コスパがいい」は違う。**
見る対象は 容量 / 価格 / タンパク質含有量 / タンパク質1g単価 の4つ。

### Pattern 2：プロテインあるある

> Amazon → 楽天 → 公式サイト → セール比較
>
> 30分経過。
>
> 結局いつものプロテインを買う。

🔒 **サービスを宣伝しなくても成立させる。**

### Pattern 3：市場観察

うちの価格データから見つけたこと（意外な価格差 / 順位変動 / 大容量の意外な結果 /
セールによる順位変動 / メーカー間の違い）を出す。

🔒 **「データがあります」ではなく「データを見たらこんなことが分かった」**の形にする。

### Pattern 4：データランキング

単純なランキングだけにしない。**ランキング ＋ 発見。**

| | |
|---|---|
| 弱い | 今週の最安プロテインランキングです！ |
| 強い | 今週の最安ランキングを見ていたら、ちょっと意外だった。<br>先週1位だった商品が、今週はかなり順位を落としている。 |

### Pattern 5：開発日記

β版であることを弱点にしない。ユーザーを「客」ではなく**初期メンバー**として扱う。

### Pattern 6：意見募集

「どう思いますか？」だけでは弱い。**答えやすい選択肢を置く。**

```
プロテインを選ぶとき、みなさんは何を一番重視しますか？

①価格
②タンパク質含有率
③味
④溶けやすさ
⑤ブランド
```

🔒 味・溶けやすさを**聞く**のはよいが、**うちが評価しない。**
「◯◯は溶けやすい」と書いた時点で N-02 に一歩入る。

## 🔒 目的を見失わない

7原則と Golden Rules は [SKILL.md](../SKILL.md) にある。特に効くのは最後の2つ。

> **最後に少しだけ余白を残す。**
> ❌「だからpergramを使ってください」 ⭕「こういうの、意外と比較したことなかった。」

> **最終目標は「pergram の広告を見ること」ではなく
> 「pergram の投稿を見るのが楽しみになること」。**

⚠️ 余白は**結論を書かないことではない**（[voice.md](voice.md)「余白 ≠ 尻切れ」）。
