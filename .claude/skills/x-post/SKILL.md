# pergram X 投稿の作成

## 目的

**毎回サービスを宣伝することではない。**

> プロテイン・サプリを買う人にとって面白く、役に立ち、思わず反応したくなる投稿を
> 積み重ね、**その結果として** pergram を認知・利用してもらう。

🔒 **最終目標は「pergram の広告を見てもらうこと」ではなく、
「pergram の投稿を見るのが楽しみになること」。**

## 立ち位置

pergram はプロテイン・サプリを**売る側ではなく買う側**に立つサービス。
パッケージ価格ではなく、タンパク質1g単価などの実質的なコスパを比較する。

X 上では、

> **「プロテインを売る公式アカウント」ではなく、
> 「プロテイン市場を観察し、買い物を少し賢くするアカウント」**

### 人格

> **プロテインに詳しくて、コスパにも敏感な友達。**

ただし馴れ馴れしすぎない。カジュアルすぎず、堅すぎず、データと根拠はしっかり。
**「中の人が普通に考えて投稿している」感覚を残す。**

避けるトーン（[reference/voice.md](reference/voice.md) に全部ある）

- 「この商品は絶対買うべきです！」「コスパ最強🔥🔥🔥」
- 「革命的なサービスをローンチしました」「当社独自のアルゴリズムにより……」
- 過度な煽り / **AI 生成文のような整いすぎた定型文**

🔒 **ブランド表記は全て小文字の `pergram`。**`Pergram` は lint が error で落とす。

## この skill が守るもの

| 何を | どこで担保するか |
|---|---|
| 文字数・禁止語・企業敬語・URL の位置・折りたたみ位置 | `npm run x:lint`（機械。**目視で数えない**） |
| 投稿に書く数字 | `npm run x:facts`（実データ。**記憶から書かない**） |
| **直近の投稿との重複**・タイプの配分 | `npm run x:feed`（フィード。**印象で判断しない**） |
| 画像の色と数字 | `npm run x:card`（トークンと実データ。生成モデルを使わない） |

書いてよいこと・書き方の判断は人（とモデル）の仕事、**落とす判断は機械の仕事**。
lint を通さずに投稿文を出さない。

## コマンド

| 入力 | すること |
|---|---|
| `/post [テーマ]` | 過去投稿を確認し、単発かツリーかを判断して投稿文を作る |
| `/reply [相手の投稿]` | 140字以内の返信文を作る。宣伝ではなく有益な補足として書く |
| `/image [投稿文]` | 16:9 のアイキャッチを作る |

🔒 **画像は `/image` か明示的に頼まれたときだけ作る。**`/post` `/reply` では作らない。

# 投稿作成のワークフロー

## Step 0. 事実を取る / 過去投稿を確認する

```bash
npm run x:facts   # 掲載件数・上位の単価・含有率・価格の取得日・β版の制約
npm run x:feed    # 直近の投稿、タイプ別の配分、次に書くタイプ、題材の候補
```

🔒 **`x:facts` に出ていない数字を投稿に書かない。**価格は毎日動くので、
前回の投稿や記憶から数字を写すと、それだけで有利誤認になる。

🔒 **過去投稿を確認せずに書き始めない。**直近とトピック・フック・切り口が被る案は捨てる。
同じ話を別の言い回しで書き直したものは「別の投稿」ではない
（`x:lint --feed` が文字 bigram の近さで拾う）。
フィードが取れないときはキャッシュが使われ、その旨が表示される。
キャッシュも無ければ、ユーザーに直近の投稿か XML を渡してもらう。

## Step 1. 投稿タイプを決める

書き方と例文は [reference/post_types.md](reference/post_types.md)。

| タイプ | 目安 |
|---|---:|
| ① プロテイン市場の発見・考察 | 25% |
| ② コスパ・比較ネタ | 25% |
| ③ 共感・あるある | 20% |
| ④ データ・ランキング | 15% |
| ⑤ 開発・β版・プロダクト思想 | 10% |
| ⑥ 直接的なサービス告知 | 5% |

⚠️ **この比率は固定ルールではない。反応を見ながら調整する。**
`x:feed` が直近の実績とのずれを出すので、**足りていないタイプ**から選ぶのが既定。

## Step 2. 狙う反応を決める

🔒 **「いいねを取る文章」だけを目的にしない。**先に「読者に何をさせたいか」を決める。

| 目的 | 投稿設計 |
|---|---|
| 最後まで読ませる | 冒頭の違和感 ＋ 答えを遅らせる |
| 返信させる | 意見が割れるテーマ ＋ 答えやすい問い |
| 引用させる | 自分の意見を付け足したくなる余白 |
| 保存させる | 後で使える数字・比較・手順 |
| プロフィールを見せる | 「他にも面白い情報を持っていそう」と思わせる |
| サービスを使わせる | 問題提起 → pergram が自然な解決策になる |
| フォローさせる | 継続的に見たいテーマ・人格・データ |

## Step 3. フックを決める

以下から1つ以上。**冒頭の役割は説明ではなく、続きを読む理由を作ること**
（[reference/voice.md](reference/voice.md) 4.1）。

常識否定 / 意外な数字 / 本音 / 違和感 / 具体的な場面 / 問い / 失敗 / 意外な結論 /
**規範への抵触**（「これ普通に売っていいの？」）/ **正体を伏せたクイズ**

⚠️ **1行目の自問は敬語にしない。**「これ普通に売っていいの？」を
「〜してもよいのでしょうか？」にすると指が止まらない。敬語にするのは
**読者への問いかけ**（最終行の問い、「みなさんは〜」）だけ。

## Step 4. 題材を決める

`x:feed` の「題材の候補」から選び、[reference/topics.md](reference/topics.md) の
同じ見出しから種を取る（22ジャンル・5族、出所つき）。

線は1本だけ:

> **pergram の視点（数字・単位・比較・出典）が入っていれば、題材は何でもよい。**

🔒 外部の数字は一次ソースを確認してから書く。まとめ記事の数字を写さない。
🔒 トレーニングの方法・食べ方・論文の紹介には踏み込まない（N-02 に一歩で届く）。
🔒 架空の例は A / B などの記号で書く。実在のブランド名と架空の数字を結びつけない。

## Step 5. 本文を書く

構造はどちらか。

- **A: 具体 → 発見 → 理由 → 一般化**
- **B: 違和感 → 疑問 → 答え → 具体例**

日本語の書き方は [reference/voice.md](reference/voice.md) の7原則（4.1〜4.7）。
見た目の型（三段＋引き、会話ログ、図解）は [reference/formats.md](reference/formats.md)。

## Step 6. ツリー判断

🔒 **140字に収めるために文章を不自然に削らない。**超えるならツリーにする。

⚠️ **pergram が X Premium に加入しているかで、ここの答えが変わる。**
非加入なら日本語140字（加重280）が硬い上限なので、長い型は**ツリーで再現する**しかない。
実測サンプル S-01（5.6M表示）は174字・28行の**1投稿**で、Premium 前提の作り。

| 状態 | 判断 |
|---|---|
| 1投稿で成立する | 完結（あるある・一言の発見・短い意見・軽い問い・データの小ネタ） |
| 答えを遅らせると面白い | 2投稿 |
| ストーリーとして展開できる | 3投稿 |

**ツリーにすること自体を目的にしない。**設計は [reference/threads.md](reference/threads.md)。

## Step 7. クリフハンガー確認（ツリーのとき）

1投稿目を読んだとき、

> **「続きを読みたい」と思うか？**
> **「続く↓」がなくても続きを読みたくなるか？**

🔒 **「続く↓」「1/2」を機械的に使わない。文章そのものを未完にする。**

## Step 8. pergram 接続確認

サービスへの接続が**必要か**を確かめる。**不要なら無理に入れない。**

自然な CTA は「問題を提示 → pergram が自然な解決策 → 軽く提示」。

- ⭕ 「こういう比較を毎回やるのが面倒だったので、pergram を作りました。」
- ❌ 「ぜひ pergram をご利用ください！」「今すぐチェック！」「詳細はこちら！」

## Step 9. 機械に通す

```bash
npm run x:lint -- draft.txt --feed
```

**error が1件でも残っている文章を提示しない。** warn は理由を添えて残してよい。
文字数は lint の出力を書き写す。自分で数えない（日本語は1文字が2、URL は23）。

| コード | 意味 |
|---|---|
| `voice.corporate` (error) | 企業の定型文。中の人が喋る言い方に直す |
| `voice.recommend` (error) | 「絶対買ったほうがいい」— 優劣の断定 |
| `voice.hype` (warn) | 「ガチで」「やばい」— 淡々と |
| `voice.today` (warn) | 「今日の最安」— `x:facts` の取得日が今日か確認する |
| `promo.cta` (warn) | その回は告知になっている。⑥の枠か、ツリーの最後に移す |
| `url.firstPost` (error) | 1投稿目に URL を置かない |

## Step 10. 提示する

```
■ タイプ: [① 市場の発見 〜 ⑥ 直接告知]
■ 狙う反応: [読了 / 返信 / 引用 / 保存 / プロフィール遷移 / サービス利用]
■ 題材: [族 / ジャンル名]（直近と被っていないことを1行）
■ メッセージ: [読み手が持ち帰る1行 =「だから何?」の答え]
■ 形式: [単発 / 2投稿 / 3投稿]（判断理由を1行）

■ 1投稿目（〇文字）
本文

■ 2投稿目（〇文字）   ← ツリーのときだけ
本文
```

# Quality Checklist

投稿完成後、必ず全部見る。

- [ ] 1行目に読む理由がある
- [ ] 企業広告っぽくない
- [ ] **AI っぽい定型表現がない**
- [ ] 抽象論だけになっていない
- [ ] 具体的な場面・数字がある
- [ ] 読者が自分事化できる
- [ ] 断定する場合、その理由がある
- [ ] 説明しすぎていない
- [ ] 読者が反応できる余白がある
- [ ] **1投稿1メッセージになっている**
- [ ] ツリーの場合、1投稿目にクリフハンガーがある
- [ ] 140字に収めるために不自然な文章になっていない
- [ ] 「続く↓」を機械的に使っていない
- [ ] サービス告知を無理に入れていない
- [ ] pergram のブランド人格から外れていない
- [ ] 🔒 直近の投稿と切り口が被っていない（`x:lint --feed`）

---

# Golden Rules

1. **「140字に収める」より「自然で読みたくなる文章」を優先する。**超えるならツリー。
2. **ツリーは単なる分割ではない。**「1投稿目：気になる → 2投稿目：なるほど →
   3投稿目：だから pergram か」という読書体験を設計する。
3. **「続く↓」を機械的に使わない。**疑問・違和感・未完・意外性・数字・👇・接続語で
   自然なクリフハンガーを作る。
4. **サービスを宣伝するために投稿するのではない。**面白い投稿を積み重ねた結果、
   「このアカウント面白いな」→「pergram ってサービスをやってるんだ」→
   「使ってみよう」という流れを作る。
5. **最終目標は「pergram の広告を見ること」ではなく
   「pergram の投稿を見るのが楽しみになること」。**

# 🔒 絶対に書かないこと

CLAUDE.md「絶対にやってはいけないこと」がそのまま X にも掛かる。
lint が落とすが、機械が拾えるのは書かれた語だけなので、意味の側は自分で守る。

- 成分の効能・効果・体感（N-02）。書けるのは含有量・単価・出典・更新日だけ
- 独自の総合スコア・おすすめ順（N-03）。並び順は成分1単位あたりの価格だけで決まる
- 診断的表現（N-07）／育毛・薄毛（N-09）／妊活・美容医療（N-10）の文脈
- 症状・不調・悩みへの言及（N-01）
- 毎回サービスに着地させること
- 企業アカウントの定型文（当社／弊社／このたび／ローンチ／ご利用くださいませ）
- 優劣の推奨（「絶対買ったほうがいい」「買うべき」）
- 「ツール」という呼び方（「サービス」「Webサービス」と呼ぶ）
- 「個人開発」「一人で作った」（公式アカウントとして書く）
- `Pergram` `PerGram`（🔒 **正式表記は全て小文字の `pergram`**）
- 「今日の最安」を、価格の取得日が今日でないまま書くこと

⚠️ [docs/Marketing/X_post_strategy.md](../../../docs/Marketing/X_post_strategy.md) の
例文には「コスパ最強」「神コスパ」「個人開発」など禁止語が含まれる。
**戦略（何を狙うか）はあの文書、語彙（どう書くか）は CLAUDE.md が勝つ。**

# アフィリエイトの扱い 🔒

投稿から送る先はサイト（`/ja/` `/ja/protein/`）で、広告表示はそのページが常時出している。
**投稿に楽天のアフィリエイト URL を直接貼るなら、その投稿自体に「広告」「PR」を明示する。**
迷ったらサイトへのリンクにする。順位に報酬額を影響させない約束は投稿でも同じ。
