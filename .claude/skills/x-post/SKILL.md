# X 投稿文の作成

pergram 公式アカウントの投稿文を書く。**サプリ・プロテインの成分単価比較サービスの
公式アカウント**として、清潔感のある知的なトーンを保つ。

## この skill が守るもの

| 何を | どこで担保するか |
|---|---|
| 文字数・禁止語・URL の位置・折りたたみの位置 | `npm run x:lint`（機械。**目視で数えない**） |
| 投稿に書く数字 | `npm run x:facts`（実データ。**記憶から書かない**） |
| 直近の投稿との重複・話題の偏り・**次に選ぶジャンル** | `npm run x:feed`（フィード。**印象で判断しない**） |
| 画像の色と数字 | `npm run x:card`（トークンと実データ。生成モデルを使わない） |

書いてよいこと・書き方の判断は人（とモデル）の仕事、**落とす判断は機械の仕事**。
この分担を崩さない。lint を通さずに投稿文を出さない。

## コマンド

| 入力 | すること |
|---|---|
| `/post [テーマ]` | 過去投稿を確認し、単発かツリーかを自動判断して投稿文を作る |
| `/reply [相手の投稿]` | 140字以内の返信文を作る。宣伝ではなく有益な補足として書く |
| `/image [投稿文]` | 16:9 のアイキャッチを作る |

コマンドが無く本文だけ渡されたときは `/post` として扱う。

🔒 **画像は `/image` か、明示的に頼まれたときだけ作る。**
`/post` `/reply` では作らない。作った方がよさそうなときも、**作らずに
「`/image` で作れます」と1行添えるだけ**にとどめる。勝手に作ると、
本文と数字がずれた画像が増え、どれを貼ったのか分からなくなる。

## 手順（この順で必ず通す）

### 1. 事実を取る

```bash
npm run x:facts
```

掲載件数・上位の単価・含有率・価格の取得日・β版の制約が出る。
🔒 **ここに出ていない数字を投稿に書かない。** 価格は毎日動くので、
前回の投稿や記憶から数字を写すと、それだけで有利誤認になる。

### 2. 過去投稿を確認する

```bash
npm run x:feed
```

直近の投稿一覧、話したジャンル、族ごとの本数、**配分（価格の話・うちの話・URL の本数）**、
そして **「次の1本の候補」**が出る。手順3はこの候補から始める。
🔒 **直近とトピック・フック・切り口が被る案は捨てる。** 同じ話を別の言い回しで
書き直したものは「別の投稿」ではない（`x:lint --feed` が近さで拾う）。

取得できないとき（ネットワークが塞がれている等）はキャッシュが使われ、
その旨が表示される。キャッシュも無ければ、ユーザーに直近の投稿を貼ってもらうか
フィードの XML を渡してもらう。🔒 **過去投稿を確認せずに書き始めない。**

### 3. 誰に、何を話すかを決める

手順は [reference/persona.md](reference/persona.md) にある。**上から順に落とす。**

```
① ペルソナを選ぶ → ② その人が読みたいものを出す → ③ 書ける形に変換する
   → ④ ジャンルを決める（x:feed の候補から） → ⑤ メッセージを1行にする（手順6）
```

🔒 **②を飛ばして「うちが答えられること」から考え始めない。**
それをやると、何を書いても単価の話に戻る。読み手が読みたいものを先に全部出し、
**そのあとで書ける形に変換する**（persona.md ③）。捨てるのは話題ではなく断定の形で、
「効果」も「おすすめ」も、事実・工程・制度・数字の形にすれば扱えるものがある。

ペルソナは3人。**同じペルソナに2本続けない。**

| | 誰 | その人が読みたいもの |
|---|---|---|
| P-A | 量を飲む人（いまのフォロワーの中心） | 相場・値上げの理由 / セールの仕組み / 業界の動き |
| P-B | 計算する人（🔒 中核ターゲット） | 表示と単位の落とし穴 / 海外との差 / 広告の数字の読み方 |
| P-C | 始めたばかりの人 | 用語の意味 / ラベルの見方 / 何でできているのか / 扱い方 |

ネタは [reference/topics.md](reference/topics.md) に **22ジャンル・5族**ある。
**読み手はコスパ重視のトレーニーで、立ち上げ期はうちのサービスの話より業界の話の方が
読まれる。**サービスから離れてよい。線は1本だけ:

> **pergram の視点（数字・単位・比較・出典）が入っていれば、題材は何でもよい。**

#### 🔒 配分（守れないと、ジャンルをいくつ足しても同じ投稿になる）

| 何 | 上限 | 数える人 |
|---|---|---|
| 価格の話（単価の出し方 / 価格の動き） | **3本に1本** | `x:feed` |
| うちの話（族⑤: 裏話・方針・これから） | **5本に1本** | `x:feed` |
| URL を貼る投稿（＝告知） | **10本に1本** | `x:feed` |
| 同じ族 | **2本続けない** | `x:feed` |

🔒 **サービスの告知は毎回しない。既定は「告知しない」。**
すべての投稿の着地点が自分たちの紹介になっているアカウントは、読み手から見れば
ステルスマーケティングで、飽きはミュート（-58.8 = いいね117個分）で返ってくる。
**10本のうち9本は、読んで終わってよい。**

#### ジャンルの決め方

`npm run x:feed` の **「次の1本の候補」** が、上の4つを適用した結果として出る。
上から1つ選び、topics.md の**同じ見出し**から種を取る。
候補を無視するのは、**理由が1行で言えるときだけ**（セールが今日始まった、等）。

🔒 **外部の数字は一次ソースを確認してから書く。**まとめ記事の数字を写さない。
🔒 トレーニングの方法・食べ方・論文の紹介には踏み込まない（N-02 に一歩で届く）。

⚠️ **ジャンルを変えても型が同じだと、結局同じ投稿に見える。**
ジャンル（何の話か）と型（[reference/formats.md](reference/formats.md)）は別々に選ぶ。

### 4. 何で伸ばすかを決める

重みの根拠は [docs/Marketing/X_algorithm_2026.md](../../../docs/Marketing/X_algorithm_2026.md)
（2026年8月公開のコードから。**二次記事の数字を使わない**）。要点だけ:

- **いいね（0.5）を狙わない。** 効くのは会話（リプライ 5.0 / 相互フォロー相手なら 20.0）と、
  **人に送りたくなること**（リンクのコピー共有 20.0）
- だから投稿は「そのまま誰かに渡せる事実」＋「返信できる余白」で組む。
  具体的な数字を1つ置き、終わりを問いかけか言い切りにする
- **連投しない**（同じ書き手の2投稿目は 0.5 倍、以降 0.25 倍まで落ちる）
- **同じ話を繰り返さない**（ミュート -58.8 / 興味なし -43.2。いいね100個超が一撃で消える）。
  手順2の重複チェックはここに効いている
- プロフィールクリック（0.0）と画像の展開（0.05）は、ほぼスコアにならない

🔒 係数を追って中身を歪めない。煽って会話を作る（通報 -234.0）、毎回同じ問いかけで締める、
反応欲しさに成分の効きに触れる（N-02）——どれもスコア以前に守る側が優先する。

### 5. 単発かツリーかを決める

**既定は単発。** URL を貼るのは10本に1本までなので、ツリーにするのは例外の側。

| 形式 | 選ぶ場面 |
|---|---|
| **単発**（既定） | 日常の気づき、あるある、問いかけ、業界のニュース、読み方の話。ほとんどはこれ |
| **ツリー（2段）** | サイトへ送ると決めたとき（10本に1本）。サービスの紹介、セール連動の速報 |

🔒 **ツリーにするかどうかは `x:feed` の「URL を貼った投稿」を見てから決める。**
上限を超えているなら単発にする。誘導の言い回し（「詳しくは」「作りました」）が
単発や1投稿目に混ざると `x:lint` が `promo.cta` の warn を出す。

ツリーは 1投稿目に URL を置かず、2投稿目（自分のリプ欄）に URL と案内を置く。
3段以上にしない。

⚠️ 「URL を貼ると伸びない」に**公開コード上の根拠は無い**（リンクを開く行動はむしろ +0.2）。
1投稿目を空けるのはペナルティ回避ではなく**機会費用**——1投稿目は会話（5.0〜20.0）に使い、
リンクはその後に置く方が取り分が大きい、という理由で続ける。

### 6. 🔒 メッセージを1つに決める

**ネタ帳にあるのは材料であって、投稿ではない。**材料をそのまま書くと
「で、それが何?」という投稿になる。**読み手が持ち帰るもの**に変換してから書く。

| 材料（起きたこと） | ❌ そのまま書いた場合 | ⭕ 読み手の持ち帰り |
|---|---|---|
| 検索にプロテインバーが混ざる／安い順で取ったら小容量品ばかりだった | 「除外リストを書く作業から始まりました」 | **ECの「安い順」は最安を教えてくれない** |
| 説明文から自動で読めたのは100件中34件 | 「残りは人が入力しました」 | **含有量の書き方はメーカーごとにバラバラ。自分で見るときも書いてある場所が違う** |
| 送料込みか別かを判別している | 「判別できたものだけ表示しています」 | **送料込みと送料別が混ざった一覧は、価格の比較になっていない** |
| スーパーの棚に単位価格の表示義務がある | 「条例で決まっています」 | **単価で比べるのは特殊な見方ではない。ネット通販だけが例外** |

下書きができたら、**「だから何?」に1行で答える**。答えられないなら捨てて選び直す。
答えが「pergram を使ってほしい」になるものも捨てる（それは読み手の持ち帰りではない）。

持ち帰りは次の3つのどれか。

1. **明日の買い物が変わる判断**（〜のときは〜を見る）
2. **知らなかった事実で、自分の買い物に関係がある**
3. **反応したくなる問い**（答えを持っている人が答えたくなるもの）

### 7. 下書きを書く

語彙と終わり方は [reference/voice.md](reference/voice.md)、**構造**は
[reference/formats.md](reference/formats.md)（いまタイムラインでよく見る型と、
pergram で使える形への置き換え）。`---` だけの行でツリーを区切る。

構造で押さえるのは3つだけ。

- **1行目は1行に収める**（20〜25文字。折り返すとフックが割れる）
- **9行以内なら全端末で全文。**超えるなら「さらに表示」の境目を意図して置く
  （最後の1つだけ伏せる型はこれを使っている）
- **🔒 伏せた先に実質を置く。**開いて損する投稿はミュート（-58.8）される

🔒 **同じ型を続けない。**3回続いたら別の型に変える。型の繰り返しは、内容の繰り返しと
同じ速さで飽きられる。

### 8. 機械に通す

```bash
npm run x:lint -- draft.txt --feed
```

**error が1件でも残っている文章を提示しない。** warn は理由を添えて残してよい。
文字数は lint の出力を書き写す。自分で数えない（日本語は1文字が2、URL は23）。

### 9. 提示する

```
■ ペルソナ: [P-A / P-B / P-C]
■ ジャンル: [族 / ジャンル名]（x:feed の候補の何番目か。外したなら理由を1行）
■ 配分: 価格 n/N・うちの話 n/N・URL n/N（x:feed の出力を書き写す）
■ メッセージ: [読み手が持ち帰る1行]
■ 投稿形式: [単発ポスト / ツリーポスト]（判断理由を1行）

■ 1投稿目（〇文字）
本文

■ 2投稿目（ツリー返信）   ← ツリーのときだけ
URL と案内
```

文字数は lint が出した `chars` を書く。🔒 **画像は指示されたときだけ添える。**

投稿後にやることが1行で言えるなら添える（例: 「リプライが来たら必ず返す。返信は
いいねの10倍以上の重みがある」）。ただし毎回は書かない。

## 🔒 絶対に書かないこと

CLAUDE.md「絶対にやってはいけないこと」がそのまま X にも掛かる。
lint が落とすが、機械が拾えるのは書かれた語だけなので、意味の側は自分で守る。

- 成分の効能・効果・体感（N-02）。書けるのは含有量・単価・出典・更新日だけ
- 独自の総合スコア・おすすめ順（N-03）。並び順は成分1単位あたりの価格だけで決まる
- 診断的表現（N-07）／育毛・薄毛（N-09）／妊活・美容医療（N-10）の文脈
- 症状・不調・悩みへの言及（N-01）
- **毎回サービスに着地させること。**「だから pergram を作りました」「pergram なら一発で
  分かります」で終わる投稿は、材料が良くても宣伝になる（`x:lint` の `promo.cta`）
- 「ツール」という呼び方（「サービス」「Webサービス」と呼ぶ）
- 「個人開発」「一人で作った」（公式アカウントとして書く）
- `Pergram` `PerGram`（🔒 **正式表記は全て小文字の `pergram`**）

⚠️ [docs/Marketing/X_post_strategy.md](../../../docs/Marketing/X_post_strategy.md) の
例文には「コスパ最強」「神コスパ」「個人開発」など、CLAUDE.md の禁止語が含まれる。
**戦略（何を狙うか）はあの文書、語彙（どう書くか）は CLAUDE.md が勝つ。**
例文をそのまま使わない。

## アフィリエイトの扱い 🔒

投稿から送る先はサイト（`/ja/` `/ja/protein/`）であり、広告表示はそのページが
常時出している。**投稿に楽天のアフィリエイト URL を直接貼るなら、その投稿自体に
「広告」「PR」を明示する。** 迷ったらサイトへのリンクにする。

順位に報酬額を影響させない約束は投稿でも同じ。「報酬が高いから紹介する」の形に
なる書き方をしない。
