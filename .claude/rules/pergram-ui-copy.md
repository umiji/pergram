# pergram の画面と文言の規約

**この規約は、画面・スタイル・文言・デザイン資料・宣伝物を触るときに読む。**
ブランドの正式表記だけはルート直下の `CLAUDE.md` にも書いてある（コミットメッセージなど、ここに来ない場面でも守る必要があるため）。

---

## ブランド表記 🔒

| 項目 | 規則 |
|---|---|
| 正式表記 | **`pergram`** — 全て小文字 |
| 禁止 | `Pergram` `PerGram` |
| 読み | パーグラム |
| タグライン | JP「1gあたり、いくら払ってる?」/ EN「What are you paying per gram?」 |

初回接触時（LP・OGP・広告）は**必ずタグラインとセットで出す**。`-gram` が Instagram / Telegram の連想を呼ぶため。

### 使ってはいけないビジュアル

葉・植物・カプセル・錠剤・筋肉・ハート・体のシルエット・チェックマーク・人物写真。
いずれも効能または推薦を連想させる。

---

## コピーの規則

**禁止語**: 効く / 効果 / 改善 / 高品質 / おすすめ / 人気No.1 / 安心 / 話題の / 選ばれる / 実感
**使う語**: 含有量 / 元素量 / 単価 / 1gあたり / 認証 / 出典 / 更新日 / 比較 / 一覧

- 能動態。ボタンは操作の結果をそのまま名乗る（「価格を通知する」。「登録」ではない）
- 数値には必ず単位と基準を添える（「¥38」ではなく「¥38 / クレアチン1g」）
- 事実のみを書き、優劣を述べない。「グリシン酸マグネシウムは吸収が良い」は書かない
- エラー文は謝らない。何が起きて、どうすれば直るかだけを書く

## UI 実装の下限

見た目の基準は [src/styles/tokens.css](src/styles/tokens.css)。**色・寸法をコンポーネントに直書きしない。**

- **数値には `font-variant-numeric: tabular-nums` を必ず適用する。** 桁が揃わない比較表は機能しない
- 色は2つしか意味を持たない。**増やしたくなったら情報設計が間違っている合図**
  - `--signal` = ブランドと操作（CTA・リンク・セクションの目印）
  - `--verified` = **主指標の最安値のみ**。全行に使うと意味が消える
  - **🔒 16進値をこの規約に書かない。値の唯一の出所は [src/styles/tokens.css](../../src/styles/tokens.css) である。**
    ここに値を書くと、実装が動いたときに規約だけが取り残される。実際、2026-09-02 まで
    この行は `#2454E6`（青）/ `#1F9254`（緑）と書いていたが、**実装はどちらも橙系**で、
    いつからか分からないまま食い違っていた。**規約が定めるのは色の「意味」であって「値」ではない**
  - **🔒 `--signal` と `--verified` は現在ほぼ同系の橙で、敢えて同値にしていない。**
    明度で読み分けさせる設計である（`tokens.css` の当該箇所に理由がある）。
    **「同じ色なら1つにまとめられる」と読んで統合しないこと**
- **操作の輪郭のための `--line-control` は、上の「色は2つ」の例外である**（2026-09-02、T-017）。
  装飾の罫線 `--line` はコントラスト比 1.23:1 で、**ボタンの輪郭に使うと「押せる操作」に見えない**
  （WCAG 2.2 の非テキストコントラスト 3:1 未満）。`--line` を濃くするとサイト全面の罫線が
  ボタンと同じ濃さになるため、**輪郭専用のトークンを分けてある。**
  🔒 **色ではなく無彩色の不透明度であり、意味を持つ色を増やしたわけではない。**
  同じ理屈で色トークンを増やしてよいという先例にしないこと
- border-radius はトークン経由（カード 14px / 面 16px / 操作 8-10px / チップは丸）。個別に数値を書かない
- UL 超過・認証の有無・最安を**色だけで表現しない**（順位番号・アイコン・テキストを併記）
- ランキングは `<ol>`、成分表は `<table>` + `scope`。div で組まない
- `prefers-reduced-motion: reduce` を尊重する
- モバイルを主とする。タップ領域 44px 以上、本文 16px 未満にしない
